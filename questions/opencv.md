## Q. 컴퓨터 비전이란 무엇이고, 대표적인 문제(task)에는 어떤 것들이 있나요?

### 30초 답변
컴퓨터 비전은 컴퓨터가 이미지나 영상을 처리하고 분석해서 그 안의 내용을 이해하게 만드는 기술입니다. 사람이 눈으로 보고 뇌로 해석하는 과정을 컴퓨터로 구현하는 AI의 한 분야라고 할 수 있습니다. 대표적인 문제로는 사진 전체가 무엇인지 맞히는 분류, 물체의 위치와 종류를 찾는 객체 탐지, 픽셀 단위로 물체를 나누는 분할, 글자를 읽는 OCR, 새 이미지를 만드는 생성이 있습니다.

### 자세히
| 문제 | 출력 | 예 |
|---|---|---|
| 이미지 분류 | 이미지 전체의 라벨 하나 | 고양이 사진 → "고양이" |
| 객체 탐지 | 물체마다 상자 + 라벨 | 차와 사람에 상자 치기 |
| 이미지 분할 | 픽셀마다 라벨 | 배경 제거 |
| OCR | 텍스트 | 영수증, 번호판 읽기 |
| 이미지 생성 | 새 이미지 | 생성형 AI |

- 쓰이는 곳: 공장 불량 검사, X-ray·CT·MRI 병변 탐지, 자율주행(차선·보행자·표지판), CCTV 이상 행동 감지, 물류 바코드 인식, 사진 보정 앱
- 출력이 라벨 하나 → 상자 → 픽셀 단위로 갈수록 더 세밀한 정보를 요구하는 문제가 된다.

### 꼬리질문
#### 영상처리와 컴퓨터 비전은 어떻게 다른가요?
영상처리는 노이즈 제거나 대비 개선처럼 입력도 출력도 이미지인 변환에 가깝고, 컴퓨터 비전은 이미지에서 "무엇이 어디에 있는가" 같은 의미를 끌어내는 데 초점이 있습니다. 실제로는 영상처리가 컴퓨터 비전의 전처리 단계로 함께 쓰이는 경우가 많습니다.

#### 분할은 의미 분할과 인스턴스 분할로 나뉜다던데 차이가 뭔가요?
의미 분할은 픽셀마다 "사람", "차" 같은 클래스만 붙여서 같은 클래스의 물체 여러 개를 구분하지 않습니다. 인스턴스 분할은 같은 클래스라도 사람 1, 사람 2처럼 개별 물체를 따로 나눕니다.

## Q. 딥러닝이 이렇게 발전했는데 규칙 기반 영상처리를 쓰는 이유는 무엇이고, 한계는 무엇인가요?
id: cv-rule-based-why
type: 이유
level: 기본
tags: 규칙 기반, 딥러닝, 임베디드, 실시간
source: 2. 왜 딥러닝 없이 도형을 찾을까

### 30초 답변
찾는 대상의 모양이 단순하고 규칙이 명확하면, 학습 데이터 없이 몇 줄의 규칙만으로 딥러닝보다 훨씬 빠르고 가볍게 처리할 수 있기 때문입니다. 그래서 실시간 처리가 필요하거나 임베디드 장치처럼 모델을 돌리기 어려운 환경에서 많이 씁니다. 다만 임계값 같은 숫자를 사람이 정해야 해서 조명, 배경, 물체 겹침 같은 조건이 바뀌면 다시 손봐야 하고, 조건이 복잡해질수록 딥러닝이 필요해집니다.

### 자세히
| | 규칙 기반 | 딥러닝 |
|---|---|---|
| 데이터 | 필요 없음 | 라벨된 데이터 많이 필요 |
| 속도·자원 | 빠르고 가벼움 | GPU 등 자원 필요 |
| 설명 가능성 | 각 단계가 왜 그렇게 나왔는지 보임 | 내부가 잘 안 보임 |
| 조건 변화 | 숫자를 다시 조정해야 함 | 다양한 데이터로 학습하면 강건 |

- 실사용 예: 차선·정지선(직선), 표지판(원·삼각형·사각형), 물류 로봇의 바닥 선·사각형 마커, 문서 스캔 앱의 종이 네 모서리 찾기
- 직접 해 보며 본 한계: Canny 임계값을 조금 높이자 오각형 경계가 사라졌고, 근사 epsilon을 키우자 원이 사각형처럼 근사됐다.

### 꼬리질문
#### 실제 시스템에서는 둘 중 하나만 쓰나요?
섞어 쓰는 경우가 많습니다. 자율주행도 딥러닝을 쓰지만 경계와 선을 찾는 처리가 바탕에 깔려 있고, 딥러닝 모델 앞뒤에서 리사이즈, 색 변환, 후처리 같은 고전 영상처리가 함께 돌아갑니다.

## Q. 딥러닝 없이 사진 속 도형을 판별하는 파이프라인을 단계별로 설명해 보세요.
id: cv-shape-pipeline
type: 개념
level: 기본
tags: 파이프라인, 전처리, Canny, Contour, 도형 판별
source: 2. 왜 딥러닝 없이 도형을 찾을까

### 30초 답변
전처리, 경계 찾기, 윤곽선 정리, 도형 판별의 네 단계입니다. 흑백으로 바꾸고 가우시안 블러로 잡티를 줄인 다음, Canny로 밝기가 크게 변하는 경계만 남깁니다. 경계 픽셀을 findContours로 연결된 좌표 묶음으로 만들고 작은 얼룩은 면적으로 거른 뒤, approxPolyDP로 점을 줄여 꼭짓점 수와 원형도로 도형을 정합니다.

### 자세히
```python
gray    = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
blurred = cv2.GaussianBlur(gray, (5, 5), 0)
edges   = cv2.Canny(blurred, 80, 160)
contours, _ = cv2.findContours(edges, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
large = [c for c in contours if cv2.contourArea(c) >= 200]
# 각 윤곽선: approxPolyDP로 꼭짓점 수, 4πA/P²로 원형도 → 규칙으로 이름 붙이기
```
- 각 단계는 앞 단계의 문제를 푼다. 노이즈가 있으면 Edge가 엉망이 되니 블러, Edge는 낱개 점이라 Contour로 묶고, 점이 너무 많으니 근사로 줄이고, 꼭짓점만으로 원을 못 가르니 원형도를 본다.

### 꼬리질문
#### 이 파이프라인에서 결과에 가장 민감한 하이퍼파라미터는 무엇이었나요?
Canny의 두 임계값과 approxPolyDP의 epsilon이었습니다. 임계값을 높이면 배경과 대비가 낮은 도형이 사라지고, epsilon을 키우면 원이 사각형 수준으로 뭉개졌습니다.

## Q. 컴퓨터는 이미지를 어떻게 표현하나요? shape와 값의 범위, 좌표계를 설명해 보세요.
id: cv-image-array
type: 개념
level: 기본
tags: 픽셀, numpy, shape, uint8, 좌표계
source: 3. 이미지와 영상 › 이미지는 숫자 배열이다

### 30초 답변
컴퓨터에게 이미지는 픽셀 값이 담긴 숫자 배열입니다. 흑백 이미지는 (높이, 너비) 2차원 배열이고, 컬러 이미지는 채널 3개가 겹친 (높이, 너비, 채널) 3차원 배열이며, 보통 0~255 범위의 uint8로 저장합니다. 원점은 왼쪽 위이고 x는 오른쪽, y는 아래로 증가하며, numpy로 접근할 때는 `img[y, x]`처럼 행, 열 순서로 씁니다.

### 자세히
```python
img = cv2.imread("shape.png")
print(type(img), img.dtype)   # numpy.ndarray, uint8
print(img.shape)              # (480, 640, 3) → 높이, 너비, 채널
```
- 실습 이미지의 빨간 원 경계를 숫자로 보면 원 안쪽은 108, 바깥 종이는 228 정도였다. 사람 눈에는 경계지만 컴퓨터가 받는 건 숫자뿐이다.
- 좌표 순서 주의: numpy 인덱싱은 `[y, x]`(행, 열), OpenCV 함수에 점을 넘길 때(`putText`, `circle` 등)는 `(x, y)`
- 640 × 480 컬러 이미지 한 장은 480 × 640 × 3 = 921,600바이트다.

### 꼬리질문
#### uint8 이미지끼리 더할 때 주의할 점은 무엇인가요?
numpy로 더하면 255를 넘는 값이 256으로 나눈 나머지로 돌아가서 250 + 10이 4가 됩니다. `cv2.add`는 255에서 잘라 주는 포화 연산이라 결과가 255가 되므로, 의도에 맞는 쪽을 쓰거나 미리 float로 바꿔 계산해야 합니다.

#### `cv2.imread`로 읽었는데 shape를 부르니 AttributeError가 납니다. 왜 그런가요?
`imread`는 경로가 틀려도 에러를 내지 않고 `None`을 돌려주기 때문입니다. 그 상태로 `img.shape`를 부르면 그제야 에러가 나서 원인이 경로라는 걸 알기 어려우니, 읽자마자 `None`인지 확인하는 게 좋습니다.

## Q. 영상(비디오)은 이미지와 어떤 관계이고, FPS는 무엇인가요?
id: cv-video-frames
type: 개념
level: 기본
tags: 영상, Frame, FPS, Codec, Container
source: 3. 이미지와 영상 › 영상은 이미지의 연속이다

### 30초 답변
영상은 여러 장의 이미지가 시간 순서대로 빠르게 이어진 것이고, 그 이미지 한 장 한 장을 프레임이라고 합니다. FPS는 1초에 보여 주는 프레임 수로, 30 FPS면 1초에 30장입니다. 그래서 영상 처리는 결국 프레임마다 이미지 처리를 반복하는 것이고, FPS가 높을수록 부드럽지만 1초에 처리할 데이터도 늘어납니다.

### 자세히
| 용어 | 뜻 | 예 |
|---|---|---|
| Frame | 영상을 이루는 이미지 한 장 | |
| FPS | 1초에 보여 주는 프레임 수 | 30 FPS |
| Resolution | 프레임 하나의 크기 | 1920 × 1080 |
| Codec | 영상을 압축·복원하는 방식 | H.264, H.265 |
| Container | 영상·오디오를 담는 파일 형식 | .mp4, .avi, .mov |

- 60 FPS는 30 FPS보다 1초에 처리할 이미지가 두 배다.
- 실시간으로 처리하려면 프레임 하나의 처리 시간이 1/FPS 안에 들어와야 한다. 30 FPS면 약 33ms다.

### 꼬리질문
#### 코덱과 컨테이너는 어떻게 다른가요?
코덱은 영상 데이터를 압축하고 푸는 방법이고, 컨테이너는 압축된 영상과 오디오, 메타데이터를 한 파일에 담는 형식입니다. 같은 .mp4 파일이라도 안에 H.264로 압축된 영상이 들어 있을 수도, H.265로 압축된 영상이 들어 있을 수도 있습니다.

## Q. OpenCV의 BGR 순서란 무엇이고, 왜 주의해야 하나요?
id: cv-bgr
type: 개념
level: 기본
tags: BGR, RGB, cvtColor, matplotlib
source: 4. OpenCV 기초 › OpenCV는 BGR 순서다

### 30초 답변
OpenCV는 컬러 이미지의 채널을 RGB가 아니라 B, G, R 순서로 저장합니다. 그래서 OpenCV로 읽은 이미지를 RGB로 해석하는 matplotlib 같은 라이브러리에 그대로 넘기면 빨강과 파랑이 뒤바뀌어 보입니다. 다른 라이브러리나 딥러닝 모델에 넘기기 전에 `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`로 바꿔야 합니다.

### 자세히
- 빨간 원 한가운데 픽셀 `img[125, 120]`이 `[60 60 220]`이었다. 빨간색인데 마지막 값이 큰 건 마지막 채널이 R이기 때문이다.
- BGR 그대로 matplotlib에 그리면 빨간 원은 파랗게, 파란 직사각형은 주황색으로 나왔다.
- 채널을 하나씩 꺼내 보면 빨간 원은 R 채널에서만, 파란 직사각형은 B 채널에서만 밝다.
- `drawContours`, `putText`의 색 인자도 BGR이라 `(0, 255, 0)`이 초록, `(0, 0, 255)`가 빨강이다.

```python
rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)   # 또는 img[..., ::-1]
```

### 꼬리질문
#### OpenCV는 왜 BGR을 쓰나요?
OpenCV가 처음 만들어질 무렵 카메라 제조사와 Windows 비트맵 같은 소프트웨어에서 BGR 순서가 흔했기 때문이라고 알려져 있습니다. 호환성 때문에 지금까지 기본값으로 남았습니다.

#### 학습한 모델에 넣을 때 BGR/RGB를 잘못 맞추면 어떻게 되나요?
에러는 나지 않지만 모델이 학습 때와 다른 색 분포를 보게 되어 성능이 조용히 떨어집니다. 그래서 학습과 추론에서 같은 순서를 쓰는지 꼭 확인해야 합니다.

## Q. 컬러 이미지를 그레이스케일로 바꾸는 공식은 무엇이고, 왜 흑백으로 바꿔서 처리하나요?
id: cv-grayscale
type: 개념
level: 기본
tags: 그레이스케일, cvtColor, 휘도
source: 4. OpenCV 기초 › 흑백 변환과 크기 변경

### 30초 답변
OpenCV는 `Y = 0.299R + 0.587G + 0.114B`로 세 채널을 가중합해 밝기 하나로 만듭니다. 사람 눈이 초록에 가장 민감하고 파랑에 가장 둔감해서, 단순 평균보다 사람이 느끼는 밝기에 가깝게 가중치를 둔 것입니다. 경계를 찾는 데는 밝기 변화만 있으면 되기 때문에, 흑백으로 바꾸면 데이터가 1/3로 줄고 계산도 단순해집니다.

### 자세히
```python
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
print(gray.shape)   # (480, 640) → 채널 축이 사라짐
```
- 가중치 합은 1이라 결과도 0~255 범위에 머문다.
- 단순 평균 `(R + G + B) / 3`을 쓰면 초록과 파랑이 같은 밝기로 계산되어 사람이 보는 밝기와 어긋난다.
- 색 자체가 단서인 문제(빨간 신호등 찾기 등)에서는 흑백으로 바꾸면 정보를 잃으므로 HSV 같은 색공간을 쓴다.

### 꼬리질문
#### 색은 다른데 밝기가 같은 두 영역은 흑백에서 어떻게 되나요?
가중합 값이 같으면 흑백에서는 같은 회색이 되어 경계가 사라집니다. 이럴 때는 채널별로 경계를 구하거나 색공간을 바꿔서 처리해야 합니다.

## Q. `cv2.resize`를 쓸 때 주의할 점과 보간(interpolation) 방법을 설명해 보세요.
id: cv-resize-interpolation
type: 개념
level: 기본
tags: resize, 보간, 종횡비
source: 4. OpenCV 기초 › 흑백 변환과 크기 변경

### 30초 답변
`cv2.resize`는 크기를 (너비, 높이) 순서로 받는데 shape는 (높이, 너비)로 나와서 순서를 헷갈리기 쉽습니다. 또 원본과 다른 비율로 크기를 직접 지정하면 비율이 깨져서 원이 타원이 됩니다. 크기를 바꾸면 새 픽셀 위치의 값을 주변 픽셀로 추정해야 하는데 이것이 보간이고, 축소할 때는 `INTER_AREA`, 확대할 때는 `INTER_LINEAR`나 `INTER_CUBIC`을 주로 씁니다.

### 자세히
```python
small = cv2.resize(img, None, fx=0.5, fy=0.5)   # 비율로 절반
fixed = cv2.resize(img, (320, 240))             # (너비, 높이)
```
- 실습에서 640 × 480을 320 × 320으로 줄였더니 원이 세로로 긴 타원이 됐다.

| 보간 | 방식 | 특징 |
|---|---|---|
| `INTER_NEAREST` | 가장 가까운 픽셀 값 | 가장 빠름, 계단 현상 |
| `INTER_LINEAR` | 주변 2×2 선형 보간 | 기본값, 무난함 |
| `INTER_CUBIC` | 주변 4×4 3차 보간 | 확대 시 더 부드러움, 느림 |
| `INTER_AREA` | 영역 평균 | 축소 시 물결무늬(모아레) 적음 |

### 꼬리질문
#### 분할 마스크처럼 라벨 값이 담긴 이미지를 리사이즈할 때는 어떤 보간을 써야 하나요?
`INTER_NEAREST`를 써야 합니다. 선형 보간을 쓰면 라벨 1과 3 사이에 존재하지 않는 라벨 2 같은 값이 생기기 때문입니다.

#### 비율을 유지하면서 정해진 입력 크기에 맞추려면 어떻게 하나요?
긴 변을 목표 크기에 맞춰 같은 비율로 줄인 뒤, 모자란 부분을 패딩으로 채웁니다. 이 방식을 레터박스라고 부르고 탐지 모델 입력을 만들 때 자주 씁니다.

## Q. HSV 색공간이란 무엇이고, 색으로 물체를 찾을 때 왜 RGB 대신 HSV를 쓰나요?
id: cv-hsv
type: 개념
level: 기본
tags: HSV, 색공간, inRange, 색 검출
source: 보충 (블로그 밖 내용)

### 30초 답변
HSV는 색을 색상(Hue), 채도(Saturation), 명도(Value) 세 성분으로 나눠 표현하는 색공간입니다. RGB는 같은 빨간색이라도 조명이 밝아지거나 어두워지면 세 값이 모두 함께 변해서 범위를 정하기 어렵습니다. HSV는 밝기 변화가 주로 V에 몰리고 색의 종류는 H 하나로 정해지기 때문에, H 범위만 잡으면 특정 색 물체를 비교적 안정적으로 골라낼 수 있습니다.

### 자세히
```python
hsv  = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
mask = cv2.inRange(hsv, (100, 100, 50), (130, 255, 255))   # 파란 계열만 흰색
```
- OpenCV의 8비트 HSV 범위: H는 0~179(360도를 2로 나눔), S와 V는 0~255
- 빨강은 H가 0 근처와 179 근처에 걸쳐 있어서 두 범위로 `inRange`를 한 뒤 합쳐야 한다.
- S가 낮으면(회색에 가까우면) H 값이 불안정하므로 S 하한도 함께 건다.

### 꼬리질문
#### HSV를 쓰면 조명 변화 문제가 완전히 해결되나요?
아닙니다. 조명의 색 자체가 바뀌거나 그림자가 심하면 H도 변하고, 너무 어두운 영역은 S와 H가 불안정해집니다. 그래서 범위를 실제 환경에서 조정하거나 다른 단서와 함께 씁니다.

## Q. 히스토그램 평활화(Histogram Equalization)란 무엇이고 언제 쓰나요?
id: cv-histogram-equalization
type: 개념
level: 심화
tags: 히스토그램, 평활화, CLAHE, 대비
source: 보충 (블로그 밖 내용)

### 30초 답변
히스토그램 평활화는 밝기 값이 한쪽에 몰린 이미지의 히스토그램을 0~255 전체에 고르게 펴서 대비를 높이는 방법입니다. 각 밝기의 누적 분포(CDF)를 새 밝기 값으로 쓰는 방식이라, 많이 나오는 밝기 구간은 넓게 벌어지고 드문 구간은 좁아집니다. 너무 어둡거나 뿌옇게 찍힌 사진, 의료 영상처럼 대비가 낮은 이미지에서 경계를 잘 보이게 할 때 씁니다.

### 자세히
```
새 값 = round( CDF(원래 값) × 255 )     # CDF는 0~1로 정규화한 누적 비율
```
```python
eq = cv2.equalizeHist(gray)                                   # 8비트 단일 채널
clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8, 8))
eq2 = clahe.apply(gray)
```
- 전역 평활화는 이미지 전체에 하나의 변환을 써서, 밝은 곳과 어두운 곳이 섞인 이미지에서는 일부가 오히려 날아가고 노이즈도 커질 수 있다.
- CLAHE는 이미지를 작은 타일로 나눠 타일마다 평활화하고, clipLimit으로 히스토그램 높이를 잘라 노이즈 증폭을 막는다. 타일 경계는 보간으로 부드럽게 잇는다.

### 꼬리질문
#### 컬러 이미지는 어떻게 평활화하나요?
B, G, R 채널을 따로 평활화하면 채널 사이 비율이 바뀌어 색이 틀어집니다. 그래서 YCrCb나 HSV로 바꾼 뒤 밝기 채널(Y나 V)만 평활화하고 다시 BGR로 돌립니다.

## Q. 이미지 노이즈란 무엇이고, 가우시안 노이즈와 Salt-and-Pepper 노이즈는 어떻게 다른가요?
id: cv-noise-types
type: 개념
level: 기본
tags: 노이즈, 가우시안 노이즈, Salt-and-Pepper
source: 5. 전처리: 노이즈를 줄이자 › 노이즈

### 30초 답변
노이즈는 원래 장면에는 없는데 촬영이나 전송 과정에서 섞여 들어간 픽셀 값의 변화입니다. 가우시안 노이즈는 모든 픽셀에 정규분포를 따르는 작은 값이 더해져서 사진이 전체적으로 자글자글해 보이는 노이즈입니다. Salt-and-Pepper 노이즈는 일부 픽셀만 0(검정)이나 255(흰색)로 튀는 노이즈로, 센서 불량이나 전송 오류에서 생깁니다. 노이즈가 많으면 경계를 잘못 찾거나 작은 점을 물체로 착각하므로 전처리에서 줄여야 합니다.

### 자세히
| | 가우시안 노이즈 | Salt-and-Pepper |
|---|---|---|
| 영향 범위 | 모든 픽셀 | 일부 픽셀 |
| 값의 모양 | 원래 값 ± 작은 정규분포 오차 | 0 또는 255로 극단값 |
| 생기는 곳 | 어두운 곳 촬영, 센서 열잡음 | 센서 불량 픽셀, 전송 오류 |
| 잘 맞는 필터 | 가우시안 블러 | 미디언 블러 |

- 실습에서는 흑백 이미지의 픽셀을 돌며 4% 확률로 0이나 255로 바꿔 Salt-and-Pepper 노이즈를 만들었다.

### 꼬리질문
#### 가우시안 노이즈를 코드로 만들려면 어떻게 하나요?
`np.random.normal(0, σ, img.shape)`로 만든 값을 float로 바꾼 이미지에 더한 뒤 0~255로 자르고 uint8로 되돌립니다. uint8 상태로 바로 더하면 값이 넘쳐서 엉뚱한 값이 됩니다.

## Q. 영상처리에서 필터를 합성곱으로 적용한다는 게 무슨 뜻이고, 패딩은 왜 필요한가요?
id: cv-convolution-padding
type: 개념
level: 기본
tags: 합성곱, 커널, 패딩, BORDER
source: 5. 전처리: 노이즈를 줄이자 › 합성곱과 Padding

### 30초 답변
작은 커널을 이미지 위에 올려 겹친 칸끼리 곱해서 더한 값을 가운데 픽셀의 새 값으로 쓰고, 이걸 한 칸씩 옮기며 반복하는 것입니다. 커널 값을 무엇으로 두느냐에 따라 블러도 되고 경계 검출도 됩니다. 그대로 하면 가장자리에서는 커널이 이미지 밖으로 나가 출력이 작아지므로, 가장자리에 칸을 덧대는 패딩으로 출력 크기를 원본과 같게 유지합니다.

### 자세히
```
출력 크기 = (N + 2P − K) / S + 1      # N 입력, K 커널, P 패딩, S stride
K가 홀수, S = 1, P = (K − 1) / 2  →  출력 = 입력
```
| 방식 | OpenCV 상수 | 예: `10 20 30 40`에 2칸 |
|---|---|---|
| 상수(보통 0) | `BORDER_CONSTANT` | `0 0 / 10 20 30 40 / 0 0` |
| 복사 | `BORDER_REPLICATE` | `10 10 / ... / 40 40` |
| 반사 | `BORDER_REFLECT` | `20 10 / ... / 40 30` |
| 경계 빼고 반사 | `BORDER_REFLECT_101` | `30 20 / ... / 30 20` (OpenCV 필터 기본값) |

- 0으로 채우고 블러하면 외곽이 어두워질 수 있다.

### 꼬리질문
#### 커널 크기를 홀수로 쓰는 이유는 무엇인가요?
홀수여야 커널에 정확한 가운데 칸이 있어서 결과를 어느 픽셀에 쓸지 정해지고, 양쪽에 같은 크기의 패딩을 붙여 위치가 밀리지 않습니다. 그래서 OpenCV의 블러 함수들도 홀수 커널을 요구합니다.

#### OpenCV의 `filter2D`는 엄밀히 합성곱인가요?
엄밀히는 커널을 뒤집지 않고 그대로 곱하는 상관(correlation)을 계산합니다. 블러나 가우시안처럼 대칭인 커널은 결과가 같고, 비대칭 커널로 수학적인 합성곱을 원하면 커널을 상하좌우로 뒤집어서 넣어야 합니다.

## Q. 평균, 가우시안, 미디언 블러를 비교하고 각각 언제 쓰는지 설명해 보세요.
id: cv-blur-compare
type: 비교
level: 기본
tags: 평균 필터, 가우시안 필터, 미디언 필터, 노이즈 제거
source: 5. 전처리: 노이즈를 줄이자 › 블러 필터 세 가지

### 30초 답변
평균 필터는 커널 안 픽셀을 똑같은 비중으로 평균 내고, 가우시안 필터는 가운데에 큰 가중치를 주고 멀어질수록 작게 주는 가중 평균입니다. 미디언 필터는 커널 안 값을 정렬해 가운데 값을 쓰는 비선형 필터라서 0이나 255처럼 튀는 값의 영향을 거의 받지 않습니다. 일반적인 자글자글한 노이즈에는 가우시안을, Salt-and-Pepper처럼 점이 튀는 노이즈에는 미디언을 씁니다.

### 자세히
```python
cv2.blur(img, (3, 3))                 # 평균
cv2.GaussianBlur(img, (5, 5), 0)      # 가우시안
cv2.medianBlur(img, 3)                # 미디언 (커널 크기는 정수 하나)
```
| | 평균 | 가우시안 | 미디언 |
|---|---|---|---|
| 방식 | 균등 가중 평균 | 거리 기반 가중 평균 | 정렬 후 중앙값 |
| 선형 여부 | 선형 | 선형 | 비선형 |
| 경계 보존 | 약함 | 평균보다 자연스러움 | 비교적 잘 보존 |
| 잘 맞는 노이즈 | 약한 노이즈 | 가우시안 노이즈 | Salt-and-Pepper |

- 직접 실험: Salt-and-Pepper 4% 이미지에서 원본과의 평균 차이가 평균 5.31, 가우시안 5.12, 미디언 0.07이었다. 평균과 가우시안은 튀는 점을 주변으로 번지게 해 얼룩이 남았다.

### 꼬리질문
#### 미디언 필터의 단점은 없나요?
값을 정렬해야 해서 커널이 커질수록 평균 계열보다 느리고, 커널이 크면 가는 선이나 뾰족한 모서리처럼 커널보다 작은 구조가 지워집니다. 가우시안 노이즈처럼 모든 픽셀이 조금씩 흔들리는 경우에는 가우시안 블러보다 효과가 덜합니다.

## Q. 가우시안 필터는 왜 쓰고, 커널 크기와 시그마(σ)는 각각 무엇을 조절하나요?
id: cv-gaussian-sigma
type: 이유
level: 심화
tags: 가우시안 필터, 시그마, 커널
source: 5. 전처리: 노이즈를 줄이자 › 가우시안 필터는 왜 쓸까

### 30초 답변
평균 필터처럼 네모 안을 똑같은 비중으로 섞으면 결과가 네모 모양으로 퍼지고 경계가 부자연스럽게 흐려집니다. 실제 밝기 변화는 중심에서 부드럽게 퍼지는 모양에 가까워서, 중심에 큰 가중치를 주고 멀어질수록 작게 주는 가우시안 가중치를 씁니다. 커널 크기는 몇 칸까지 볼지를 정하고, σ는 그 안에서 가중치가 얼마나 넓게 퍼지는지를 정해서 σ가 클수록 바깥 칸 영향이 커져 더 많이 흐려집니다.

### 자세히
```
G(x, y) = (1 / 2πσ²) · exp( −(x² + y²) / 2σ² )
```
```python
cv2.GaussianBlur(gray, (5, 5), 0)        # σ=0이면 커널 크기로 자동 계산 (5×5면 약 1.1)
cv2.GaussianBlur(gray, (0, 0), 2.0)      # 크기를 0으로 두면 σ로 크기를 계산
```
- 커널 크기는 3×3, 5×5처럼 홀수만 되고 튜플로 넘긴다.
- 실습: σ = 2.5인 5×5 커널은 가중치가 거의 평평해서 평균 필터와 비슷해졌다.
- 커널이 σ에 비해 너무 작으면 가우시안 꼬리가 잘려 평균 필터에 가까워진다. 보통 반지름을 3σ 정도로 잡는다.

### 꼬리질문
#### 2D 가우시안 필터를 빠르게 계산하는 방법이 있나요?
2D 가우시안은 x 방향 1D 가우시안과 y 방향 1D 가우시안의 곱으로 나뉩니다(분리 가능). 그래서 가로로 한 번, 세로로 한 번 1D 필터를 적용하면 같은 결과를 얻고, 픽셀당 연산이 K²에서 2K로 줄어듭니다.

## Q. 경계를 보존하면서 노이즈를 줄이는 bilateral 필터를 설명해 보세요.
id: cv-bilateral
type: 개념
level: 심화
tags: bilateral 필터, 경계 보존, 노이즈 제거
source: 보충 (블로그 밖 내용)

### 30초 답변
bilateral 필터는 가우시안 필터처럼 가까운 픽셀에 큰 가중치를 주되, 밝기 차이가 큰 픽셀에는 가중치를 거의 주지 않는 필터입니다. 그래서 같은 영역 안에서는 노이즈를 평균으로 지우고, 경계 건너편의 다른 밝기 픽셀은 섞지 않아 경계가 선명하게 남습니다. 대신 픽셀마다 가중치를 새로 계산해야 해서 가우시안보다 훨씬 느립니다.

### 자세히
```
가중치 = (거리 가우시안) × (밝기 차이 가우시안)
```
```python
cv2.bilateralFilter(img, d=9, sigmaColor=75, sigmaSpace=75)
```
- `sigmaSpace`: 얼마나 먼 픽셀까지 섞을지 (가우시안 필터의 σ와 같은 역할)
- `sigmaColor`: 밝기 차이가 얼마나 나도 섞을지. 크게 하면 경계까지 섞여 일반 가우시안에 가까워진다.
- 피부 보정, 만화풍 필터처럼 경계는 살리고 면은 매끈하게 만들 때 많이 쓴다.

### 꼬리질문
#### Salt-and-Pepper 노이즈에도 bilateral 필터가 잘 맞나요?
잘 맞지 않습니다. 튀는 점은 주변과 밝기 차이가 매우 커서 주변 픽셀이 그 점을 덮어 줄 만큼 섞이지 않고, 그 점의 가중치 계산도 극단값에 끌려가기 때문입니다. 이 경우는 미디언 필터가 낫습니다.

## Q. 이미지에서 Edge란 무엇이고, 왜 미분으로 찾나요?
id: cv-edge-gradient
type: 개념
level: 기본
tags: Edge, 미분, Gradient
source: 6. Edge 검출 › 밝기가 빠르게 변하는 곳

### 30초 답변
Edge는 물체와 배경이 바뀌는 곳처럼 밝기가 빠르게 변하는 위치입니다. 물체 안쪽과 바깥쪽에서는 밝기가 거의 일정하다가 경계에서만 뚝 떨어지거나 뛰기 때문에, 옆 픽셀과의 차이, 즉 미분 값이 경계에서만 크게 나옵니다. 2차원 이미지에서는 x, y 방향 미분을 함께 구한 그래디언트의 크기가 큰 곳을 Edge로 봅니다.

### 자세히
```
Gx = ∂I/∂x,  Gy = ∂I/∂y
크기 = sqrt(Gx² + Gy²),   방향 θ = atan2(Gy, Gx)
```
- 실습: 125번째 행의 밝기를 따라가 보니 옆 픽셀과의 차이가 x = 47, 192, 254, 430, 509, 580에서만 컸다. 빨간 원, 파란 직사각형, 초록 삼각형의 양쪽 경계였다.
- 그래디언트 방향은 밝기가 가장 빠르게 변하는 방향이고, 경계선은 그 방향과 수직으로 놓인다.
- 이미지는 이산 값이라 실제로는 미분 대신 픽셀 차이를 커널로 계산한다.

### 꼬리질문
#### 미분은 노이즈에 왜 약한가요?
노이즈는 옆 픽셀과 갑자기 다른 값이라 그 자리의 차이가 크게 나옵니다. 미분은 이런 급격한 변화를 키우는 연산이라 노이즈까지 Edge처럼 잡히므로, 미분 전에 블러로 먼저 노이즈를 줄입니다.

## Q. Prewitt 필터와 Sobel 필터의 차이를 설명해 보세요.
id: cv-prewitt-vs-sobel
type: 비교
level: 기본
tags: Prewitt, Sobel, 미분 필터, Edge
source: 6. Edge 검출 › Prewitt와 Sobel

### 30초 답변
둘 다 가로와 세로 방향의 밝기 변화를 Gx, Gy 두 개의 3×3 커널로 계산하는 1차 미분 필터입니다. 차이는 Prewitt는 세 행(열)에 같은 가중치 1을 주고, Sobel은 가운데 행(열)에 가중치 2를 준다는 점입니다. Sobel은 미분과 함께 가운데를 강조하는 평활화를 하는 셈이라 노이즈에 조금 더 강하고, OpenCV는 `cv2.Sobel`만 함수로 제공합니다.

### 자세히
```
Prewitt Gx        Sobel Gx
[-1 0 1]          [-1 0 1]
[-1 0 1]          [-2 0 2]
[-1 0 1]          [-1 0 1]       = [1 2 1]ᵀ(평활화) × [-1 0 1](미분)
```
```python
gx = cv2.Sobel(gray, cv2.CV_32F, 1, 0, ksize=3)   # 좌우 변화 → 세로 경계
gy = cv2.Sobel(gray, cv2.CV_32F, 0, 1, ksize=3)   # 위아래 변화 → 가로 경계
mag = cv2.convertScaleAbs(cv2.magnitude(gx, gy))
```
- 실습: 직사각형은 Sobel X에서 세로 변만, Sobel Y에서 가로 변만 나왔다. 둘을 합치면 전체 경계가 보이지만 선이 두껍고 곳곳이 흐릿했다.

### 꼬리질문
#### Sobel 결과를 왜 `CV_32F` 같은 실수형으로 계산하나요?
밝아지는 방향이면 양수, 어두워지는 방향이면 음수가 나오는데 uint8로 계산하면 음수가 0으로 잘려 한쪽 경계를 잃습니다. 그래서 실수형으로 계산한 뒤 화면에 볼 때 `convertScaleAbs`로 절댓값을 취해 0~255로 바꿉니다.

## Q. 1차 미분 기반 Edge 검출과 2차 미분(Laplacian) 기반 검출은 어떻게 다른가요?
id: cv-laplacian
type: 비교
level: 심화
tags: Laplacian, 2차 미분, LoG, Edge
source: 보충 (블로그 밖 내용)

### 30초 답변
1차 미분은 경계에서 값이 최대가 되므로 그래디언트 크기가 큰 곳을 Edge로 잡고, 방향 정보도 얻을 수 있습니다. 2차 미분인 Laplacian은 경계 한가운데에서 값이 양수에서 음수로 바뀌는 영교차(zero-crossing)가 생겨서 그 위치를 Edge로 잡고, 방향과 상관없이 커널 하나로 계산합니다. 대신 2차 미분은 노이즈를 더 크게 키우기 때문에 보통 가우시안 블러를 먼저 하는 LoG(Laplacian of Gaussian)로 씁니다.

### 자세히
```
∇²I = ∂²I/∂x² + ∂²I/∂y²
Laplacian 커널:  [0  1 0]
                 [1 -4 1]
                 [0  1 0]
```
| | 1차 미분 (Sobel) | 2차 미분 (Laplacian) |
|---|---|---|
| Edge 위치 | 크기의 최댓값 | 영교차 |
| 커널 | 방향별 2개 (Gx, Gy) | 방향 무관 1개 |
| 방향 정보 | 있음 | 없음 |
| 노이즈 | 민감 | 더 민감 |

```python
lap = cv2.Laplacian(cv2.GaussianBlur(gray, (5, 5), 0), cv2.CV_32F)
```

### 꼬리질문
#### Laplacian은 Edge 검출 말고 어디에 쓰나요?
원본에서 Laplacian 결과를 빼면 경계가 강조되어 이미지를 선명하게 만드는 샤프닝이 됩니다. 또 Laplacian 값의 분산이 작으면 경계가 흐릿하다는 뜻이라, 사진이 흔들렸는지 판단하는 초점 측정에도 씁니다.

## Q. Canny Edge 검출의 단계를 설명해 보세요.
id: cv-canny-steps
type: 개념
level: 기본
tags: Canny, NMS, Hysteresis, Edge
source: 6. Edge 검출 › Canny

### 30초 답변
Canny는 1986년 John Canny가 제안한 Edge 검출기로, 가우시안 블러로 노이즈를 줄이고 Sobel로 그래디언트 크기와 방향을 구한 뒤 정리 단계를 두 번 더 거칩니다. 먼저 비최대 억제(NMS)로 그래디언트 방향에서 가장 강한 픽셀만 남겨 선을 한 픽셀 두께로 얇게 만듭니다. 그다음 임계값 두 개로 강한 Edge와 약한 Edge를 나누고, 강한 Edge에 이어진 약한 Edge만 살리는 히스테리시스로 노이즈는 버리고 끊기지 않은 선을 만듭니다.

### 자세히
1. 노이즈 제거: 가우시안 블러
2. 그래디언트: Sobel로 크기와 방향 계산
3. 비최대 억제: 그래디언트 방향 앞뒤 이웃보다 크지 않으면 0으로 → 얇은 선
4. 이중 임계값 + 히스테리시스

| 그래디언트 크기 | 처리 |
|---|---|
| 낮은 임계값 미만 | 버림 |
| 높은 임계값 초과 | 확실한 Edge |
| 두 값 사이 | 확실한 Edge와 이어져 있을 때만 남김 |

```python
edges = cv2.Canny(blurred, 80, 160)   # 80, 160은 픽셀 밝기가 아니라 그래디언트 크기 기준
```

### 꼬리질문
#### Sobel만 써도 경계가 나오는데 Canny가 더 많이 쓰이는 이유는 무엇인가요?
Sobel 결과는 선이 두껍고 약한 경계에서 끊기거나 흐릿합니다. Canny는 NMS로 한 픽셀 두께의 선만 남기고 히스테리시스로 약한 경계를 이어 주기 때문에, 뒤 단계에서 윤곽선을 따기에 훨씬 깔끔한 이진 결과가 나옵니다.

#### 임계값을 하나만 쓰면 안 되나요?
하나만 쓰면 높게 잡을 때 약한 경계가 중간중간 끊기고, 낮게 잡을 때 노이즈가 Edge로 들어옵니다. 두 값을 두고 연결성을 보면 노이즈는 거르면서 확실한 경계에서 이어지는 약한 부분은 살릴 수 있습니다.

## Q. Canny를 적용하기 전에 블러를 먼저 하는 이유는 무엇인가요?
id: cv-blur-before-canny
type: 이유
level: 기본
tags: Canny, 가우시안 블러, 전처리, 노이즈
source: 6. Edge 검출 › Canny

### 30초 답변
Edge 검출은 미분 기반이라 픽셀 하나가 튀는 노이즈도 큰 밝기 변화로 보고 Edge로 잡기 때문입니다. 블러로 작은 변화를 먼저 평탄하게 만들면 물체 경계처럼 넓게 이어지는 큰 변화만 남습니다. 직접 해 보니 노이즈를 섞은 이미지에서 블러 없이 Canny를 하면 Edge 픽셀이 24,141개였는데, 5×5 가우시안 블러를 먼저 하자 3,181개로 줄고 도형 경계만 남았습니다.

### 자세히
```python
blurred = cv2.GaussianBlur(gray, (5, 5), 0)
edges = cv2.Canny(blurred, 80, 160)
```
| 처리 | Edge 픽셀 수 | 결과 |
|---|---|---|
| 블러 없이 Canny | 24,141 | 노이즈 하나하나가 Edge |
| 5×5 가우시안 후 Canny | 3,181 | 도형 경계만 남음 |

- Canny 알고리즘 자체의 첫 단계가 가우시안 평활화지만, `cv2.Canny`는 내부에서 Sobel만 계산하므로 블러는 직접 먼저 해 준다.

### 꼬리질문
#### 블러를 너무 세게 하면 어떻게 되나요?
노이즈뿐 아니라 실제 경계도 넓게 퍼져 그래디언트가 약해지므로, 대비가 낮은 경계가 임계값을 못 넘어 사라지고 모서리 위치도 무뎌집니다. 그래서 노이즈 수준에 맞는 최소한의 커널과 σ를 고릅니다.

## Q. Canny 임계값을 어떻게 정했고, 바꿔 보니 결과가 어떻게 달라졌나요?
id: cv-canny-threshold
type: 경험
level: 심화
tags: Canny, 임계값, 하이퍼파라미터
source: 6. Edge 검출 › Canny

### 30초 답변
노이즈를 조금 섞고 블러한 이미지에 임계값 쌍을 바꿔 가며 Canny를 돌려 비교했습니다. 20 / 60처럼 낮게 잡으면 종이의 자글자글한 무늬까지 Edge로 잡혀 Edge 픽셀이 16,107개나 됐고, 150 / 300처럼 높이면 깔끔하지만 배경과 밝기 차이가 작은 오각형의 경계가 통째로 사라졌습니다. 이 이미지에서는 80 / 160이 노이즈는 거르고 도형 경계는 모두 남기는 적당한 값이었습니다.

### 자세히
| 낮은 / 높은 임계값 | 결과 |
|---|---|
| 20 / 60 | 종이 무늬까지 Edge, 16,107픽셀 |
| 80 / 160 | 도형 경계만 깔끔하게 |
| 150 / 300 | 깔끔하지만 저대비 오각형이 사라짐 |

- 두 값은 픽셀 밝기가 아니라 그래디언트 크기 기준이다.
- 낮은 임계값은 약한 경계를 얼마나 이어 줄지, 높은 임계값은 어디서부터 확실한 경계로 볼지를 정한다.
- 보충: Canny는 높은 임계값을 낮은 임계값의 2~3배로 잡기를 권했다.

### 꼬리질문
#### 이미지마다 임계값을 손으로 정하기 어려우면 어떻게 하나요?
이미지 밝기의 중앙값을 기준으로 그 아래위 일정 비율을 낮은·높은 임계값으로 잡는 방법을 많이 씁니다. 또는 Otsu로 구한 이진화 임계값을 높은 임계값으로, 그 절반을 낮은 임계값으로 쓰기도 합니다. 둘 다 경험적인 방법이라 결과를 보고 조정합니다.

## Q. 이진화(thresholding)란 무엇이고, Otsu 방법과 적응형 이진화는 무엇인가요?
id: cv-threshold-otsu
type: 개념
level: 기본
tags: 이진화, threshold, Otsu, adaptive threshold
source: 보충 (블로그 밖 내용)

### 30초 답변
이진화는 임계값보다 밝은 픽셀은 255, 어두운 픽셀은 0으로 바꿔 물체와 배경을 흑백 두 값으로 나누는 것입니다. Otsu 방법은 임계값을 사람이 정하지 않고, 히스토그램을 두 그룹으로 나눴을 때 각 그룹 안의 분산이 가장 작아지는 값을 자동으로 찾습니다. 조명이 고르지 않아 한 값으로 나누기 어려울 때는 픽셀마다 주변 영역의 평균으로 임계값을 따로 정하는 적응형 이진화를 씁니다.

### 자세히
```python
_, bin1 = cv2.threshold(gray, 127, 255, cv2.THRESH_BINARY)            # 고정 임계값
t, bin2 = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)   # t = 찾은 값
bin3 = cv2.adaptiveThreshold(gray, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C,
                             cv2.THRESH_BINARY, 11, 2)                 # 블록 11, 상수 2
```
| 방법 | 임계값 | 잘 맞는 경우 |
|---|---|---|
| 고정 | 사람이 지정 | 조건이 일정할 때 |
| Otsu | 히스토그램에서 자동, 이미지 전체에 하나 | 물체·배경 밝기가 뚜렷한 두 봉우리 |
| 적응형 | 픽셀마다 주변 기준 | 그림자, 조명 불균일 (문서 스캔) |

- `THRESH_BINARY_INV`로 뒤집으면 어두운 물체를 흰색으로 만들 수 있다. findContours는 흰색을 물체로 본다.

### 꼬리질문
#### Otsu 방법은 언제 잘 안 맞나요?
히스토그램이 두 봉우리로 뚜렷하게 나뉜다고 가정하기 때문에, 물체가 아주 작아서 봉우리가 거의 안 보이거나 조명이 한쪽으로 기울어져 밝기 분포가 겹치면 엉뚱한 값을 고릅니다. 이럴 때는 블러를 먼저 하거나 적응형 이진화를 씁니다.

## Q. Edge와 Contour는 어떻게 다른가요?
id: cv-edge-vs-contour
type: 비교
level: 기본
tags: Edge, Contour, findContours
source: 7. Contour › Edge와 Contour는 다르다

### 30초 답변
Edge는 밝기 변화가 큰 픽셀 위치를 표시한 이미지일 뿐이라, 사람 눈에는 선으로 보여도 컴퓨터에게는 아직 낱개 점의 모음입니다. Contour는 그 경계 픽셀을 따라가며 연결된 좌표를 순서대로 묶은 것으로, 물체 하나의 테두리를 하나의 객체로 다룰 수 있게 해 줍니다. 그래서 Contour가 있어야 면적, 둘레, 꼭짓점 수처럼 도형 단위의 특징을 계산할 수 있습니다.

### 자세히
| | Edge | Contour |
|---|---|---|
| 형태 | 이진 이미지 (H × W) | 좌표 배열의 리스트, 윤곽선마다 (N, 1, 2) |
| 단위 | 픽셀 | 연결된 경계 하나 |
| 할 수 있는 것 | 경계 위치 표시 | 면적, 둘레, 외접 사각형, 근사 |
| 대표 함수 | `cv2.Canny` | `cv2.findContours` |

- Contour 입력으로는 Canny 결과뿐 아니라 이진화 결과도 쓸 수 있다.

### 꼬리질문
#### Canny 결과 대신 이진화 결과로 Contour를 찾으면 무엇이 다른가요?
이진화 결과는 물체 내부가 채워진 영역이라 테두리가 하나로 닫히기 쉽고, 선이 끊겨 조각나는 문제가 적습니다. 대신 조명이 고르지 않으면 영역이 잘못 나뉠 수 있어서, 대비가 뚜렷하면 이진화, 색이나 밝기가 다양하면 Canny를 먼저 고려합니다.

## Q. `cv2.findContours`의 검색 모드(계층)와 근사 방법 옵션을 설명해 보세요.

### 30초 답변
검색 모드는 윤곽선 사이의 안팎 관계를 얼마나 찾을지 정하는 옵션으로, `RETR_EXTERNAL`은 가장 바깥 윤곽선만, `RETR_LIST`는 관계 없이 전부, `RETR_TREE`는 전체 포함 관계를 트리로 돌려줍니다. 근사 방법은 좌표를 얼마나 저장할지 정하는데, `CHAIN_APPROX_NONE`은 경계 픽셀을 전부, `CHAIN_APPROX_SIMPLE`은 가로·세로·대각선 직선 구간의 중간 점을 생략하고 끝점만 저장합니다. 도형 판별처럼 바깥 테두리만 필요하면 `RETR_EXTERNAL`과 `CHAIN_APPROX_SIMPLE` 조합을 씁니다.

```python

```
| 모드 | 찾는 것 |
|---|---|
| `RETR_EXTERNAL` | 가장 바깥 윤곽선만 |
| `RETR_LIST` | 전부, 계층 정보 없음 |
| `RETR_CCOMP` | 바깥 테두리와 구멍의 2단계 |
| `RETR_TREE` | 전체 포함 관계 |

- OpenCV 3.x는 반환값이 3개(이미지, 윤곽선, 계층), 4.x부터는 2개다.

### 꼬리질문
#### 도넛 모양 물체의 구멍을 구분하려면 어떤 모드를 쓰나요?
`RETR_CCOMP`나 `RETR_TREE`를 씁니다. 바깥 테두리와 안쪽 구멍 테두리가 부모와 자식 관계로 나오므로, 부모가 있는 윤곽선을 구멍으로 보고 면적에서 빼면 됩니다.

#### `CHAIN_APPROX_SIMPLE`이면 사각형은 항상 점 4개가 되나요?
축에 나란한 직사각형은 4개가 되지만, 기울어진 변은 픽셀 계단이 생겨 정확한 직선 구간이 짧게 끊기므로 점이 많이 남습니다. 실습에서 기울어진 정사각형이 360개 점으로 저장된 이유이고, 그래서 approxPolyDP로 따로 줄여야 합니다.

## Q. `cv2.approxPolyDP`는 무엇을 하는 함수이고, 왜 필요한가요?
id: cv-approxpolydp
type: 개념
level: 기본
tags: approxPolyDP, Douglas-Peucker, 꼭짓점 근사
source: 8. 도형 판별 › 꼭짓점 근사

### 30초 답변
윤곽선은 점이 수십에서 수백 개라 그대로 세면 도형을 구분할 수 없어서, 허용 오차 epsilon 안에서 점을 줄여 도형의 뼈대인 꼭짓점만 남기는 함수입니다. Douglas-Peucker 알고리즘을 쓰는데, 양 끝점을 이은 직선에서 가장 먼 점이 epsilon보다 멀면 그 점을 꼭짓점으로 남기고 양쪽을 다시 나눠 반복합니다. 실습에서는 둘레의 2%를 epsilon으로 줘서 삼각형 3개, 사각형 4개, 오각형 5개로 깔끔하게 줄었습니다.

### 자세히
```python
peri = cv2.arcLength(cnt, True)
approx = cv2.approxPolyDP(cnt, 0.02 * peri, True)   # True = 닫힌 곡선
print(len(cnt), "→", len(approx))
```
- 근사 전 점 수: 빨간 원 210개, 기울어진 정사각형 360개
- 근사 후: 삼각형 3, 사각형 4, 오각형 5, 원 두 개는 모두 8
- epsilon을 둘레에 비례하게 잡으면 도형 크기가 달라도 같은 기준이 적용된다.

### 꼬리질문
#### 원은 꼭짓점이 없는데 근사하면 몇 개가 나오나요?
매끈한 곡선이라 정해진 꼭짓점 수가 없고, epsilon에 따라 달라집니다. 실습에서는 둘레의 2%로 8개가 나왔는데, 이 값은 원의 크기보다 epsilon 비율에 따라 정해지는 숫자라서 원 판별에는 원형도를 함께 봤습니다.

## Q. approxPolyDP의 epsilon 값은 어떻게 정했고, 값에 따라 결과가 어떻게 달라졌나요?
id: cv-epsilon-effect
type: 경험
level: 심화
tags: approxPolyDP, epsilon, 하이퍼파라미터
source: 8. 도형 판별 › 꼭짓점 근사

### 30초 답변
epsilon을 둘레의 0.5%부터 12%까지 바꿔 가며 원과 오각형을 근사해 봤습니다. 원은 0.5%에서 16개, 2%에서 8개, 5%를 넘기면 4개가 되어 사각형과 구분이 안 됐고, 오각형은 5%까지 5개를 유지하다가 12%에서 삼각형처럼 뭉개졌습니다. 그래서 원은 원답게, 다각형은 다각형답게 남기는 둘레의 2%를 썼습니다.

### 자세히
| epsilon (둘레 대비) | 원 | 오각형 |
|---|---|---|
| 0.5% | 꼭짓점 16 | |
| 2% | 꼭짓점 8 | 꼭짓점 5 |
| 5% 이하 | | 5개 유지 |
| 5% 초과 | 꼭짓점 4 (사각형과 구분 불가) | |
| 12% | | 삼각형처럼 뭉개짐 |

- 너무 작으면 픽셀 계단까지 꼭짓점으로 남아 다각형도 꼭짓점이 늘어난다.
- 너무 크면 모서리가 지워져 원이 사각형, 오각형이 삼각형이 된다.

### 꼬리질문
#### 2%라는 값이 다른 이미지에서도 통할까요?
보장되지 않습니다. 해상도가 낮거나 경계가 울퉁불퉁하면 2%로도 다각형의 꼭짓점이 늘 수 있어서, 대표 이미지로 다시 확인하고 조정해야 합니다. 이렇게 조건마다 숫자를 손봐야 한다는 점이 규칙 기반 방식의 한계입니다.

## Q. 원형도(circularity)란 무엇이고, 왜 원 판별에 쓰나요?
id: cv-circularity
type: 개념
level: 심화
tags: 원형도, circularity, 면적, 둘레
source: 8. 도형 판별 › 원형도

### 30초 답변
원형도는 `4π × 면적 / 둘레²`로, 도형이 얼마나 원에 가까운지를 0~1 사이 값으로 나타냅니다. 둘레가 같으면 면적이 가장 넓은 도형이 원이라서 완벽한 원이면 1이 나오고, 각진 모양일수록 작아집니다. 원은 근사 꼭짓점 수가 epsilon에 따라 달라져 꼭짓점만으로는 가르기 어렵기 때문에 원형도를 함께 봤습니다.

### 자세히
```
원: A = πr², P = 2πr  →  4π·πr² / (2πr)² = 1
이론값: 원 1.000, 정사각형 π/4 ≈ 0.785, 정삼각형 ≈ 0.605
```
| 도형 | 근사 꼭짓점 | 원형도 |
|---|---|---|
| 빨간 원 | 8 | 0.894 |
| 회색 작은 원 | 8 | 0.897 |
| 파란 직사각형 | 4 | 0.758 |
| 보라 정사각형(기울어짐) | 4 | 0.681 |
| 주황 오각형 | 5 | 0.781 |
| 초록 삼각형 | 3 | 0.537 |

- 원 두 개만 0.85를 넘어서 기준으로 쓰기 충분했다.

### 꼬리질문
#### 원의 원형도가 1이 아니라 0.89 정도로 나온 이유는 무엇인가요?
픽셀로 그린 원의 테두리는 계단처럼 울퉁불퉁해서 둘레가 실제보다 길게 재지고, 둘레가 제곱으로 들어가 값이 내려갑니다. 기울어진 정사각형이 이론값 0.785보다 한참 낮은 0.681이 나온 것도 비스듬한 변에 계단이 더 많이 생겨서입니다.

## Q. 도형 판별 규칙은 어떻게 짰고, 결과는 어땠나요?
id: cv-shape-classify
type: 경험
level: 기본
tags: 도형 판별, 규칙 기반, boundingRect, putText
source: 8. 도형 판별 › 판별하고 이름 달기

### 30초 답변
근사 꼭짓점이 3개면 삼각형, 4개면 사각형, 8개 이상이면서 원형도 0.85 이상이면 원, 나머지는 미판정으로 두는 규칙을 썼습니다. 원 두 개, 직사각형, 기울어진 정사각형, 삼각형은 모두 맞게 나왔고, 기울어진 정사각형도 꼭짓점이 4개라 문제없이 사각형이 됐습니다. 오각형은 규칙에 없어서 Unknown으로 남았는데, 꼭짓점 5개 조건 한 줄만 더하면 잡을 수 있습니다.

### 자세히
```python
def classify_shape(cnt):
    peri = cv2.arcLength(cnt, True)
    approx = cv2.approxPolyDP(cnt, 0.02 * peri, True)
    circularity = 4 * np.pi * cv2.contourArea(cnt) / peri ** 2
    if len(approx) == 3: return "Triangle"
    if len(approx) == 4: return "Rectangle"
    if len(approx) >= 8 and circularity >= 0.85: return "Circle"
    return "Unknown"
```
- `boundingRect`로 감싸는 상자를 구해 그 위에 `putText`로 이름을 썼다. 기본 글꼴은 한글을 못 써서 영어로 표시했다.

### 꼬리질문
#### 정사각형과 직사각형을 구분하려면 어떻게 하나요?
꼭짓점이 4개인 도형의 가로세로 비율을 보면 됩니다. 축에 나란하면 `boundingRect`의 w/h가 1에 가까운지 보면 되지만, 기울어진 도형은 외접 상자가 비율을 왜곡하므로 회전을 고려한 `cv2.minAreaRect`의 두 변 길이로 비율을 계산합니다.

#### 꼭짓점이 4개인데 사각형이 아닌 경우는 없나요?
오목한 사각형이나 찌그러진 모양도 꼭짓점이 4개로 근사될 수 있습니다. `cv2.isContourConvex`로 볼록한지 확인하거나 변 길이와 각도 조건을 추가하면 더 엄격하게 거를 수 있습니다.

### 30초 답변
허프 변환은 Edge 픽셀 하나하나가 자신을 지날 수 있는 모든 직선(또는 원)에 투표하게 해서, 표를 많이 받은 직선을 찾는 방법입니다. 직선은 기울기가 무한대가 되는 문제를 피하려고 `ρ = x cosθ + y sinθ`처럼 원점으로부터의 거리와 각도로 표현하고, 누적 배열에서 표가 임계값을 넘는 (ρ, θ)를 직선으로 봅니다. 선이 중간에 끊겨 있어도 같은 직선 위 점들이 같은 칸에 투표하므로 차선 검출처럼 끊긴 선을 찾는 데 강합니다.

### 자세히
```python
lines = cv2.HoughLinesP(edges, rho=1, theta=np.pi/180, threshold=50,
                        minLineLength=30, maxLineGap=10)          # 선분 양 끝점
circles = cv2.HoughCircles(gray_blur, cv2.HOUGH_GRADIENT, dp=1, minDist=20,
                           param1=100, param2=30, minRadius=0, maxRadius=0)
```
- `HoughLines`는 무한 직선의 (ρ, θ), `HoughLinesP`는 확률적 방식으로 선분의 끝점을 돌려준다.
- `HoughCircles`는 Canny 결과가 아니라 흑백 이미지를 받고 내부에서 Canny를 돌린다. `param1`은 Canny 높은 임계값, `param2`는 투표 임계값이다.
- 투표 임계값이 낮으면 가짜 선이 많아지고, 높으면 짧거나 흐린 선을 놓친다.

### 꼬리질문
#### 윤곽선 근사로 도형을 찾는 방식과 비교하면 어떤 장점이 있나요?
윤곽선 방식은 경계가 하나로 닫혀 있어야 잘 동작하지만, 허프 변환은 점들이 같은 직선이나 원 위에 있기만 하면 끊기거나 일부가 가려져도 찾을 수 있습니다. 대신 파라미터 공간을 모두 투표해야 해서 계산량이 많고, 특히 원은 반지름까지 찾아야 해서 더 무겁습니다.

## Q. OpenCV로 웹캠 영상을 실시간 처리하는 기본 루프를 설명해 보세요.
id: cv-webcam-loop
type: 개념
level: 기본
tags: VideoCapture, waitKey, 실시간 처리, 웹캠
source: 9. 영상에 적용하기: 웹캠 도형 검출

### 30초 답변
`cv2.VideoCapture(0)`으로 첫 번째 카메라를 열고, while 문 안에서 `cap.read()`로 프레임을 한 장씩 읽어 처리한 뒤 `imshow`로 띄우는 구조입니다. `read()`는 성공 여부 `ret`과 프레임을 돌려주므로 `ret`이 False면 루프를 빠져나오고, `waitKey(1)`로 키 입력을 확인해 q를 누르면 종료합니다. 끝나면 `release()`로 카메라를 놓고 `destroyAllWindows()`로 창을 닫습니다. 영상이 사진의 연속이라 이미지 처리 함수를 루프 안에 그대로 넣으면 됩니다.

### 자세히
```python
cap = cv2.VideoCapture(0)
while cap.isOpened():
    ret, img = cap.read()
    if not ret:
        break
    # 흑백 → 5×5 블러 → Canny(80/160) → 면적 1000 이상 윤곽선 → classify_shape
    cv2.imshow("Webcam", img)
    if cv2.waitKey(1) & 0xFF == ord("q"):
        break
cap.release()
cv2.destroyAllWindows()
```
- Colab에서는 카메라를 바로 못 써서 로컬(VS Code, Python 3.11)에서 실행했다. Windows 카메라 앱이 켜져 있으면 OpenCV가 카메라를 못 연다.
- 노트북에서는 도형이 움직이고 정사각형이 돌아가는 30프레임 가짜 영상에 같은 처리를 적용했고, 45도쯤 돌아 마름모처럼 보이는 프레임에서도 꼭짓점 4개라 Rectangle로 잡혔다.

### 꼬리질문
#### `waitKey(1)`은 왜 꼭 필요한가요?
`imshow` 창은 `waitKey`가 호출될 때 화면을 갱신하고 이벤트를 처리하므로, 없으면 창이 멈춘 것처럼 보입니다. 인자 1은 1ms만 키를 기다린다는 뜻이고, `& 0xFF`는 반환값의 하위 8비트만 남겨 플랫폼에 상관없이 키 코드를 비교하려는 것입니다.

#### 처리가 느려서 화면이 끊기면 어떻게 개선하나요?
프레임 하나 처리 시간이 1/FPS를 넘으면 밀리므로, 프레임을 작게 리사이즈해서 처리하거나 몇 프레임마다 한 번만 처리합니다. 관심 영역(ROI)만 잘라 처리하거나 무거운 단계를 가벼운 것으로 바꾸는 것도 방법입니다.
