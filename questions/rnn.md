## Q. 시퀀스 데이터란 무엇이고, 어떤 특징이 있나요?
id: rnn-sequence-data
type: 개념
level: 기본
tags: 시퀀스, 시계열, 기초
source: 1. 시퀀스 데이터: 순서가 곧 의미다

### 30초 답변
시퀀스 데이터는 일정한 순서로 나열된 데이터로, 문장, 대화, 음성 파형, 영상, 주가나 기온 같은 시계열이 여기에 들어갑니다. 가장 중요한 특징은 순서를 섞으면 의미가 사라진다는 점입니다. 같은 1, 2, 3이라도 1, 2, 3 순서면 다음에 4가, 3, 2, 1 순서면 0이 올 것 같은 것처럼 순서 자체가 다음 값을 결정합니다. 그래서 값의 구성이 아니라 순서 안의 변화 패턴을 학습하는 모델이 필요합니다.

### 자세히
| 종류 | 예 |
|---|---|
| 텍스트 | 단어가 이어진 문장, 대화 |
| 신호 | 소리 파형, 센서 값 |
| 시계열 | 주가, 기온, 전력 사용량 |
| 영상 | 프레임의 연속 |

- 순서를 섞으면 의미가 바뀐다. 이미지가 공간상의 이웃 관계가 중요하다면 시퀀스는 앞뒤 관계가 중요하다.
- 샘플마다 길이가 다른 경우가 많다. 문장마다 단어 수가 다르다.
- 변화가 복잡해지면 사람도 규칙을 바로 찾기 어려워서, 패턴을 데이터에서 학습하는 모델을 쓴다.

### 꼬리질문
#### 시계열 데이터와 시퀀스 데이터는 같은 말인가요?
시계열은 시간 간격을 두고 측정한 값의 나열로, 시퀀스의 한 종류입니다. 문장은 시간 축은 없지만 순서가 의미를 가지므로 시퀀스 데이터에 속합니다.

#### 시계열 데이터를 학습용과 평가용으로 나눌 때 주의할 점은 무엇인가요?
무작위로 섞어서 나누면 미래 시점의 정보가 학습에 들어가 성능이 실제보다 좋게 나옵니다. 그래서 과거 구간으로 학습하고 그 뒤 구간으로 평가하도록 시간 순서대로 나눕니다.

## Q. 시퀀스 모델로 푸는 문제를 입력과 출력 형태에 따라 나눠 설명해 보세요.
id: rnn-task-types
type: 개념
level: 기본
tags: Many-to-One, Many-to-Many, One-to-Many
source: 1. 시퀀스 데이터: 순서가 곧 의미다

### 30초 답변
입력과 출력의 개수로 나눕니다. Many-to-One은 시퀀스를 끝까지 다 본 뒤 답을 하나 내는 구조로, 영화 리뷰의 긍정·부정 분류나 며칠간 주가로 내일 주가를 맞히는 문제입니다. Many-to-Many는 입력이 하나 들어올 때마다 답을 하나씩 내는 구조로, 품사 태깅이나 센서 이상 탐지가 해당합니다. 그 밖에 입력 하나로 시퀀스를 만들어 내는 One-to-Many도 있고, 이미지 캡셔닝이나 음악 생성이 예입니다.

### 자세히
| 유형 | 입력 → 출력 | 예 | RNN 출력 사용 |
|---|---|---|---|
| Many-to-One | 시퀀스 → 값 1개 | 감성 분류, 음성 명령 분류, 다음 날 주가 | 마지막 시점 hₜ만 출력층에 |
| Many-to-Many | 시퀀스 → 같은 길이 시퀀스 | 품사 태깅, 이상 탐지, 매일 매수·매도 신호 | 모든 시점 hₜ를 출력층에 |
| One-to-Many (보충) | 값 1개 → 시퀀스 | 이미지 캡셔닝, 음악 생성 | 만든 출력을 다음 입력으로 다시 넣음 |

- 입력과 출력 길이가 다른 Many-to-Many(번역 등)는 Encoder-Decoder 구조로 푼다. Seq2Seq에서 따로 다룬다.

### 꼬리질문
#### Many-to-One이면 RNN 내부 계산도 달라지나요?
달라지지 않습니다. 셀 안에서는 매 시점 hₜ가 똑같이 계산되고, 마지막 hₜ만 출력층에 넣어 예측 하나로 손실을 구한다는 점만 다릅니다.

#### Many-to-Many에서는 손실을 어떻게 계산하나요?
시점마다 예측과 정답을 비교해 손실을 구하고 평균을 냅니다. 그래서 역전파 때 기울기가 마지막 시점 하나가 아니라 모든 시점에서 들어옵니다.

## Q. MLP로 시퀀스 데이터를 다루기 어려운 이유는 무엇인가요?
id: rnn-mlp-limits
type: 이유
level: 기본
tags: MLP, 가변 길이, 파라미터 수
source: 2. MLP로는 왜 안 될까

### 30초 답변
세 가지 이유가 있습니다. 첫째, MLP는 첫 층의 입력 크기가 고정이라 길이 5로 만든 모델에 길이 6짜리 입력을 넣을 수 없습니다. 둘째, 입력 칸을 각각 별개의 값으로 받기 때문에 "이 단어가 저 단어 앞에 있었다"는 순서 관계를 따로 표현해 줘야 합니다. 셋째, 시퀀스가 길어질수록 입력 차원과 가중치 수가 같이 늘어납니다.

### 자세히
은닉 노드 8개, 입력 feature 1개 기준 파라미터 수

| 입력 길이 T | MLP 첫 층 | nn.RNN(1, 8) |
|---|---|---|
| 10 | 88 | 88 |
| 50 | 408 | 88 |

- MLP 첫 층은 `T × 8 + 8`이라 길이가 한 칸 늘 때마다 가중치가 8개씩 는다.
- RNN은 길이와 상관없이 같은 셀을 반복해서 쓰므로 파라미터 수가 고정이다.
- MLP는 위치마다 다른 가중치를 쓰므로, 같은 패턴이 다른 위치에 나오면 따로 다시 배워야 한다.

### 꼬리질문
#### 가장 긴 길이에 맞춰 패딩하면 MLP로도 되지 않나요?
입력은 들어가지만 최대 길이를 미리 정해야 하고, 그보다 긴 입력은 여전히 못 받습니다. 위치마다 다른 가중치라는 문제와 길이에 비례해 파라미터가 느는 문제도 그대로 남습니다.

## Q. RNN의 구조와 Hidden State에 대해 설명해 보세요.
id: rnn-structure
type: 개념
level: 기본
tags: RNN, Hidden State, 순환 구조
source: 3. RNN의 구조 › 계산 자체는 MLP와 같다

### 30초 답변
RNN의 노드 계산은 MLP와 같아서 입력에 가중치를 곱하고 bias를 더한 뒤 활성화 함수를 통과시킵니다. 다른 점은 그 결과 hₜ를 출력으로도 쓰고 다음 시점 계산의 입력으로도 다시 넣는다는 것입니다. 이 hₜ를 Hidden State라고 하고, 과거 데이터를 그대로 저장한 것이 아니라 지금까지 본 정보를 압축한 벡터라서 RNN의 기억 역할을 합니다.

### 자세히
```
hₜ = tanh(Wₓ · xₜ + Wₕ · hₜ₋₁ + b)
```

- Wₓ: 이번 입력에 곱하는 가중치, Wₕ: 지난 기억 hₜ₋₁에 곱하는 가중치
- 이 계산 묶음을 셀(cell, memory cell)이라고 부른다.
- hidden 노드가 32개면 hₜ는 숫자 32개짜리 벡터다.
- `nn.RNN(F, H)`의 가중치: `weight_ih (H, F)`, `weight_hh (H, H)`, `bias_ih (H)`, `bias_hh (H)`. 수식의 b는 bias 두 개를 더한 값이다.
- 첫 시점의 h₀는 기본적으로 0에서 시작한다.

### 꼬리질문
#### h₀는 어떻게 정하나요?
PyTorch는 따로 주지 않으면 0 벡터로 시작합니다. `rnn(x, h0)`처럼 직접 넘길 수도 있고, 학습 가능한 파라미터로 두어 초기 상태까지 학습시키는 방법도 있습니다.

#### Hidden 크기는 어떻게 정하나요?
하이퍼파라미터입니다. 키우면 담을 수 있는 정보가 늘지만 Wₕ가 H × H라 파라미터가 제곱으로 늘고 과적합 위험도 커지므로 검증 성능을 보며 정합니다.

## Q. RNN의 펼친 그림(unrolled)과 가중치 공유를 설명해 보세요.
id: rnn-weight-sharing
type: 개념
level: 기본
tags: Weight Sharing, Unrolled, 파라미터 수
source: 3. RNN의 구조 › 접힌 그림과 펼친 그림

### 30초 답변
RNN은 셀에서 자기 자신으로 돌아오는 화살표를 그린 접힌 그림과, 그것을 시점 순서대로 옆으로 펼친 그림으로 표현합니다. 펼친 그림의 칸들은 셀이 시점 수만큼 따로 있는 것이 아니라 같은 셀 하나를 시점마다 한 번씩 쓴 것을 늘어놓은 것입니다. 모든 칸이 같은 Wₓ, Wₕ, b를 쓰는 가중치 공유 덕분에 시퀀스가 길어져도 셀을 쓰는 횟수만 늘고 파라미터 수는 그대로입니다.

### 자세히
```
파라미터 수 = H·F (Wₓ) + H·H (Wₕ) + 2H (bias 2개)
nn.RNN(1, 8) = 8 + 64 + 16 = 88   # 길이 10이든 50이든 같다
```

- CNN이 같은 필터를 이미지 전체에 슬라이딩하는 것과 비슷하다. CNN은 공간 방향, RNN은 시간 방향으로 공유한다.
- 같은 규칙을 모든 시점에 적용하므로 길이가 다른 입력을 처리할 수 있고, 특정 위치에 묶이지 않은 패턴을 배운다.

### 꼬리질문
#### 파라미터 수가 일정하면 메모리 사용량도 길이와 상관없나요?
아닙니다. 학습할 때는 역전파를 위해 시점마다 hₜ 같은 중간값을 모두 저장해야 하므로, 활성값 메모리는 시퀀스 길이에 비례해서 늘어납니다.

## Q. RNN이 이전 입력을 기억한다는 것을 숫자로 확인해 본 적이 있나요?
id: rnn-forward-numbers-exp
type: 경험
level: 기본
tags: 순전파, Hidden State, 손계산
source: 3. RNN의 구조 › 숫자로 따라가 보기

### 30초 답변
입력 1개, hidden 1개짜리 가장 작은 RNN에 Wₓ = 0.5, Wₕ = 0.8, b = 0.1, h₀ = 0을 두고 직접 계산해 봤습니다. 첫 입력 1에서 h₁ = 0.537이 나왔고, 두 번째 입력은 0.5로 더 작은데도 h₂ = 0.652로 오히려 커졌습니다. h₁이 Wₕ를 거쳐 다음 계산에 더해졌기 때문이고, 같은 입력이라도 앞에 무엇이 왔느냐에 따라 결과가 달라진다는 것을 숫자로 확인했습니다.

### 자세히
```
h₁ = tanh(0.5·1   + 0.8·0     + 0.1) = tanh(0.6)  ≈ 0.537
h₂ = tanh(0.5·0.5 + 0.8·0.537 + 0.1) = tanh(0.78) ≈ 0.652
```

- x₂ < x₁인데 h₂ > h₁이다. 차이를 만든 것은 `Wₕ · h₁` 항이다.
- 이 값이 시퀀스를 따라 계속 전달되면서 "지금까지 본 것"이 반영된다.

### 꼬리질문
#### Wₕ가 0이면 어떻게 되나요?
이전 hidden이 계산에 전혀 들어가지 않아 시점마다 독립적으로 계산하는 MLP와 같아집니다. 같은 입력에는 항상 같은 출력이 나오고 기억이 사라집니다.

## Q. RNN의 활성화 함수로 ReLU 대신 tanh를 주로 쓰는 이유는 무엇인가요?
id: rnn-tanh
type: 이유
level: 기본
tags: tanh, ReLU, 활성화 함수
source: 3. RNN의 구조 › 활성화 함수는 왜 tanh일까

### 30초 답변
RNN은 hₜ를 다음 시점 계산에 계속 다시 넣기 때문에 출력 범위가 묶여 있어야 합니다. ReLU는 상한이 없어서 Wₕ가 1보다 크면 값이 시점마다 커지며 발산하는데, tanh는 출력이 -1~1이라 Wₕ가 커도 일정 범위를 넘지 않습니다. 또 tanh는 0을 중심으로 하고 최대 미분값이 1이라, 최대 미분값이 0.25인 sigmoid보다 기울기를 잘 전달합니다.

### 자세히
입력 0.5를 20시점 동안 계속 넣었을 때, Wₕ = 1.2이면 ReLU의 hₜ는 93까지 커지고 tanh의 hₜ는 범위 안에 머문다.

| | 출력 범위 | 최대 미분값 | RNN에서 문제 |
|---|---|---|---|
| ReLU | 0 ~ ∞ | 1 | 값이 누적되어 발산할 수 있다 |
| sigmoid | 0 ~ 1 | 0.25 | 기울기가 빨리 줄고, 0 중심이 아니다 |
| tanh | -1 ~ 1 | 1 | 양 끝에서 포화되면 기울기가 0에 가깝다 |

- tanh도 입력이 크면 기울기가 거의 0이 된다. 이것이 기울기 소실의 씨앗이다.

### 꼬리질문
#### RNN에서는 ReLU를 아예 쓸 수 없나요?
쓸 수는 있습니다. PyTorch도 `nn.RNN(..., nonlinearity='relu')` 옵션을 제공하고, Wₕ를 단위행렬로 초기화해 ReLU RNN을 안정적으로 학습시키는 방법(IRNN, Le 등 2015)도 있습니다. 다만 기본값은 tanh이고 발산을 막으려면 초기화와 학습률을 조심해야 합니다.

## Q. RNN 뒤의 출력층과 손실 함수는 문제 종류에 따라 어떻게 정하나요?
id: rnn-output-layer
type: 개념
level: 기본
tags: 출력층, 손실 함수, nn.Linear
source: 3. RNN의 구조 › Hidden State와 출력층

### 30초 답변
RNN의 출력층은 hₜ를 받는 `nn.Linear` 한 층이고, 문제 종류에 따라 출력 개수와 손실 함수만 바뀝니다. 회귀는 출력 1개나 n개에 MSE, 이진 분류는 출력 1개에 BCEWithLogits, 다중 분류는 클래스 수만큼 출력해 cross entropy를 씁니다. sigmoid나 softmax는 forward에 넣지 않고 손실 함수 안에서 처리합니다.

### 자세히
| 문제 | 마지막 층 | 손실 함수 | 예측값 |
|---|---|---|---|
| 회귀 | Linear(H, 1 또는 n) | F.mse_loss | 그대로 |
| 이진 분류 | Linear(H, 1) | F.binary_cross_entropy_with_logits | out > 0 |
| 다중 분류 | Linear(H, C) | F.cross_entropy | out.argmax(-1) |
| 다중 레이블 | Linear(H, C) | F.binary_cross_entropy_with_logits | out > 0 |

- 다중 분류는 클래스 중 하나만 정답, 다중 레이블은 클래스마다 따로 예/아니오를 판단한다.
- `F.mse_loss(pred, y)`와 `nn.MSELoss()(pred, y)`는 결과가 완전히 같다. 후자가 안에서 전자를 부른다.

### 꼬리질문
#### softmax를 forward에 넣으면 왜 안 되나요?
`F.cross_entropy`가 안에서 log_softmax와 NLL 손실을 함께 계산하므로, forward에 softmax를 또 넣으면 두 번 적용됩니다. 손실 안에서 합쳐 계산하는 쪽이 수치적으로도 안정적입니다.

## Q. PyTorch의 nn.RNN에 넣는 입력 텐서의 모양을 설명해 보세요.

level: 기본
tags: PyTorch, 입력 모양, batch_first
source: 4. RNN에 넣는 데이터의 모양

### 30초 답변
RNN 데이터는 Sample, Timestep, Feature 세 축으로 이루어집니다. 과거 24시간의 기온, 습도, 전력, 축제 여부로 예측하는 Sample이 500개면 전체 데이터는 `[500, 24, 4]`입니다. 그런데 `nn.RNN`은 기본적으로 미니배치를 시간 축이 맨 앞인 `[T, B, F]`로 받고, `batch_first=True`를 주면 `[B, T, F]`로 받습니다.

### 자세히
```python
rnn = nn.RNN(5, 10)                       # 입력: [T, B, F]
rnn_bf = nn.RNN(5, 10, batch_first=True)  # 입력: [B, T, F]

x = torch.randn(7, 3, 5)                  # T=7, B=3, F=5
out, h_n = rnn(x)
# out: [7, 3, 10], h_n: [1, 3, 10]
```

- Sample: 모델에 들어가는 데이터 한 묶음, Timestep: 그 안의 각 시점, Feature: 시점마다 관측한 값
- Feature가 1개여도 마지막 축은 지우지 않고 `[T, B, 1]`로 둔다.

### 꼬리질문
#### batch_first=True로 바꾸면 h_n의 모양도 바뀌나요?
바뀌지 않습니다. `batch_first`는 입력과 out에만 적용되고, h_n은 항상 `(층 수 × 방향 수, B, H)`입니다. 자주 헷갈리는 부분입니다.

#### Feature가 1개라고 [T, B]로 넣으면 어떻게 되나요?
PyTorch는 2차원 입력을 배치가 없는 `(T, F)`로 해석하기 때문에 모양이 맞지 않아 에러가 나거나 의도와 다르게 계산됩니다. 그래서 `x.unsqueeze(-1)`로 마지막 축을 만들어 넣습니다.

## Q. nn.RNN이 반환하는 out과 h_n은 어떻게 다른가요?
id: rnn-out-vs-hn
type: 비교
level: 기본
tags: PyTorch, out, h_n
source: 6. 실습: 숫자 기억하기 › 처음 본 숫자 맞추기

### 30초 답변
out은 마지막 층의 모든 시점 hₜ를 모은 것으로 모양이 `[T, B, H]`이고, h_n은 마지막 시점의 hₜ를 층마다 모은 것으로 `[층 수, B, H]`입니다. 매 시점 답이 필요한 Many-to-Many는 out 전체를, 끝에서 한 번 답하는 Many-to-One은 마지막 시점 하나만 씁니다. 단층·단방향이면 `out[-1]`과 `h_n[0]`은 같은 값입니다.

### 자세히
| 표현 | 모양 | 특징 |
|---|---|---|
| out | (T, B, H) | 모든 시점의 hₜ, Many-to-Many에 사용 |
| out[-1] | (B, H) | 바로 nn.Linear에 넣을 수 있다 |
| h_n | (num_layers, B, H) | 3차원이라 h_n[-1]이나 h_n[0]으로 꺼내야 한다 |

```python
H, _ = self.rnn(x); return self.fc(H)       # Many-to-Many
h, _ = self.rnn(x); return self.fc(h[-1])   # Many-to-One
```

### 꼬리질문
#### LSTM은 반환값이 어떻게 다른가요?
`out, (h_n, c_n) = lstm(x)`처럼 마지막 cell state c_n이 튜플로 함께 나옵니다. out과 h_n은 RNN과 같은 의미라서 `H, _ = self.rnn(x)`처럼 out만 쓰던 코드는 nn.RNN을 nn.LSTM으로 바꿔도 그대로 돌아갑니다.

#### 양방향 RNN에서도 out[-1]을 그대로 쓰면 되나요?
조심해야 합니다. out[-1]의 역방향 절반은 마지막 시점 하나만 읽은 값이라 요약이 되지 않습니다. 보통 h_n에서 정방향과 역방향의 마지막 상태를 꺼내 이어 붙여 씁니다.

## Q. BPTT(Backpropagation Through Time)란 무엇인가요?
id: rnn-bptt
type: 개념
level: 기본
tags: BPTT, 역전파, 학습
source: 5. RNN은 어떻게 학습할까

### 30초 답변
BPTT는 RNN을 시간 축으로 펼쳐서 가중치를 공유하는 깊은 네트워크로 보고, 거기에 일반 역전파를 적용하는 방법입니다. 순전파는 첫 시점부터 마지막 시점까지 가고, 역전파는 마지막 시점에서 시작해 앞 시점으로 기울기를 넘깁니다. 같은 가중치가 모든 시점에서 쓰였으므로 시점마다 나온 기울기를 전부 더해서 한 번 업데이트합니다.

### 자세히
```
∂L/∂Wₕ = Σₜ (∂L/∂hₜ) · (∂hₜ/∂Wₕ)          # 칸별 기울기의 합
∂hₜ/∂hₜ₋₁ = diag(tanh′(·)) · Wₕ           # 한 칸 거슬러 갈 때 곱해지는 값
```

- PyTorch에서는 `loss.backward()` 한 줄이 BPTT를 수행한다.
- 학습 절차 자체는 다른 신경망과 같다: 순전파 → 손실 → 역전파 → 업데이트.
- 모든 시점의 중간값을 저장해야 하므로 길이가 길수록 메모리가 많이 든다.

### 꼬리질문
#### Many-to-Many에서는 hₜ가 받는 기울기가 어떻게 되나요?
각 hₜ는 자기 시점 손실에서 오는 기울기와, 다음 시점 hₜ₊₁에서 거슬러 넘어온 기울기를 더해서 받습니다. Many-to-One은 마지막 시점에만 손실이 있으므로 앞 시점들은 넘어온 기울기만 받습니다.

## Q. BPTT를 직접 손으로 계산해 본 적이 있나요?
id: rnn-bptt-by-hand-exp
type: 경험
level: 심화
tags: BPTT, 수치 미분, 기울기 검증
source: 5. RNN은 어떻게 학습할까

### 30초 답변
앞의 3시점 RNN 예제에서 마지막 출력 h₃를 정답 0.5와 비교해 손실을 만들고, 칸별 기울기를 직접 계산했습니다. Wₕ는 세 칸에서 모두 쓰였으니 기울기도 칸마다 하나씩 나오고, 최종 기울기는 그 합이었습니다. 1번 칸의 Wₕ 기울기는 h₀ = 0이라 0이었습니다. 마지막으로 Wₕ를 아주 조금 올리고 내렸을 때의 손실 변화와 비교했더니 소수점 여섯째 자리까지 같았습니다.

### 자세히
```
수치 미분:  ∂L/∂Wₕ ≈ (L(Wₕ + ε) − L(Wₕ − ε)) / 2ε
```

- 1번 칸에서 Wₕ에 곱해진 값은 h₀ = 0이므로 그 칸의 기울기는 0이다.
- 칸이 세 개여도 W는 하나다. 합한 기울기로 한 번 업데이트하고, 바뀐 W를 모든 칸이 같이 쓴다.
- 이 비교로 역전파가 "W를 살짝 바꾸면 손실이 얼마나 변하나"를 효율적으로 계산하는 방법이라는 것을 확인했다.

### 꼬리질문
#### 그럼 왜 학습할 때는 수치 미분을 쓰지 않나요?
수치 미분은 파라미터 하나마다 순전파를 두 번씩 해야 해서 파라미터가 많으면 비용이 감당되지 않습니다. 역전파는 역방향 계산 한 번으로 모든 파라미터의 기울기를 구하므로, 수치 미분은 구현이 맞는지 검증할 때만 씁니다.

## Q. Truncated BPTT란 무엇이고, 언제 쓰나요?
id: rnn-truncated-bptt
type: 개념
level: 심화
tags: Truncated BPTT, 긴 시퀀스, 메모리
source: 보충 (블로그 밖 내용)

### 30초 답변
Truncated BPTT는 아주 긴 시퀀스를 k시점짜리 구간으로 나누고, 역전파를 그 구간 안에서만 하는 방법입니다. 순전파에서 hidden state 값은 다음 구간으로 넘겨 주지만 기울기 연결은 구간 경계에서 끊습니다. 메모리와 계산량이 줄어드는 대신, k보다 먼 시점 사이의 의존성은 기울기로 직접 배우기 어렵습니다.

### 자세히
```python
h = None
for x_chunk, y_chunk in chunks(seq, k):   # k시점씩
    out, h = rnn(x_chunk, h)
    loss = criterion(fc(out), y_chunk)
    optimizer.zero_grad(); loss.backward(); optimizer.step()
    h = h.detach()                         # 값은 넘기고 기울기 연결은 끊는다
```

- 장점: 메모리가 k에 비례하고, 업데이트를 자주 할 수 있다.
- 단점: 기울기가 최대 k칸까지만 거슬러 가므로 그보다 긴 의존성 학습이 약하다.

### 꼬리질문
#### detach()를 빼먹으면 어떻게 되나요?
계산 그래프가 시퀀스 처음부터 계속 이어져서 메모리가 계속 늘어나고, 이미 역전파하고 해제한 그래프를 다시 거슬러 가려다 "backward through the graph a second time" 에러가 납니다.

## Q. RNN의 장기 의존성 문제란 무엇인가요?
id: rnn-long-term-dependency
type: 개념
level: 기본
tags: 장기 의존성, Long-term Dependency, 한계
source: 7. RNN의 한계 › 오래된 정보가 희석된다

### 30초 답변
장기 의존성은 오래전 정보가 지금 판단에 필요한 관계로, 문장 앞부분의 주어가 한참 뒤 동사의 형태를 정하는 경우가 예입니다. RNN은 새 입력이 들어올 때마다 Hidden State를 다시 계산하기 때문에 오래된 정보가 새 정보에 조금씩 덮입니다. 직접 계산해 보니 첫 입력만 다르게 넣었을 때 생긴 hₜ 차이가 12시점 만에 거의 사라졌습니다.

### 자세히
입력 12개 중 x₁만 +2와 -2로 다르게 하고 나머지는 같게 넣은 뒤, 두 경우의 hₜ 차이(= x₁의 흔적)를 계산했다.

| 시점 | Wₕ = 0.5 | Wₕ = 1.0 |
|---|---|---|
| 1 | 1.93 | 1.93 |
| 12 | 0.0000012 | 0.00016 |

- 매 시점 `tanh(Wₓxₜ + Wₕhₜ₋₁ + b)`로 기억을 새로 만들면서 옛 정보에 Wₕ와 tanh가 계속 곱해진다.
- 순전파에서 정보가 희석되는 문제이고, 역전파에서는 같은 원인으로 기울기 소실이 생긴다.

### 꼬리질문
#### Hidden 크기를 키우면 해결되나요?
담을 수 있는 정보량은 늘지만, 매 시점 같은 곱셈으로 기억을 다시 만드는 구조는 그대로라서 근본적인 해결은 되지 않습니다. 그래서 기억이 지나가는 길 자체를 바꾼 LSTM이 나왔습니다.

## Q. RNN에서 기울기 소실과 기울기 폭발은 왜 생기나요?
id: rnn-vanishing-exploding
type: 이유
level: 기본
tags: 기울기 소실, 기울기 폭발, BPTT
source: 7. RNN의 한계 › 기울기가 사라지거나 폭발한다

### 30초 답변
BPTT로 한 칸 거슬러 올라갈 때마다 기울기에 `tanh′ × Wₕ`가 곱해지고, 시점이 많으면 같은 값이 거듭제곱으로 곱해집니다. 그 배율이 1보다 작으면 지수적으로 줄어 먼 과거 시점은 학습 신호를 거의 못 받고, 이것이 기울기 소실입니다. 반대로 1보다 크면 지수적으로 커져 학습이 불안정해지는 기울기 폭발이 됩니다.

### 자세히
```
∂h_T/∂h_k = Π_{t=k+1..T} diag(tanh′ₜ) · Wₕ
배율 0.8 → 0.8⁵⁰ ≈ 1/70,000        배율 1.2 → 1.2⁵⁰ ≈ 9,100
```

- 행렬로 보면 Wₕ를 반복해서 곱하는 셈이다. Wₕ의 고유값 크기가 1보다 작은 방향은 0으로, 1보다 큰 방향은 폭발한다.
- tanh′ ≤ 1이라서 Wₕ의 가장 큰 특이값이 1보다 작으면 기울기는 반드시 지수적으로 준다(보충, Pascanu 등 2013).
- 깊은 MLP는 층마다 다른 가중치지만, RNN은 같은 행렬이 반복되므로 이 효과가 더 직접적으로 나타난다.

### 꼬리질문
#### 소실과 폭발 중 무엇이 더 다루기 어렵나요?
보통 소실입니다. 폭발은 손실이 NaN이 되는 식으로 바로 드러나고 gradient clipping으로 쉽게 막을 수 있지만, 소실은 먼 의존성을 조용히 못 배울 뿐이라 잘 보이지 않고 LSTM, GRU처럼 구조를 바꿔야 합니다.

#### 그 밖의 대책에는 무엇이 있나요?
폭발에는 gradient clipping, 소실에는 게이트 구조(LSTM, GRU)가 대표적입니다. 보충으로 Wₕ를 직교 행렬로 초기화해 배율을 1 근처에서 시작하게 하는 방법도 씁니다.

## Q. Gradient clipping이란 무엇인가요?
id: rnn-gradient-clipping
type: 개념
level: 심화
tags: Gradient Clipping, 기울기 폭발
source: 보충 (블로그 밖 내용)

### 30초 답변
Gradient clipping은 기울기의 크기가 정한 임계값을 넘으면 크기를 줄여서 업데이트하는 방법으로, 기울기 폭발을 막는 대표적인 대책입니다. 보통 전체 기울기의 노름을 계산해 임계값을 넘을 때 방향은 그대로 두고 길이만 줄입니다. 기울기가 커지는 것은 막지만 작아지는 소실 문제는 해결하지 못합니다.

### 자세히
```
‖g‖ > c 이면  g ← g · c / ‖g‖
```
```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

- 위치는 backward와 step 사이다.
- 노름 기준 clipping은 방향을 유지한다. 원소마다 자르는 value clipping(`clip_grad_value_`)은 방향이 바뀔 수 있다.

### 꼬리질문
#### 임계값은 어떻게 정하나요?
`clip_grad_norm_`이 자르기 전 전체 노름을 반환하므로, 학습 중 이 값을 기록해 평소 크기를 보고 그보다 조금 큰 값으로 정합니다. 1이나 5 같은 값으로 시작해 조정하는 경우가 많습니다.

## Q. LSTM은 어떤 아이디어로 RNN의 한계를 줄였나요?
id: rnn-lstm-idea
type: 개념
level: 기본
tags: LSTM, Cell State, Vanilla RNN
source: 8. LSTM: 곱하지 말고 더하자 › 핵심 아이디어

### 30초 답변
LSTM(Long Short-Term Memory)은 1997년 Hochreiter와 Schmidhuber가 제안한 모델로, RNN이 오래된 정보를 유지하지 못하는 문제를 줄이려고 만들었습니다. 핵심은 "곱하지 말고 더하자"입니다. RNN처럼 기억을 매 시점 곱해서 새로 만들지 않고, Cell State라는 별도의 기억 통로를 그대로 흘려보내면서 Gate로 필요한 만큼만 지우고 더합니다.

### 자세히
```
RNN:   hₜ = tanh(Wₓxₜ + Wₕhₜ₋₁ + b)       # 기억을 매번 새로 만든다
LSTM:  Cₜ = fₜ ⊙ Cₜ₋₁ + iₜ ⊙ gₜ           # 기억은 지나가고 조금씩 지우고 더한다
```

- 구성: Cell State Cₜ, Gate 3개(망각 fₜ, 입력 iₜ, 출력 oₜ), 후보값 gₜ
- 기본 RNN은 Vanilla RNN이라고도 부른다. 정식 명칭은 Elman RNN(Elman, 1990)이고 Keras에서는 SimpleRNN이다.

### 꼬리질문
#### "Long Short-Term Memory"라는 이름은 무슨 뜻인가요?
RNN의 hidden state 같은 단기 기억(short-term memory)을 오래(long) 유지하게 만든다는 뜻입니다. 장기 기억과 단기 기억 두 개가 따로 있다는 뜻이 아닙니다.

## Q. LSTM의 Gate란 무엇인가요?
id: rnn-gate
type: 개념
level: 기본
tags: LSTM, Gate, sigmoid
source: 8. LSTM › Gate: 얼마나 통과시킬지 정하는 0~1 값

### 30초 답변
Gate는 정보의 각 성분을 얼마나 통과시킬지 정하는 0~1 사이 값의 벡터입니다. 정보와 같은 자리끼리 곱해서 0에 가까우면 거의 막고 1에 가까우면 그대로 통과시킵니다. 값은 sigmoid를 거쳐 나오므로 항상 0~1이고, 얼마나 열지는 Gate 안의 가중치가 정하며 이 가중치도 학습으로 정해집니다.

### 자세히
```
gate  = σ(W · [hₜ₋₁, xₜ] + b)       # 0~1 벡터
결과  = gate ⊙ 정보                  # ⊙: 같은 자리끼리 곱
예: [0.9, 0.1, 0.5] ⊙ [2, 3, -1] = [1.8, 0.3, -0.5]
```

- 사람이 정하는 스위치가 아니라, 현재 입력 xₜ와 직전 출력 hₜ₋₁를 보고 매 시점 새로 계산된다.
- LSTM의 Gate는 망각(fₜ), 입력(iₜ), 출력(oₜ) 세 개다.

### 꼬리질문
#### Gate에는 sigmoid를, 후보값에는 tanh를 쓰는 이유는 무엇인가요?
Gate는 통과 비율이라 0~1 범위가 맞습니다. 후보값은 기억에 더하거나 뺄 내용 자체라서 부호가 있는 -1~1 범위의 tanh를 씁니다.

#### Gate 값이 정확히 0이나 1이 되나요?
sigmoid라서 0이나 1에 가까워질 뿐 정확히 되지는 않습니다. 대신 부드럽게 변하므로 미분이 가능하고, 그래서 Gate를 여닫는 방법을 경사하강법으로 학습할 수 있습니다.

## Q. LSTM의 망각 게이트(forget gate)는 어떤 역할을 하나요?
id: rnn-forget-gate
type: 개념
level: 기본
tags: LSTM, Forget Gate
source: 8. LSTM › LSTM 셀 구조

### 30초 답변
망각 게이트 fₜ는 이전 Cell State Cₜ₋₁을 얼마나 남길지 정합니다. fₜ가 1이면 이전 기억을 그대로 두고, 0이면 다 지웁니다. 예를 들어 문장에서 새로운 주어가 나오면 이전 주어 정보를 지우는 식으로 쓸모가 끝난 기억을 정리합니다.

### 자세히
```
fₜ = σ(W_f · [hₜ₋₁, xₜ] + b_f)
Cₜ = fₜ ⊙ Cₜ₋₁ + ...
```

- 직접 계산한 예: Cₜ₋₁ = 2, fₜ = 0.760 → 1.52만 남긴다.
- Cell State 경로의 기울기도 이 fₜ에 곱해진다. 그래서 fₜ가 기억의 길이와 기울기 전달을 같이 정한다.
- 보충: 1997년 원래 LSTM에는 망각 게이트가 없었고, 이후 Gers 등(2000)이 추가했다.

### 꼬리질문
#### 망각 게이트가 없거나 항상 1이면 어떤 문제가 생기나요?
기억이 지워지지 않고 계속 더해지기만 해서 Cell State가 한없이 커질 수 있고, 다 쓴 정보를 정리하지 못합니다. 긴 연속 입력에서 이 문제가 드러나 망각 게이트가 추가됐습니다.

## Q. LSTM의 입력 게이트와 후보값은 각각 무엇을 하나요?
id: rnn-input-gate
type: 개념
level: 기본
tags: LSTM, Input Gate, 후보값
source: 8. LSTM › LSTM 셀 구조

### 30초 답변
후보값 gₜ는 이번 시점에 새로 기록할 내용이고, tanh를 거쳐 -1~1 값으로 나옵니다. 입력 게이트 iₜ는 그 후보를 얼마나 반영할지 정하는 0~1 비율입니다. 둘을 같은 자리끼리 곱한 `iₜ ⊙ gₜ`를 Cell State에 더하고, iₜ가 0이면 새 정보를 하나도 넣지 않습니다.

### 자세히
```
iₜ = σ(W_i · [hₜ₋₁, xₜ] + b_i)
gₜ = tanh(W_g · [hₜ₋₁, xₜ] + b_g)
Cₜ = fₜ ⊙ Cₜ₋₁ + iₜ ⊙ gₜ
```

- 직접 계산한 예: 후보값 0.635 중 iₜ = 0.690만큼 반영 → 0.44를 더한다.
- 후보값이 음수일 수 있으므로 기억을 더하는 것뿐 아니라 줄이는 것도 가능하다.

### 꼬리질문
#### 입력 게이트와 후보값을 왜 따로 두나요?
무엇을 쓸지(내용)와 얼마나 쓸지(양)를 분리하기 위해서입니다. 후보값만 있으면 매 시점 무조건 기억에 쓰게 되어 중요하지 않은 입력이 저장된 기억을 계속 덮어씁니다.

## Q. LSTM의 출력 게이트는 어떤 역할을 하나요?
id: rnn-output-gate
type: 개념
level: 기본
tags: LSTM, Output Gate
source: 8. LSTM › LSTM 셀 구조

### 30초 답변
출력 게이트 oₜ는 Cell State에 담긴 기억 중 얼마를 이번 시점의 출력 hₜ로 꺼낼지 정합니다. hₜ는 Cₜ를 tanh로 눌러 -1~1로 만든 뒤 oₜ를 곱한 값입니다. 덕분에 기억은 Cell State에 계속 유지하면서도, 지금 답에 필요 없는 내용은 출력에 드러내지 않을 수 있습니다.

### 자세히
```
oₜ = σ(W_o · [hₜ₋₁, xₜ] + b_o)
hₜ = oₜ ⊙ tanh(Cₜ)
```

- 직접 계산한 예: Cₜ = 1.957 → tanh(1.957) ≈ 0.96, 이 중 74%만 꺼내 hₜ = 0.712
- hₜ는 출력층으로도 가고, 다음 시점 Gate 계산의 입력으로도 쓰인다.

### 꼬리질문
#### hₜ를 만들 때 Cₜ에 tanh를 한 번 더 씌우는 이유는 무엇인가요?
Cₜ는 덧셈으로 누적되어 -1~1을 넘을 수 있습니다. 출력과 다음 시점 입력으로 쓰이는 hₜ의 범위를 안정적으로 묶기 위해 tanh로 한 번 누릅니다.

## Q. LSTM 셀 한 시점의 계산 과정을 순서대로 설명해 보세요.
id: rnn-lstm-equations
type: 개념
level: 심화
tags: LSTM, 수식, 순전파
source: 8. LSTM › 숫자로 한 시점 따라가기

### 30초 답변
먼저 직전 출력 hₜ₋₁과 현재 입력 xₜ를 이어 붙여서 망각 게이트, 입력 게이트, 출력 게이트, 후보값 네 개를 계산합니다. 다음으로 이전 Cell State에 망각 게이트를 곱하고 입력 게이트를 곱한 후보값을 더해 새 Cell State를 만듭니다. 마지막으로 새 Cell State를 tanh로 누르고 출력 게이트를 곱해 hₜ를 냅니다.

### 자세히
```
fₜ, iₜ, oₜ = σ(W_· · [hₜ₋₁, xₜ] + b_·)   # 게이트마다 W, b가 따로 있다
gₜ = tanh(W_g · [hₜ₋₁, xₜ] + b_g)
Cₜ = fₜ ⊙ Cₜ₋₁ + iₜ ⊙ gₜ
hₜ = oₜ ⊙ tanh(Cₜ)
```

입력 1개, hidden 1개, 임의 가중치로 한 시점을 계산한 결과

| 단계 | 값 |
|---|---|
| 남길 기억 | 0.760 × 2 = 1.52 |
| 더할 정보 | 0.690 × 0.635 = 0.44 |
| 새 Cₜ | 1.957 |
| 출력 hₜ | 0.74 × tanh(1.957) = 0.712 |

### 꼬리질문
#### 네 개의 식을 실제로는 어떻게 계산하나요?
따로 네 번 계산하지 않고, 네 식의 가중치를 세로로 이어 붙인 큰 행렬로 한 번에 곱한 뒤 결과를 네 조각으로 나눕니다. PyTorch의 `weight_ih_l0` 모양이 `(4H, F)`이고 조각 순서는 입력, 망각, 후보, 출력(i, f, g, o)입니다.

## Q. LSTM의 Cell State와 Hidden State는 어떻게 다른가요?
id: rnn-cell-vs-hidden
type: 비교
level: 기본
tags: LSTM, Cell State, Hidden State
source: 8. LSTM › Cell State와 Hidden State는 다르다

### 30초 답변
Cell State Cₜ는 오래 유지할 정보를 나르는 내부 기억 통로이고, 곱셈 한 번과 덧셈 한 번으로만 갱신됩니다. Hidden State hₜ는 Cₜ를 tanh로 누르고 출력 게이트를 곱한 요약값으로, 출력층과 다음 시점 Gate 계산에 쓰입니다. 같은 입력 1을 열 번 넣어 보니 Cₜ는 쌓여서 1.69까지 갔지만 hₜ는 항상 -1~1 안에 있었습니다.

### 자세히
| | Cell State Cₜ | Hidden State hₜ |
|---|---|---|
| 역할 | 장기 기억 통로 | 현재까지의 요약, 출력 |
| 갱신 | fₜ ⊙ Cₜ₋₁ + iₜ ⊙ gₜ | oₜ ⊙ tanh(Cₜ) |
| 범위 | 제한 없음(누적 가능) | -1 ~ 1 |
| 밖으로 나가나 | 셀 내부에서만 다음 시점으로 | 출력층과 다음 시점 Gate로 |
| PyTorch | c_n | out, h_n |

### 꼬리질문
#### Gate를 계산할 때 Cₜ₋₁도 보나요?
기본 LSTM은 hₜ₋₁과 xₜ만 보고 Cₜ₋₁은 직접 보지 않습니다. Cell State까지 Gate 입력으로 넣는 변형을 peephole LSTM이라고 합니다.

## Q. LSTM이 RNN보다 기울기 소실이 덜한 이유는 무엇인가요?
id: rnn-lstm-gradient
type: 이유
level: 기본
tags: LSTM, 기울기 소실, Cell State
source: 8. LSTM › 왜 기울기가 덜 사라질까

### 30초 답변
RNN은 한 칸 거슬러 갈 때마다 `tanh′ × Wₕ`가 곱해져 기울기가 빨리 사라집니다. LSTM의 Cell State 길에서는 `Cₜ = fₜ ⊙ Cₜ₋₁ + ...`라서 한 칸 거슬러 갈 때 망각 게이트 값 fₜ만 곱해지고, 같은 행렬의 반복 곱이나 tanh 미분이 끼지 않습니다. fₜ가 1에 가까우면 기억과 기울기가 그 길을 따라 거의 줄지 않고 멀리 갑니다.

### 자세히
```
RNN:   ∂hₜ/∂hₜ₋₁ = diag(tanh′) · Wₕ
LSTM:  ∂Cₜ/∂Cₜ₋₁ = fₜ          (Cell State 경로만 볼 때)
```

- 마지막 시점까지 이어진 배율을 계산해 보면 RNN은 20칸만 가도 10⁻⁵~10⁻⁷ 수준이고, LSTM은 fₜ가 1에 가까울수록 거의 줄지 않는다.
- 다만 fₜ가 0.5 근처면 0.5ⁿ으로 줄어서 LSTM도 RNN 못지않게 기울기가 사라진다. 구조만으로 해결되는 것은 아니다.
- 덧셈으로 기울기 길을 열어 준다는 점에서 ResNet의 잔차 연결과 같은 발상이다.

### 꼬리질문
#### LSTM은 기울기 폭발도 막아 주나요?
Cell State 경로의 배율 fₜ는 1을 넘지 않아 그 길로는 폭발이 잘 생기지 않지만, hₜ를 거치는 다른 경로와 큰 가중치 때문에 폭발이 생길 수 있습니다. 그래서 실무에서는 LSTM에도 gradient clipping을 함께 씁니다.

## Q. LSTM의 파라미터 수가 RNN의 정확히 4배인 이유는 무엇인가요?
id: rnn-lstm-params
type: 이유
level: 심화
tags: LSTM, 파라미터 수, 비용
source: 8. LSTM › 대신 비싸다

### 30초 답변
LSTM은 Gate 3개와 후보값 1개, 모두 네 개의 식을 계산하고, 식마다 RNN 하나와 같은 크기의 입력 가중치, 순환 가중치, bias를 가지기 때문입니다. 그래서 `nn.RNN(1, 64)`가 4,288개일 때 `nn.LSTM(1, 64)`는 정확히 4배인 17,152개입니다. 파라미터는 학습과 추론 모두에서 저장하고 계산해야 하므로 LSTM은 메모리와 속도 면에서 비싼 모델입니다.

### 자세히
```
RNN  = H·F + H·H + 2H
LSTM = 4 × (H·F + H·H + 2H)
GRU  = 3 × (H·F + H·H + 2H)

H=64, F=1:  RNN 4,288   GRU 12,864   LSTM 17,152
```

- 시점마다 계산량도 대략 4배라서 같은 길이를 처리하는 데 더 느리다.

### 꼬리질문
#### Hidden 크기를 두 배로 늘리면 파라미터는 얼마나 늘어나나요?
H·H 항이 대부분을 차지하므로 거의 4배로 늘어납니다. H가 64에서 128이 되면 순환 가중치만 4,096개에서 16,384개가 되고, LSTM은 여기에 다시 4를 곱합니다.

## Q. RNN과 LSTM을 같은 문제로 비교해 본 결과는 어땠나요?
id: rnn-exp-n-turn
type: 경험
level: 기본
tags: 실험, N턴 전 숫자, RNN vs LSTM
source: 9. RNN vs LSTM › A. N턴 전 숫자 맞추기

### 30초 답변
0~9 숫자가 하나씩 들어올 때 매 턴 "N턴 전 숫자"를 맞히는 Many-to-Many 문제로 비교한 수업 실습 결과를 봤습니다. 3턴 전까지는 둘 다 100%였지만 RNN은 5턴 전부터 틀리기 시작해 10턴 전에서는 찍는 수준인 10%까지 떨어졌습니다. LSTM은 20턴 전까지 98% 넘게 버티다가 30턴 전에서 27%로 무너졌습니다. 그래서 LSTM이 항상 좋은 것이 아니라 긴 기억이 필요할 때 좋은 것이라고 정리했습니다.

### 자세히
- 데이터: 정답 y는 입력 x를 N칸 뒤로 민 것, 앞 N칸은 0
- 비교 설정: `(T, B, F) = (100, 64, 1)`, Adam, 학습률 0.001, 3000 epoch
- 직접 짠 코드: `nn.RNN(1, 32)` + `nn.Linear(32, 1)`, MSE 손실, Adam 학습률 0.003

| N턴 전 | RNN | LSTM |
|---|---|---|
| 3 | 100% | 100% |
| 10 | 10% | 98% 이상 |
| 30 | - | 27% |

- 정확도는 예측을 반올림해 정답과 같은 비율로, 앞 N칸은 빼고 쟀다. 0~9를 찍으면 약 10%다.

### 꼬리질문
#### 그럼 언제 RNN을 고르겠습니까?
필요한 기억이 짧을 때입니다. 3턴 전 숫자는 RNN도 100% 맞혔으니, 이런 문제에 파라미터가 4배이고 느린 LSTM을 쓰는 것은 낭비입니다. 문제에 맞는 가장 단순한 모델부터 고르는 게 맞다고 생각합니다.

#### 회귀로 학습했는데 정확도를 어떻게 쟀나요?
숫자 하나를 값으로 예측하는 회귀라서 MSE로 학습하고, 평가할 때만 예측을 반올림해서 정답 정수와 같은지 셌습니다.

## Q. 시퀀스 맨 처음 숫자를 기억하는 실험에서는 어떤 결과가 나왔나요?
id: rnn-exp-first-number
type: 경험
level: 심화
tags: 실험, Many-to-One, 처음 본 숫자
source: 9. RNN vs LSTM › B. 처음 본 숫자 맞추기

### 30초 답변
숫자를 T개 다 본 뒤 맨 처음 숫자를 한 번만 답하는 Many-to-One 문제였습니다. RNN은 길이 10부터 바로 10%로 떨어졌고, LSTM은 길이 30까지 100%를 유지하다가 50에서 89%로 내려갔습니다. 첫 숫자를 T칸 내내 온전히 들고 있어야 하는 문제라 두 모델의 기억 길이 차이가 크게 드러났습니다.

### 자세히
- 설정: `(5, 64, 1)`에서 시작해 길이를 늘림, Adam, 학습률 0.01, 2000 epoch (수업 자료 결과)
- 모델: 마지막 시점만 출력층에 넣는다.

```python
h, _ = self.rnn(x)        # (T, B, H)
return self.fc(h[-1])     # (B, H) → (B, 1)
```

| 길이 | RNN | LSTM |
|---|---|---|
| 10 | 10% | 100% |
| 30 | - | 100% |
| 50 | - | 89% |

### 꼬리질문
#### N턴 전 숫자 맞추기보다 어떤 점이 더 어려운가요?
N턴 전 문제는 매 시점 손실이 있어 기울기가 여러 곳에서 들어오고 기억할 거리가 N으로 고정입니다. 이 문제는 기억할 거리가 시퀀스 전체 길이이고 손실이 마지막 한 번뿐이라, 첫 시점까지 기울기가 T칸을 온전히 거슬러 가야 합니다.

## Q. 신호 다음 숫자를 맞히는 실험에서 RNN과 LSTM은 어떻게 달랐나요?
id: rnn-exp-signal
type: 경험
level: 심화
tags: 실험, 선택적 기억, RNN vs LSTM
source: 9. RNN vs LSTM › C. 신호 바로 다음 숫자 맞추기

### 30초 답변
숫자들 사이에 신호(10)가 한 번 나오고, 끝에서 그 신호 바로 다음 숫자를 맞히는 문제였습니다. 신호 위치가 매번 랜덤이라 모델이 무엇을 기억할지 스스로 골라야 합니다. 길이 10에서는 둘 다 애매했고 20, 30에서는 의외로 RNN도 꽤 잘 맞혔지만, 길이 50이 되자 RNN은 8%로 무너지고 LSTM은 100%를 찍었습니다.

### 자세히
- 설정: `(10, 64, 1)`에서 시작해 길이를 늘림, Adam, 학습률 0.001, 3000 epoch (수업 자료 결과)

| 길이 | RNN | LSTM |

| 10 | 애매 | 애매 |
| 20, 30 | 꽤 잘 맞힘 | - |
| 50 | 8% | 100% |

- 짧은 길이에서는 RNN도 반복 학습으로 규칙을 잡지만, 길이가 길어지면 저장한 값을 끝까지 지키지 못한다.

### 꼬리질문
#### 앞의 두 실험과 비교해 이 문제의 특징은 무엇인가요?
기억할 위치가 고정되어 있지 않아서, 입력 내용을 보고 언제 저장하고 언제 무시할지 정해야 합니다. 정보를 선택적으로 쓰고 지키는 능력이 필요한 문제라 Gate가 있는 LSTM의 장점이 가장 분명하게 나타났습니다.

## Q. RNN과 LSTM의 기울기를 직접 측정해 보면 어떤가요?
id: rnn-exp-measured-gradient
type: 경험
level: 심화
tags: 실험, 기울기 소실, 망각 bias, 초기화
source: 9. RNN vs LSTM › 기울기를 직접 재 보면

### 30초 답변
길이 50 시퀀스의 마지막 출력으로 손실을 만들고, 각 시점 hₜ가 받는 기울기 크기를 PyTorch로 잰 수업 자료 결과를 봤습니다. RNN은 50칸 전까지 기울기가 약 166억 배 줄었는데, 망각 bias를 0으로 둔 LSTM도 약 30억 배 줄었습니다. 망각 bias를 2로 올려 시작한 LSTM만 10배 정도로 버텼습니다. LSTM 구조만으로 기울기 소실이 해결되는 것이 아니라 망각 게이트가 열린 상태에서 시작해야 한다는 뜻입니다.

### 자세히
- bias 0 → fₜ ≈ σ(0) = 0.5에서 시작 → Cell State 경로에서도 0.5씩 계속 곱해진다.
- bias 2 → fₜ ≈ σ(2) ≈ 0.88에서 시작 → 기억과 기울기를 오래 끌고 간다.

```python
H = lstm.hidden_size
with torch.no_grad():                    # 게이트 순서: i, f, g, o
    lstm.bias_ih_l0[H:2*H].fill_(2.0)    # 망각 게이트 bias
    lstm.bias_hh_l0[H:2*H].fill_(0.0)
```

### 꼬리질문
#### PyTorch의 기본 초기화에서 망각 bias는 어떻게 되나요?
PyTorch는 LSTM의 가중치와 bias를 모두 ±1/√H 범위의 균등분포로 초기화하므로 망각 bias도 0 근처에서 시작합니다. 대부분은 그대로 충분하지만, 아주 긴 시퀀스에서는 망각 bias를 1~2 정도로 올려 주면 기억을 더 오래 합니다. 보충으로 Keras는 `unit_forget_bias=True`가 기본이라 1에서 시작합니다.

## Q. 학습된 LSTM의 Gate 값을 들여다본 적이 있나요?
id: rnn-exp-gate-values
type: 경험
level: 심화
tags: 실험, Gate, 해석
source: 9. RNN vs LSTM › Gate가 실제로 하는 일

### 30초 답변
신호 다음 숫자 맞추기 문제로 학습된 LSTM의 Gate 값을 시점별로 본 수업 자료 결과가 있었습니다. 신호가 들어온 t=12에서 망각 게이트가 0.098까지 떨어져 기존 내용을 비우고, 정답 숫자가 들어온 t=13에서는 입력 게이트를 0.994까지 열어 저장했습니다. t=14부터는 입력 게이트를 0.01 이하로 잠그고 망각 게이트를 0.91로 올려 저장한 값을 지켰습니다. 아무도 그렇게 하라고 가르치지 않았는데 정답을 맞히다 보니 Gate가 그렇게 학습된 것입니다.

### 자세히
| 시점 | 무슨 일 | 망각 게이트 | 입력 게이트 |
|---|---|---|---|
| t=12 | 신호 입력 | 0.098 (비우기) | - |
| t=13 | 정답 숫자 입력 | - | 0.994 (저장) |
| t=14~ | 이후 숫자 | 0.91 (유지) | 0.01 이하 (무시) |

- CNN 필터가 학습만으로 세로줄 모양이 되는 것과 같은 이야기다. 역할은 사람이 정하지 않고 손실을 줄이는 방향으로 생긴다.

### 꼬리질문
#### nn.LSTM에서 Gate 값은 어떻게 꺼내나요?
nn.LSTM은 out과 (h_n, c_n)만 반환하고 Gate 값은 돌려주지 않습니다. 그래서 학습된 가중치로 Gate 수식을 시점마다 직접 다시 계산하거나, nn.LSTMCell로 한 시점씩 돌리며 중간값을 계산해야 합니다.

## Q. GRU란 무엇이고, LSTM과 어떻게 다른가요?
id: rnn-gru
type: 개념
level: 기본
tags: GRU, Update Gate, Reset Gate
source: 10. 부록: RNN 변형들

### 30초 답변
GRU(Gated Recurrent Unit)는 2014년 Cho 등이 제안한 구조로, LSTM을 단순하게 만든 모델입니다. Cell State 없이 Hidden State 하나만 쓰고 Gate도 두 개입니다. Update Gate는 이전 상태와 새 후보 상태를 어떤 비율로 섞을지, Reset Gate는 새 후보를 만들 때 이전 상태를 얼마나 참고할지 정합니다. 파라미터가 RNN의 3배라 LSTM보다 싸면서 성능도 비슷하게 나오는 경우가 많습니다.

### 자세히
```
rₜ = σ(W_r · [hₜ₋₁, xₜ])                 Reset Gate
zₜ = σ(W_z · [hₜ₋₁, xₜ])                 Update Gate
ñₜ = tanh(W_n · [rₜ ⊙ hₜ₋₁, xₜ])         새 후보 상태
hₜ = (1 − zₜ) ⊙ ñₜ + zₜ ⊙ hₜ₋₁           (PyTorch 표기)
```

- zₜ와 1 − zₜ 중 어느 쪽에 이전 상태를 곱하는지는 자료마다 표기가 다르다. 의미는 같다.
- `nn.GRU(1, 64)` = 12,864개 (RNN의 3배)
- `nn.GRU`는 nn.RNN과 같은 반환 형식 `out, h_n`이다.

### 꼬리질문
#### Update Gate는 LSTM의 어떤 Gate들을 합친 셈인가요?
zₜ 하나로 이전 상태를 남길 비율과 새 후보를 넣을 비율(1 − zₜ)을 함께 정하므로 망각 게이트와 입력 게이트를 묶은 셈입니다. 출력 게이트는 없어서 상태 전체가 그대로 출력됩니다.

## Q. RNN, LSTM, GRU를 비교하고 어떻게 고를지 말해 보세요.
id: rnn-rnn-lstm-gru
type: 비교
level: 기본
tags: RNN, LSTM, GRU, 모델 선택
source: 10. 부록: RNN 변형들

### 30초 답변
RNN은 가장 단순하고 싸지만 기억이 짧고 기울기 소실이 심합니다. LSTM은 Cell State와 Gate 3개로 긴 기억을 다루지만 파라미터가 4배라 비쌉니다. GRU는 Gate 2개로 LSTM을 단순화해 파라미터가 3배이고 성능은 LSTM과 비슷한 경우가 많습니다. 어떤 것이 항상 낫다기보다 필요한 기억 길이, 검증 성능, 속도, 파라미터 수를 같이 보고 고릅니다.

### 자세히
| | RNN | LSTM | GRU |
|---|---|---|---|
| 상태 | hₜ | Cₜ, hₜ | hₜ |
| Gate | 없음 | 3개 (망각, 입력, 출력) | 2개 (Update, Reset) |
| 파라미터 | 1배 | 4배 | 3배 |
| 긴 의존성 | 약함 | 강함 | 강함 |
| PyTorch 반환 | out, h_n | out, (h_n, c_n) | out, h_n |

- 실험에서 3턴 전 기억은 RNN도 100%였다. 짧은 기억이면 RNN으로 충분하다.

### 꼬리질문
#### LSTM과 GRU 중 무엇을 먼저 시도하겠습니까?
데이터가 적거나 속도가 중요하면 파라미터가 적은 GRU를 먼저 시도해 볼 만합니다. 다만 둘의 우열은 데이터마다 달라서 결국 같은 조건으로 둘 다 돌려 검증 성능과 속도를 비교해 정합니다.

## Q. Stacked RNN(다층 RNN)은 무엇이고, 층을 쌓으면 무엇이 좋아지나요?
id: rnn-stacked
type: 개념
level: 심화
tags: Stacked RNN, num_layers, 깊이
source: 10. 부록: RNN 변형들

### 30초 답변
Stacked RNN은 RNN 층을 여러 개 쌓아서, 앞 층이 낸 출력 시퀀스를 다음 층이 다시 입력으로 받는 구조입니다. PyTorch에서는 `nn.LSTM(..., num_layers=3)`처럼 씁니다. 층을 쌓는 목적은 기억을 더 오래 하는 것이 아니라 더 추상적이고 복잡한 패턴을 잡는 것이고, 계산량과 과적합 위험도 같이 늘어납니다.

### 자세히
```
층 1:  x₁ x₂ ... x_T  →  h¹₁ h¹₂ ... h¹_T
층 2:  h¹₁ ... h¹_T   →  h²₁ ... h²_T   →  out
```

- out: 마지막 층의 모든 시점 `(T, B, H)`
- h_n: 층마다 마지막 시점 `(num_layers, B, H)`, Many-to-One에서는 `h_n[-1]`이 마지막 층이다.
- `nn.LSTM(..., num_layers=2, dropout=0.2)`의 dropout은 층과 층 사이에만 적용되고 마지막 층 출력에는 적용되지 않는다.

### 꼬리질문
#### 층을 쌓아도 기억이 길어지지 않는 이유는 무엇인가요?
시간 방향으로 정보가 전달되는 길은 층마다 여전히 한 칸씩 이어지는 같은 사슬이라서, 먼 시점까지의 거리가 줄지 않습니다. 층은 같은 시점의 표현을 더 깊게 가공할 뿐입니다.

## Q. Bidirectional RNN은 무엇이고, 언제 쓸 수 없나요?
id: rnn-bidirectional
type: 개념
level: 기본
tags: Bidirectional RNN, 양방향
source: 10. 부록: RNN 변형들

### 30초 답변
Bidirectional RNN은 앞에서부터 읽는 RNN과 뒤에서부터 읽는 RNN을 함께 써서, 각 시점에서 앞쪽과 뒤쪽 문맥을 모두 보게 만든 구조입니다. 문장 분류, 품사 태깅, 개체명 인식처럼 입력 전체를 미리 알고 있는 작업에 씁니다. 파라미터가 2배이고 뒤쪽 입력을 미리 알아야 하므로, 실시간 예측처럼 미래 입력이 아직 없는 상황에서는 쓸 수 없습니다.

### 자세히
```python
lstm = nn.LSTM(F, H, bidirectional=True)
out, (h_n, c_n) = lstm(x)
# out: (T, B, 2H)   시점마다 정방향과 역방향 hₜ를 이어 붙임
# h_n: (2 × num_layers, B, H)
```

- 출력층 입력 크기가 2H가 되므로 `nn.Linear(2*H, ...)`로 맞춰야 한다.
- 예: "배를 먹었다"에서 "배"의 뜻은 뒤 단어를 봐야 정해진다.

### 꼬리질문
#### 주가 예측에 양방향 RNN을 쓰면 어떻게 되나요?
학습 때는 미래 가격까지 입력으로 보게 되어 성능이 좋아 보이지만, 실제 예측 시점에는 미래 값이 없어서 그대로 쓸 수 없습니다. 미래 정보가 학습에 새어 들어간 데이터 누수입니다.
