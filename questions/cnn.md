## Q. 컴퓨터는 이미지를 어떻게 표현하고, 채널이란 무엇인가요?
id: cnn-image-as-tensor
type: 개념
level: 기본
tags: 이미지, 채널, 텐서, PyTorch
source: 1. 이미지는 그냥 숫자 행렬이다

### 30초 답변
컴퓨터에게 이미지는 픽셀마다 밝기 숫자가 하나씩 적힌 행렬입니다. 흑백 이미지는 행렬 한 장이고, 컬러 이미지는 빨강, 초록, 파랑 세 장의 행렬을 겹친 것인데 이 한 장 한 장을 채널이라고 부릅니다. PyTorch에서는 이미지 묶음을 `(Batch, Channel, Height, Width)` 순서의 4차원 텐서로 다룹니다.

### 자세히
- 흑백 8비트 이미지: 0이 검정, 255가 흰색인 2차원 행렬
- 컬러 이미지: R, G, B 3채널이라 같은 크기라도 숫자가 3배다.

| 데이터 | 한 장의 모양 | 배치 16장 텐서 |
|---|---|---|
| MNIST (흑백 28×28) | 1×28×28 | `(16, 1, 28, 28)` |
| CIFAR-10 (컬러 32×32) | 3×32×32 | `(16, 3, 32, 32)` |

- 학습 전에는 보통 0~255를 0~1로 나누고, 평균과 표준편차로 정규화한다.

### 꼬리질문
#### 이미지를 넘파이나 PIL로 읽으면 순서가 다르지 않나요?
네, 넘파이와 PIL은 보통 `(H, W, C)` 순서이고 PyTorch는 `(C, H, W)`입니다. `transforms.ToTensor()`가 순서를 바꾸고 값을 0~1로 나눠 주며, 직접 바꿀 때는 `permute(2, 0, 1)`을 씁니다.

#### 채널은 항상 색을 뜻하나요?
입력층에서만 색입니다. Conv층을 지난 뒤의 채널은 필터 하나가 만든 특성맵 한 장을 뜻하므로, "어떤 특징이 어디에 있는가"를 담은 지도라고 보는 게 맞습니다.

## Q. 이미지를 펴서 FC층(MLP)에 그대로 넣으면 어떤 문제가 있나요?
id: cnn-fc-limitations
type: 이유
level: 기본
tags: MLP, Flatten, 파라미터, 공간 구조
source: 2. 이미지를 FC에 그대로 넣으면 생기는 문제

### 30초 답변
두 가지 문제가 있습니다. 첫째, 한 줄로 펴는 순간 위아래로 붙어 있던 픽셀이 멀리 떨어져서 이웃 관계라는 공간 구조가 사라지고, 모델이 그 관계를 처음부터 다시 배워야 합니다. 둘째, 입력 픽셀마다 모든 은닉 노드와 연결되므로 가중치 수가 이미지 크기에 비례해 폭발합니다. 그래서 CNN은 앞쪽에서 작은 필터로 특징을 먼저 뽑고, 줄어든 특징만 FC에 넘깁니다.

### 자세히
- 이미지의 의미는 픽셀 하나가 아니라 주변 픽셀이 모인 덩어리(꺾인 선, 둥근 테두리)에서 나온다.
- FC층은 784개 입력을 서로 관계없는 별개의 값으로 받는다.

| 첫 층 | 가중치 수 |
|---|---|
| FC, 224×224×3 입력 → 은닉 128 | 224·224·3·128 ≈ 1,900만 |
| Conv, 3×3 필터 64개 (RGB) | 3·3·3·64 = 1,728 (이미지 크기와 무관) |

### 꼬리질문
#### 그래도 MNIST는 MLP로도 꽤 잘 맞히지 않나요?
MNIST는 작고 숫자가 가운데에 정렬된 데이터라 픽셀 위치만으로도 어느 정도 구분됩니다. 하지만 같은 숫자가 몇 칸만 옮겨져도 입력 벡터가 크게 달라져서, 위치 변화와 큰 이미지에는 약합니다.

## Q. CNN의 지역 연결(local connectivity)과 가중치 공유(weight sharing)를 설명해 보세요.
id: cnn-local-connectivity-weight-sharing
type: 개념
level: 기본
tags: 지역 연결, 가중치 공유, inductive bias, 파라미터
source: 보충 (블로그 밖 내용)

### 30초 답변
지역 연결은 출력 한 칸이 입력 전체가 아니라 필터 크기만큼의 작은 영역에만 연결된다는 뜻입니다. 가중치 공유는 같은 필터를 이미지의 모든 위치에 똑같이 적용한다는 뜻입니다. 이 두 가지 덕분에 파라미터 수가 입력 크기와 무관하게 필터 크기와 채널 수로만 정해지고, 한 위치에서 배운 패턴 탐지기를 다른 위치에서도 그대로 쓸 수 있습니다.

### 자세히
- 지역 연결: 가까운 픽셀끼리 관련이 깊다는 가정(locality)
- 가중치 공유: 같은 패턴은 이미지 어디에 나와도 같은 패턴이라는 가정

| | FC층 | Conv층 |
|---|---|---|
| 출력 한 칸이 보는 입력 | 전체 | K×K×C_in 영역 |
| 파라미터 수 | 입력 크기 × 출력 크기 | K·K·C_in·C_out + C_out |
| 입력 크기가 커지면 | 파라미터 증가 | 그대로 |

### 꼬리질문
#### 이런 가정을 inductive bias라고 하던데, 무엇인가요?
모델 구조에 미리 넣어 둔 가정을 말합니다. CNN은 지역성과 위치 이동에 대한 가정을 갖고 있어서 적은 데이터로도 잘 배우고, 이런 가정이 약한 Vision Transformer는 보통 훨씬 많은 데이터가 있어야 CNN만큼 성능이 나옵니다.

#### 가중치 공유가 오히려 맞지 않는 경우도 있나요?
얼굴처럼 위치가 정렬된 이미지에서는 눈 자리와 입 자리에서 찾아야 할 패턴이 다릅니다. 이런 경우 위치마다 다른 필터를 쓰는 locally connected layer를 쓰기도 합니다.

## Q. 합성곱 연산이 무엇인지 설명해 보세요.
id: cnn-convolution-operation
type: 개념
level: 기본
tags: 합성곱, 필터, 커널, 특성맵
source: 3. 합성곱 연산: 겹친 칸끼리 곱해서 더한다

### 30초 답변
합성곱은 필터 또는 커널이라고 부르는 작은 행렬을 이미지 위에 올리고, 겹친 칸끼리 곱한 뒤 전부 더해 출력 한 칸을 만드는 연산입니다. 필터를 왼쪽 위부터 한 칸씩 옮기면서 놓을 수 있는 모든 자리에서 이 계산을 반복하고, 그 결과를 모은 것을 특성맵(feature map)이라고 합니다. 필터가 놓일 수 있는 자리만큼만 출력이 나오므로 padding이 없으면 출력이 입력보다 작아집니다.

### 자세히
```
출력[i, j] = Σ_m Σ_n 입력[i+m, j+n] · 필터[m, n]  (+ bias)
```
- 필터는 왼쪽 위에서 출발해 오른쪽으로 이동하고, 줄 끝에 닿으면 다음 줄로 내려간다.
- 5×5 입력에 3×3 필터: 가로 3곳, 세로 3곳에 놓을 수 있어 출력은 3×3
- 블로그 예: 왼쪽 열 +1, 오른쪽 열 -1인 필터는 "왼쪽은 밝고 오른쪽은 어두운" 자리에서 값이 커진다.

### 꼬리질문
#### 딥러닝의 합성곱은 수학의 합성곱과 같은가요?
엄밀히는 다릅니다. 수학의 합성곱은 필터를 뒤집어서 곱하고, 딥러닝 프레임워크는 뒤집지 않는 교차상관(cross-correlation)을 계산합니다. 필터 값을 학습하므로 뒤집든 안 뒤집든 결과적으로 같은 표현력을 가져서 관례적으로 합성곱이라고 부릅니다.

#### 합성곱 한 층의 곱셈 횟수는 어떻게 계산하나요?
출력 한 칸에 K×K×C_in번 곱하고, 출력 칸이 H_out×W_out×C_out개이므로 둘을 곱하면 됩니다. 출력 크기에 비례하기 때문에 stride나 pooling으로 크기를 줄이면 연산량이 크게 줄어듭니다.

## Q. 필터는 무엇을 하는 것이고, 특성맵의 값은 무엇을 의미하나요?
id: cnn-filter-pattern-detector
type: 개념
level: 기본
tags: 필터, 특성맵, Sobel, 패턴 탐지
source: 4. 필터는 패턴 탐지기다

### 30초 답변
필터는 패턴 탐지기입니다. 곱해서 더하는 계산이라 필터와 비슷하게 생긴 영역을 만나면 값이 커지므로, 필터의 숫자 배치가 곧 찾고 싶은 모양입니다. 그래서 특성맵은 "이 필터가 찾는 모양이 이미지 어디에 얼마나 있는가"를 적어 놓은 지도라고 볼 수 있습니다.

### 자세히
- X 모양 필터 실험: X와 정확히 겹치는 자리에서 5가 나왔다. 필터의 1이 5개라 낼 수 있는 최댓값이다. X와 일부만 닮은 세로선 쪽은 1~4 정도였다.
- 사람이 설계한 대표 필터

| 필터 | 잡아내는 것 |
|---|---|
| Sobel x | 세로 경계 (벽, 창틀, 기둥) |
| Sobel y | 가로 경계 (지붕선, 땅) |
| Blur | 주변 평균으로 흐리게 |
| Sharpen | 경계를 강조해 선명하게 |

- 같은 그림에 숫자 9개만 바꿔 적용해도 결과가 크게 달라진다.

### 꼬리질문
#### 특성맵 값이 음수라면 무슨 뜻인가요?
필터가 찾는 모양과 반대 모양이 있다는 뜻입니다. 예를 들어 "왼쪽 밝고 오른쪽 어두운" 필터는 반대 방향 경계에서 음수가 나옵니다. 보통 Conv 뒤에 ReLU를 두어 음수를 0으로 만들고 "있다" 쪽 신호만 다음 층에 넘깁니다.

## Q. CNN에서 필터 값은 어떻게 정해지나요? 직접 확인해 본 적이 있나요?
id: cnn-filter-learning
type: 경험
level: 심화
tags: 필터, 역전파, 학습, 실험
source: 5. 그런데 필터 값은 사람이 정하지 않는다

### 30초 답변
CNN에서는 필터 안의 숫자가 곧 학습할 가중치이고, 손실을 줄이는 방향으로 역전파가 값을 바꿉니다. 저는 6×6 이미지의 가로줄과 세로줄을 구분하는 아주 작은 모델을 numpy로 만들어 확인해 봤습니다. 처음엔 의미 없던 3×3 필터가 300에폭 뒤에 가운데 열은 크게 음수, 양쪽 열은 양수인 세로줄 탐지기 모양이 됐습니다. 아무도 세로줄 필터를 만들라고 하지 않았는데 정답을 맞히다 보니 그렇게 된 겁니다.

### 자세히
```
구조: 3×3 필터 1개 → ReLU → 특성맵 평균 → w·x + b → sigmoid
데이터: 6×6 가로줄 6장, 세로줄 6장
```
- 학습 후 필터의 각 행 합이 0.13~0.14로 거의 0이다. 가로줄이 지나가면 한 행을 더하게 되므로 가로줄에는 거의 반응하지 않는다.
- 세로줄이 필터의 왼쪽이나 오른쪽 열에 걸리면 약 4.45가 나온다. 세로줄에 강하게 반응한다.
- 결론: CNN은 분류기뿐 아니라 어떤 특징을 뽑을지(필터 모양)까지 데이터에서 배운다.

### 꼬리질문
#### 필터를 전부 같은 값(예: 0)으로 초기화하면 어떻게 되나요?
같은 층의 필터들이 같은 출력을 내고 같은 기울기를 받아서 계속 똑같이 갱신됩니다. 필터를 여러 개 둔 의미가 없어지므로 무작위로 초기화해 대칭을 깨야 하고, ReLU를 쓰는 CNN은 보통 He 초기화를 씁니다.

## Q. Conv층의 출력 채널 수는 무엇으로 정해지나요?
id: cnn-filters-and-channels
type: 개념
level: 기본
tags: 필터 개수, 채널, nn.Conv2d
source: 6. 필터 개수와 채널

### 30초 답변
출력 채널 수는 필터 개수로 정해집니다. 필터 하나는 특징 하나만 찾으므로 세로선, 둥근 선, 모서리처럼 여러 특징을 찾으려고 필터를 여러 개 쓰고, 필터가 K개면 특성맵도 K장이 나와 출력 채널이 K가 됩니다. 입력 채널 수와는 상관없다는 점이 헷갈리기 쉬운 부분입니다.

### 자세히
```python
conv = nn.Conv2d(in_channels=3, out_channels=16, kernel_size=3)
x = torch.randn(1, 3, 32, 32)
conv(x).shape       # (1, 16, 30, 30)
conv.weight.shape   # (16, 3, 3, 3)  = (C_out, C_in, K, K)
conv.bias.shape     # (16,)          필터당 bias 1개
```
- `weight`의 모양은 "3×3×3 필터가 16개"라는 뜻이다.
- padding이 없어서 공간 크기도 32에서 30으로 줄었다.

### 꼬리질문
#### 출력 채널을 늘리면 무엇이 달라지나요?
찾을 수 있는 특징 종류가 늘어나는 대신, 그 층의 파라미터와 연산량이 출력 채널 수에 비례해 늘고 다음 층의 입력 채널도 함께 늘어납니다. 그래서 보통 앞쪽 층은 적게, 뒤쪽 층은 많이 둡니다.

## Q. RGB처럼 채널이 여러 개인 입력에는 합성곱을 어떻게 하나요?
id: cnn-multichannel-conv
type: 개념
level: 기본
tags: 다채널, 3D 필터, 채널
source: 6. 필터 개수와 채널

### 30초 답변
필터의 깊이를 입력 채널 수에 맞춥니다. 3채널 입력이면 필터 하나가 3×3×3 모양이고, 채널마다 겹친 칸끼리 곱해 더한 다음 세 채널의 결과를 다시 전부 더하고 bias를 하나 더해 특성맵 한 장을 만듭니다. 그래서 필터 하나는 입력 채널이 몇 개든 항상 특성맵 한 장을 냅니다.

### 자세히
```
입력 (3, H, W) * 필터 (3, 3, 3)  →  특성맵 (1, H', W')
출력[i, j] = Σ_c Σ_m Σ_n 입력[c, i+m, j+n] · 필터[c, m, n] + b
필터 K개  →  특성맵 K장  →  출력 (K, H', W')
```
- 필터는 가로·세로로만 움직이고 채널 방향으로는 움직이지 않는다. 깊이가 입력 채널과 같기 때문이다.
- 채널을 합치는 과정에서 색 정보나 이전 층의 여러 특징이 하나로 섞인다.

### 꼬리질문
#### 두 번째 Conv층 필터의 깊이는 얼마인가요?
첫 번째 Conv층의 출력 채널 수와 같습니다. 예를 들어 첫 층이 필터 64개를 썼다면 두 번째 층의 3×3 필터는 3×3×64 모양입니다.

## Q. Padding은 왜 쓰나요?
id: cnn-padding
type: 이유
level: 기본
tags: Padding, 경계, 출력 크기
source: 7. Padding: 크기가 줄어드는 걸 막는다

### 30초 답변
합성곱에는 두 가지 불편한 점이 있습니다. 층을 지날 때마다 출력이 작아지고, 가장자리 픽셀이 계산에 덜 참여해서 가장자리 특징이 덜 반영됩니다. 이미지 둘레를 0으로 한 겹 두르는 padding을 쓰면 출력 크기를 유지할 수 있고 가장자리 픽셀의 참여 횟수도 늘어납니다.

### 자세히
- 6×6 입력, 3×3 필터에서 각 칸이 계산에 들어간 횟수

| | 가운데 칸 | 모서리 칸 | 출력 크기 |
|---|---|---|---|
| padding 0 | 9번 | 1번 | 4×4 |
| padding 1 | 9번 | 4번 | 6×6 |

```python
F.pad(x, pad=(1, 1, 1, 1), value=0)        # 직접 붙이기 (좌, 우, 위, 아래)
nn.Conv2d(3, 16, kernel_size=3, padding=1)  # 보통 이쪽을 쓴다
```
- 0을 쓰는 이유: 곱해도 0이라 원래 값을 왜곡하지 않는다.

### 꼬리질문
#### 0 말고 다른 값으로 채우는 방법도 있나요?
가장자리 값을 거울처럼 반사하는 reflect, 가장자리 값을 그대로 늘리는 replicate 같은 방식이 있고 PyTorch에서는 `padding_mode`로 고릅니다. 0 패딩은 경계에 인위적인 검은 테두리를 만드는 셈이라, 이미지 생성처럼 경계 품질이 중요한 작업에서는 reflect를 쓰기도 합니다.

## Q. same padding과 valid padding의 차이는 무엇인가요?
id: cnn-same-valid-padding
type: 비교
level: 기본
tags: Padding, same, valid
source: 8. Stride › 출력 크기 공식

### 30초 답변
valid는 padding을 전혀 주지 않는 방식이라 필터 크기에 따라 출력이 줄어듭니다. same은 stride 1일 때 출력 크기가 입력과 같아지도록 padding을 주는 방식으로, 필터 크기 K가 홀수면 P = (K − 1) / 2로 두면 됩니다. 3×3 필터면 padding 1, 5×5 필터면 padding 2입니다.

### 자세히
| | valid | same |
|---|---|---|
| padding | 0 | (K − 1) / 2 |
| 출력 크기 (stride 1) | I − K + 1 | I |
| 32 입력, 3×3 필터 | 30 | 32 |

```python
nn.Conv2d(3, 16, kernel_size=3, padding=1)       # same
nn.Conv2d(3, 16, kernel_size=3, padding='same')  # stride 1에서만 허용
nn.Conv2d(3, 16, kernel_size=3, padding=0)       # valid
```

### 꼬리질문
#### 필터 크기는 왜 보통 홀수를 쓰나요?
홀수면 가운데 칸이 있어서 출력 한 칸이 입력의 어느 위치에 대응하는지 분명하고, same padding을 양쪽에 똑같이 (K − 1) / 2씩 줄 수 있습니다. 짝수 필터는 한쪽에 padding을 하나 더 줘야 해서 특성맵이 반 칸씩 치우칩니다.

## Q. Stride란 무엇이고, 키우면 무엇이 달라지나요?
id: cnn-stride
type: 개념
level: 기본
tags: Stride, 다운샘플링, 연산량
source: 8. Stride: 한 번에 몇 칸씩 옮길까

### 30초 답변
Stride는 필터를 한 번에 몇 칸씩 옮길지 정하는 값입니다. stride를 키우면 출력의 가로·세로가 줄어들고, 연산량이 출력 크기에 비례하므로 stride 2면 연산량이 약 1/4로 줄어듭니다. 대신 겹치던 계산이 빠지는 만큼 세밀한 정보가 줄고, 나누어떨어지지 않으면 가장자리 일부가 아예 계산에서 빠질 수 있습니다.

### 자세히
- 크기를 유지하면 층마다 연산량과 메모리 부담이 그대로 남고, 한 칸씩 옮긴 창은 서로 많이 겹쳐 비슷한 계산을 반복한다.
- 연산량 = 출력 가로 × 출력 세로 × 필터 개수 × (F × F × 입력 채널)
- stride 2: 출력 가로·세로가 각각 절반 → 연산량 1/4
- 7×7 입력, 3×3 필터, stride 3: 오른쪽과 아래 한 줄이 계산에서 빠진다. 다음 자리로 가려면 3칸이 필요한데 1칸만 남기 때문이다.

```python
nn.Conv2d(3, 16, 3, stride=2, padding=1)(torch.randn(1, 3, 32, 32)).shape  # (1, 16, 16, 16)
```

### 꼬리질문
#### stride를 크게 하면 어떤 정보를 잃나요?
필터가 건너뛴 자리의 응답을 계산하지 않으니 작은 특징의 정확한 위치나 촘촘한 변화가 사라집니다. 그래서 첫 층부터 큰 stride를 쓰기보다 stride 1로 특징을 충분히 뽑은 뒤 단계적으로 줄이는 설계가 흔합니다.

## Q. 합성곱 출력 크기 공식을 말하고 적용해 보세요.
id: cnn-output-size
type: 개념
level: 기본
tags: 출력 크기, Padding, Stride, 공식
source: 8. Stride › 출력 크기 공식

### 30초 답변
출력 크기는 O = (I − K + 2P) / S + 1이고, 나누어떨어지지 않으면 소수점을 버립니다. I는 입력 크기, K는 필터 크기, P는 padding, S는 stride입니다. 예를 들어 32×32 입력에 3×3 필터, padding 1, stride 2를 쓰면 31 / 2를 버림해서 15, 여기에 1을 더해 16이 됩니다.

### 자세히
```
O = floor((I − K + 2P) / S) + 1
```

| I | K | P | S | 출력 O |
|---|---|---|---|---|
| 32 | 3 | 1 | 1 | (32 − 3 + 2) / 1 + 1 = 32 |
| 32 | 3 | 1 | 2 | 31 / 2 → 15 + 1 = 16 |
| 28 | 5 | 2 | 1 | (28 − 5 + 4) / 1 + 1 = 28 |
| 7 | 3 | 0 | 3 | 4 / 3 → 1 + 1 = 2 |

- 가로와 세로에 따로 적용한다. 출력 채널 수는 이 공식이 아니라 필터 개수로 정해진다.

### 꼬리질문
#### Pooling 층에도 이 공식이 적용되나요?
네, 창 크기를 K로 보고 같은 공식을 씁니다. `MaxPool2d(2)`는 K=2, S=2, P=0이라 (I − 2) / 2 + 1 = I / 2로 가로·세로가 절반이 됩니다.

#### 공식에서 버림이 일어나면 실제로는 무슨 일이 생기나요?
필터가 마지막 자리까지 가지 못해서 오른쪽과 아래쪽 남는 픽셀이 계산에 쓰이지 않습니다. 이 손실을 피하려면 padding을 조절하거나, pooling에서는 `ceil_mode=True`로 남는 부분까지 창을 만들 수 있습니다.

## Q. Pooling이란 무엇이고, 왜 쓰나요?
id: cnn-pooling
type: 개념
level: 기본
tags: Pooling, 다운샘플링, 파라미터
source: 9. Pooling: 구역마다 대표값만 남긴다

### 30초 답변
Pooling은 특성맵을 구역으로 나누고 구역마다 대표값 하나만 남기는 연산입니다. 목적은 크기를 줄여 계산량을 덜어 주는 것과, 특징이 조금 움직여도 결과가 크게 바뀌지 않도록 작은 위치 변화에 둔감하게 만드는 것입니다. 정해진 규칙대로 값을 고르는 연산이라 학습할 파라미터가 없습니다.

### 자세히
```python
maxpool = nn.MaxPool2d(kernel_size=2, stride=2)   # stride 생략 시 kernel_size와 같음
sum(p.numel() for p in maxpool.parameters())      # 0
```
- 2×2, stride 2면 가로·세로가 절반, 칸 수는 1/4이 된다.
- 채널마다 따로 적용하므로 채널 수는 그대로다.
- 블로그 예: 값 9가 같은 2×2 구역 안에서 한 칸 움직여도 Max Pooling 결과는 같다. 구역을 벗어나면 달라지므로 "완전히 무시"가 아니라 "조금 둔감해진다"가 정확하다.

### 꼬리질문
#### 학습 파라미터가 없는데 역전파는 어떻게 되나요?
Max Pooling은 순전파 때 최댓값이었던 위치로만 기울기를 그대로 보내고 나머지 위치는 0을 받습니다. Average Pooling은 기울기를 구역 안 칸들에 똑같이 나눠 보냅니다.

## Q. Max Pooling과 Average Pooling을 비교해 보세요.
id: cnn-max-vs-avg-pooling
type: 비교
level: 기본
tags: Max Pooling, Average Pooling
source: 9. Pooling: 구역마다 대표값만 남긴다

### 30초 답변
Max Pooling은 구역에서 가장 큰 값을, Average Pooling은 평균을 남깁니다. CNN 중간층에서는 Max Pooling을 압도적으로 많이 쓰는데, "여기에 이 패턴이 있는가"를 판단할 때는 강한 반응 하나를 살리는 최댓값이 평균보다 쓸모 있기 때문입니다. 평균은 약한 값과 섞이면서 강한 신호가 흐려집니다.

### 자세히
```
입력 4×4                Max 2×2       Avg 2×2
[[1, 3, 2, 4],
 [5, 9, 1, 0],    →    [[9, 4],      [[4.50, 1.75],
 [2, 0, 7, 3],          [4, 8]]       [1.75, 6.00]]
 [1, 4, 6, 8]]
```

| | Max | Average |
|---|---|---|
| 남기는 값 | 가장 강한 반응 | 구역 전체의 평균 |
| 성격 | 특징의 존재 여부 강조 | 부드럽게 요약 |
| 주로 쓰는 곳 | 중간층 다운샘플링 | LeNet-5 원본, 마지막 층의 Global Average Pooling |

### 꼬리질문
#### Global Average Pooling은 무엇인가요?
특성맵 한 장 전체를 평균 내서 숫자 하나로 만드는 방식입니다. C×H×W 특성맵이 C개 숫자가 되므로, Flatten 대신 써서 바로 마지막 분류층에 넘길 수 있습니다.

## Q. Stride와 Pooling은 둘 다 크기를 줄이는데, 무엇이 다른가요?
id: cnn-stride-vs-pooling
type: 비교
level: 심화
tags: Stride, Pooling, 다운샘플링
source: 9. Pooling: 구역마다 대표값만 남긴다

### 30초 답변
Stride는 합성곱을 하면서 건너뛰는 방식으로 크기를 줄이고, 줄이는 과정에 학습되는 필터가 관여합니다. Pooling은 합성곱이 끝난 특성맵을 최댓값이나 평균이라는 고정된 규칙으로 요약하면서 줄이고, 학습할 값이 없습니다. 한 줄로 정리하면 padding은 의도치 않게 줄어드는 걸 막고, stride와 pooling은 필요할 때 일부러 줄이는 도구입니다.

### 자세히
| | Stride > 1 Conv | Pooling |
|---|---|---|
| 줄이는 방식 | 합성곱 자리를 건너뜀 | 구역별 대표값만 남김 |
| 학습 파라미터 | 있음 (필터) | 없음 |
| 연산량 절감 | 해당 Conv 자체가 가벼워짐 | Conv 뒤에 추가 연산 |
| 위치 변화 둔감성 | 따로 보장 안 함 | Max Pooling은 구역 안 이동에 둔감 |

- 최근 구조는 pooling 대신 stride 2 Conv로 다운샘플링하는 경우가 많다. 줄이는 방법까지 학습하게 하려는 것이다.

### 꼬리질문
#### Pooling 없이 stride만으로 CNN을 만들 수 있나요?
네, Conv층만으로 구성하고 다운샘플링을 stride 2 Conv로 대신한 구조도 비슷한 성능을 낸다고 알려져 있습니다. 다만 파라미터와 연산이 조금 늘어나므로, 작은 모델에서는 여전히 2×2 Max Pooling이 간단한 기본값입니다.

## Q. CNN의 translation equivariance와 translation invariance를 비교해 보세요.
id: cnn-equivariance-invariance
type: 비교
level: 심화
tags: 등변성, 불변성, 합성곱, Pooling
source: 보충 (블로그 밖 내용)

### 30초 답변
등변성(equivariance)은 입력이 옮겨지면 출력도 같은 만큼 옮겨지는 성질이고, 불변성(invariance)은 입력이 옮겨져도 출력이 바뀌지 않는 성질입니다. 합성곱은 같은 필터를 모든 위치에 쓰므로 등변성을 갖습니다. 불변성은 pooling과 마지막의 FC나 Global Pooling이 위치 정보를 점점 버리면서 근사적으로 생기고, 분류에는 결국 이 불변성이 필요합니다.

### 자세히
```
T = 평행이동, f = 층
등변성: f(T(x)) = T(f(x))    # Conv: 고양이가 옮겨지면 특성맵의 반응 위치도 옮겨짐
불변성: f(T(x)) = f(x)       # 분류 결과: 고양이가 어디 있든 "고양이"
```
- Max Pooling은 구역 안의 작은 이동에만 둔감하다. 층을 쌓을수록 둔감한 범위가 넓어진다.
- 완전한 불변은 아니다. stride나 pooling 때문에 한두 픽셀만 옮겨도 출력이 달라지는 경우가 있다.

### 꼬리질문
#### CNN은 회전이나 크기 변화에도 불변인가요?
아닙니다. 구조가 보장하는 건 평행이동에 대한 성질뿐이고, 회전이나 크기 변화에 대한 강건함은 데이터 증강 등으로 학습시켜야 생깁니다.

## Q. CNN의 전체 구조를 설명해 보세요.
id: cnn-architecture
type: 개념
level: 기본
tags: CNN 구조, 특징 추출, 분류기
source: 10. CNN 전체 구조

### 30초 답변
CNN은 특징 추출부와 분류부 두 부분으로 나뉩니다. 특징 추출부는 Conv → ReLU → Pool 블록을 보통 2~5번 반복하는데, Conv가 지역 패턴을 뽑고 Pool이 크기를 줄이면서 위치 변화에 둔감하게 만듭니다. 분류부는 특성맵을 Flatten해서 FC층에 넣고 클래스별 확률을 냅니다. 블록을 지날수록 공간 크기는 줄고 채널은 늘어납니다.

### 자세히
```
입력 → [Conv → ReLU → Pool] × N → Flatten → FC → ReLU → FC → Softmax
        └──── 특징 추출부 ────┘     └────── 분류부 (MLP) ──────┘
```
- 1×32×32 입력에 [Conv 3×3(padding 1) → ReLU → MaxPool 2×2] 4번, 필터 8, 16, 32, 64

| 블록 후 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 모양 | 8×16×16 | 16×8×8 | 32×4×4 | 64×2×2 |

- 공간 정보는 압축되고, "어떤 특징이 있는가"를 나타내는 채널은 많아진다.

### 꼬리질문
#### 공간이 줄어들 때 채널을 늘리는 이유는 무엇인가요?
뒤로 갈수록 조합해서 표현해야 할 특징 종류가 많아지기 때문입니다. 또 pooling으로 가로·세로가 절반이 되면 칸 수가 1/4로 줄어서, 채널을 2배로 늘려도 층마다 연산량이 크게 늘지 않고 비슷하게 유지됩니다.

#### 학습 흐름은 MLP와 무엇이 다른가요?
데이터를 (B, C, H, W) 텐서로 만들고 순전파가 Conv 블록을 지난다는 점만 다르고, 손실 계산, 역전파, 옵티마이저 스텝을 에폭만큼 반복하는 흐름은 같습니다.

## Q. Receptive field란 무엇이고, 층을 쌓으면 어떻게 변하나요?
id: cnn-receptive-field
type: 개념
level: 심화
tags: Receptive field, 수용 영역, 깊이
source: 보충 (블로그 밖 내용)

### 30초 답변
Receptive field는 출력 한 칸이 원래 입력 이미지에서 보고 있는 영역의 크기입니다. 3×3 Conv 한 층의 출력 한 칸은 입력 3×3을 보지만, 한 층을 더 쌓으면 그 3×3 각각이 다시 3×3을 보므로 5×5를 보게 됩니다. stride나 pooling이 끼면 훨씬 빠르게 커져서, 깊은 층일수록 넓은 영역을 보고 큰 구조를 판단할 수 있습니다.

### 자세히
```
stride 1인 3×3 Conv를 L층 쌓으면  RF = 1 + 2L    (1층 3, 2층 5, 3층 7)
일반식: RF_l = RF_(l−1) + (K_l − 1) × (앞 층들의 stride 곱)
```
- pooling이나 stride 2 뒤의 층은 한 칸이 입력의 여러 칸에 해당하므로 같은 3×3이라도 receptive field가 더 크게 늘어난다.
- 마지막 층의 receptive field가 물체 크기보다 작으면 물체 전체를 보고 판단할 수 없다.

### 꼬리질문
#### 파라미터를 늘리지 않고 receptive field를 키우는 방법이 있나요?
dilated(atrous) convolution이 있습니다. 필터 칸 사이를 띄워서 3×3 필터가 dilation 2면 5×5 영역을 보게 되고, 파라미터는 9개 그대로입니다. 해상도를 유지해야 하는 분할(segmentation) 모델에서 많이 씁니다.

## Q. CNN은 층이 깊어질수록 어떤 특징을 학습하나요?
id: cnn-feature-hierarchy
type: 개념
level: 기본
tags: 계층적 특징, 저수준, 고수준, 시각화
source: 보충 (블로그 밖 내용)

### 30초 답변
앞쪽 층은 경계, 색, 방향 같은 단순한 저수준 특징을 잡고, 가운데 층은 이를 조합해 질감이나 반복 무늬, 물체의 일부를 잡습니다. 깊은 층으로 갈수록 눈, 바퀴, 얼굴처럼 물체 단위의 고수준 특징에 반응합니다. 층마다 receptive field가 넓어지고 앞 층의 특징을 조합하기 때문에 이런 계층 구조가 생깁니다.

### 자세히
| 층 | 반응하는 특징 | 성격 |
|---|---|---|
| 앞쪽 | 경계, 색 덩어리, 방향 | 어느 데이터에서나 비슷함 |
| 중간 | 질감, 무늬, 모서리 조합 | 중간 |
| 뒤쪽 | 물체의 부분, 물체 전체 | 데이터와 과제에 특화됨 |

- 블로그의 Sobel 필터나 세로줄 필터 실험이 첫 층이 하는 일에 해당한다.
- 특성맵이나 필터를 시각화하는 연구(Zeiler & Fergus 등)로 이런 경향이 확인됐다.

### 꼬리질문
#### 첫 층 필터를 시각화하면 어떤 모양이 나오나요?
여러 방향의 경계 탐지기와 색 덩어리 탐지기처럼 생긴 필터가 주로 나옵니다. AlexNet 논문에서도 첫 층 필터를 시각화해 이런 모양을 보여 줬습니다.

## Q. 이미지를 바로 Flatten하면 문제라고 했는데, CNN 뒤쪽에서는 왜 Flatten해도 괜찮나요?

type: 이유
level: 기본
tags: Flatten, FC, 분류부
source: 10. CNN 전체 구조 › Flatten: 숫자 하나가 특징 하나

### 30초 답변
원본 픽셀을 펴면 이웃 관계가 깨지는 게 문제였는데, CNN 뒤쪽에서는 이미 합성곱이 지역 패턴을 다 뽑아 놓은 상태입니다. 그래서 편 숫자 하나하나가 "이 위치에 이 특징이 이만큼 있다"는 의미를 가지고, 그 숫자 하나가 FC의 입력 노드 하나가 됩니다. 공간이 충분히 줄어든 뒤라 입력 개수도 감당할 만합니다.

### 자세히
- Flatten 순서: 채널 순서대로, 각 채널 안에서는 위에서 아래로(행 우선) 이어 붙인다.
- (3, 2, 2) 특성맵 → 12개짜리 벡터
- `nn.Linear`의 입력 크기는 C × H × W로 맞춰야 한다.

```python
nn.Flatten()                  # (B, 16, 5, 5) → (B, 400), 배치 차원은 유지
nn.Linear(16 * 5 * 5, 120)
```

### 꼬리질문
#### Linear의 입력 크기를 틀리면 어떻게 되나요?
행렬 곱 모양이 맞지 않아 순전파에서 바로 에러가 납니다. 그래서 입력 크기나 padding을 바꿨으면 출력 크기 공식으로 마지막 특성맵 크기를 다시 계산하거나, 임의 텐서를 한 번 통과시켜 모양을 확인합니다.

## Q. CNN의 학습 파라미터 수는 어떻게 세나요?
id: cnn-parameter-count
type: 개념
level: 기본
tags: 파라미터 수, Conv, FC, bias
source: 10. CNN 전체 구조 › 학습할 값(파라미터) 세기

### 30초 답변
Conv층은 필터 하나가 K×K×C_in개의 가중치를 갖고 필터가 C_out개이며, 필터마다 bias가 하나씩 있어서 K·K·C_in·C_out + C_out개입니다. FC층은 입력 노드 × 출력 노드 + 출력 노드 수이고, Pooling과 Flatten은 학습할 값이 없습니다. Conv 파라미터에는 입력 이미지의 가로·세로 크기가 들어가지 않는다는 점이 핵심입니다.

### 자세히
입력 1×28×28 예시

| 층 | 출력 모양 | 학습할 값 |
|---|---|---|
| Conv(1→8, 3×3, padding 1) | 8×28×28 | (3·3·1)·8 + 8 = 80 |
| MaxPool 2×2 | 8×14×14 | 0 |
| Conv(8→16, 3×3, padding 1) | 16×14×14 | (3·3·8)·16 + 16 = 1,168 |
| MaxPool 2×2 → Flatten | 784 | 0 |
| FC(784→64) | 64 | 784·64 + 64 = 50,240 |
| FC(64→10) | 10 | 64·10 + 10 = 650 |
| 합계 | | 52,138 |

```python
sum(p.numel() for p in model.parameters() if p.requires_grad)
```

### 꼬리질문
#### Conv 뒤에 BatchNorm을 쓰면 Conv의 bias를 빼는 이유는 무엇인가요?
BatchNorm이 채널별 평균을 빼기 때문에 Conv의 bias가 더해져도 그대로 상쇄됩니다. BatchNorm에 학습되는 이동 값(β)이 bias 역할을 대신하므로 `bias=False`로 두어 쓸모없는 파라미터를 없앱니다.

## Q. LeNet-5의 구조를 설명해 보세요.
id: cnn-lenet5
type: 개념
level: 기본
tags: LeNet-5, MNIST, 역사
source: 11. LeNet-5 (1998): CNN의 원형

### 30초 답변
LeNet-5는 1998년 얀 르쿤이 손글씨 숫자 인식을 위해 만든 모델로, Conv와 Pooling을 번갈아 쌓고 FC로 분류하는 CNN 구조의 원형입니다. C1(Conv) → S2(Pool) → C3(Conv) → S4(Pool)가 특징 추출부이고 C5 → F6 → 출력이 분류부입니다. 파라미터는 61,706개인데 그중 95.8%가 FC층에 있습니다.

### 자세히
| 층 | 연산 | 출력 |
|---|---|---|
| C1 | Conv 5×5, 6개, padding 2 | 6×28×28 |
| S2 | AvgPool 2×2 | 6×14×14 |
| C3 | Conv 5×5, 16개 | 16×10×10 |
| S4 | AvgPool 2×2 | 16×5×5 |
| C5 | 120 (Flatten 400 → FC) | 120 |
| F6 | FC | 84 |
| 출력 | FC | 10 |

- C는 Conv, S는 Subsampling(Pooling), F는 FC
- 실습 설정: CrossEntropyLoss, SGD(학습률 0.01, momentum 0.9), 배치 32, 10에폭

### 꼬리질문
#### C5는 Conv층인데 왜 FC와 같다고 하나요?
S4 출력이 16×5×5이고 C5 필터가 5×5라서 필터가 놓일 자리가 딱 한 곳이고 출력이 1×1이 됩니다. 필터 하나가 입력 400개를 한 번에 보는 것이므로, 400개로 펴서 FC(400→120)에 넣는 것과 같은 계산입니다.

#### 실습 코드와 원본 LeNet-5는 무엇이 다른가요?
실습은 ReLU와 일반 AvgPool을 썼지만, 원본은 tanh 계열 활성화 함수를 썼고 서브샘플링 층에도 학습되는 계수와 bias가 있었습니다. 원본은 C3에서 일부 채널끼리만 연결하는 방식도 썼습니다.

## Q. LeNet-5를 MNIST 28×28에 쓸 때 첫 Conv에 padding 2를 준 이유는 무엇인가요?
id: cnn-lenet5-padding
type: 경험
level: 심화
tags: LeNet-5, Padding, 출력 크기
source: 11. LeNet-5 (1998): CNN의 원형

### 30초 답변
논문의 LeNet-5는 32×32 입력에 맞춰 설계되어 있고 MNIST는 28×28이기 때문입니다. C1에 padding 2를 주면 (28 − 5 + 4) / 1 + 1 = 28로 원래 설계대로 C1 출력이 28×28이 되고, 그 뒤 크기도 설계와 맞아서 Flatten 개수가 400이 됩니다. padding을 안 주면 크기가 줄줄이 어긋나 FC 입력 크기가 맞지 않습니다. 처음에 헷갈렸는데 공식에 직접 넣어 보면서 정리됐습니다.

### 자세히
| 층 | padding 2 | padding 0 |
|---|---|---|
| C1 (5×5) | 28 | 24 |
| S2 (2×2) | 14 | 12 |
| C3 (5×5) | 10 | 8 |
| S4 (2×2) | 5 | 4 |
| Flatten | 16·5·5 = 400 | 16·4·4 = 256 |

- padding 0이면 `nn.Linear(400, 120)`과 모양이 맞지 않아 에러가 난다.

### 꼬리질문
#### padding 대신 입력 이미지를 32×32로 키워도 되나요?
네, 이미지 둘레에 0을 2칸씩 붙이거나 리사이즈해서 32×32로 맞춰도 됩니다. 0을 붙이는 방식이면 C1의 padding 2와 같은 결과이고, 원래 LeNet-5 논문도 28×28 숫자를 32×32 영역 가운데에 두는 방식으로 입력을 만들었습니다.

## Q. AlexNet이 중요한 이유와 주요 특징을 설명해 보세요.
id: cnn-alexnet
type: 개념
level: 기본
tags: AlexNet, ReLU, Dropout, GPU, LRN, ImageNet
source: 12. AlexNet (2012): 딥러닝 붐의 시작

### 30초 답변
AlexNet은 2012년 ImageNet 대회(ILSVRC)에서 top-5 오류율 약 15.3%로 2위와 큰 차이를 내며 우승한 CNN이고, 이후 컴퓨터 비전에서 딥러닝이 주류가 되는 계기가 됐습니다. ReLU로 기울기 소실을 줄여 학습을 빠르게 했고, GPU로 대규모 학습을 했으며, Dropout과 데이터 증강으로 과적합을 줄였습니다. Conv 5개와 FC 3개로 이루어져 있고 파라미터는 약 6,000만 개입니다.

### 자세히
| 요소 | 내용 |
|---|---|
| ReLU | tanh, sigmoid보다 양수 구간 기울기가 1이라 학습이 빠름 |
| GPU | GPU 2개에 모델을 나눠 학습 (당시 GPU 메모리 한계) |
| Dropout | 앞쪽 FC 두 층에 p = 0.5 |
| 데이터 증강 | 무작위 자르기, 좌우 뒤집기, 색 변화 |
| LRN | 같은 위치의 인접 채널끼리 값을 정규화 |
| Overlapping pooling | 3×3 창, stride 2로 창이 겹치게 |

- 입력 224×224, 첫 Conv는 11×11 필터에 stride 4

### 꼬리질문
#### LRN은 지금도 쓰이나요?
거의 쓰이지 않습니다. 이후 VGG 논문에서 LRN이 성능을 높이지 못하고 메모리와 연산만 늘린다고 보고했고, 지금은 Batch Normalization이 그 자리를 대신합니다.

#### ReLU가 학습을 빠르게 한 이유는 무엇인가요?
sigmoid나 tanh는 입력이 크면 기울기가 0에 가까워져 깊은 층으로 갈수록 기울기가 사라지는데, ReLU는 양수 구간에서 기울기가 항상 1이라 기울기가 잘 전달됩니다. 계산도 0과 비교하는 것뿐이라 가볍고, AlexNet 논문에서는 tanh보다 약 6배 빠르게 수렴했다고 보고했습니다.

## Q. 원본 AlexNet을 CIFAR-10(32×32)에 그대로 쓰면 어떻게 되나요?
id: cnn-alexnet-small-input
type: 경험
level: 심화
tags: AlexNet, CIFAR-10, 출력 크기, 입력 크기
source: 12. AlexNet › 원본 AlexNet을 32×32에 쓰면?

### 30초 답변
원본 AlexNet은 224×224 ImageNet 사진에 맞춘 구조라 첫 Conv가 11×11 필터에 stride 4입니다. 32×32를 넣으면 Conv1에서 바로 7×7로 줄고 Pool2를 지나면 1×1이 되며, 마지막 Pool3에서 1×1 위에 3×3 창을 올릴 수 없어 에러가 납니다. 층마다 출력 크기를 직접 계산해서 확인했고, 큰 필터와 큰 stride는 작은 이미지에 그대로 쓰면 안 된다는 걸 숫자로 확인했습니다.

### 자세히
| 층 | 224 입력 | 32 입력 |
|---|---|---|
| Conv1 (11×11, s4, p2) | 55 | 7 |
| Pool1 (3×3, s2) | 27 | 3 |
| Conv2 (5×5, p2) | 27 | 3 |
| Pool2 (3×3, s2) | 13 | 1 |
| Conv3~5 (3×3, p1) | 13 | 1 |
| Pool3 (3×3, s2) | 6 | 에러 |

- 예: Conv1에 32를 넣으면 (32 − 11 + 4) / 4 = 6 (버림) + 1 = 7

### 꼬리질문
#### 에러가 나지 않게 이미지를 224로 키우면 해결되나요?
돌아가기는 하지만 32×32에 없던 정보가 생기지 않으면서 연산량만 크게 늘어납니다. 그래서 작은 이미지에는 필터와 stride를 줄인 구조를 쓰는 편이 효율적입니다.

## Q. CIFAR-10에 맞춰 AlexNet을 어떻게 바꿨나요?
id: cnn-mini-alexnet
type: 경험
level: 심화
tags: AlexNet, CIFAR-10, Mini-AlexNet, 구조 설계
source: 12. AlexNet › Mini-AlexNet

### 30초 답변
필터를 3×3, stride 1, padding 1로 줄인 Mini-AlexNet을 만들었습니다. Conv 5개와 FC 3개, ReLU, Max Pooling, Dropout이라는 핵심 구성은 원본 그대로 두고, Pool을 세 번 거쳐 32 → 16 → 8 → 4가 되게 했습니다. 마지막 특성맵 256×4×4를 펴면 4,096개이고, 전체 파라미터는 6,976,842개로 LeNet-5의 약 113배입니다.

### 자세히
```
3×32×32
→ Conv 64  → Pool → 64×16×16
→ Conv 192 → Pool → 192×8×8
→ Conv 384 → Conv 256 → Conv 256 → Pool → 256×4×4
→ Flatten 4096 → Dropout → FC 1024 → Dropout → FC 512 → FC 10
```
- 전처리: `Normalize((0.5,)*3, (0.5,)*3)`로 0~1을 -1~1로
- 학습: CrossEntropyLoss, 원본 설정을 따라 SGD(학습률 0.01, momentum 0.9, weight decay 0.0005)
- Conv는 모두 same padding이라 크기는 Pool에서만 줄어든다.

### 꼬리질문
#### Dropout은 왜 FC층 앞에만 넣었나요?
과적합 위험이 큰 곳이 파라미터가 몰린 FC층이기 때문입니다. 원본 AlexNet도 앞쪽 FC 두 층에만 Dropout을 썼고, Conv층은 파라미터가 적고 가중치를 공유해서 상대적으로 과적합이 덜합니다.

## Q. CNN의 파라미터는 주로 어디에 몰려 있나요?
id: cnn-fc-param-share
type: 경험
level: 심화
tags: 파라미터 수, FC, LeNet-5, AlexNet, Global Average Pooling
source: 12. AlexNet › Mini-AlexNet

### 30초 답변
대부분 Flatten 직후의 첫 FC층에 몰려 있습니다. 직접 세어 보니 LeNet-5는 61,706개 중 FC층이 95.8%였고 C5 하나가 78%를 차지했습니다. Mini-AlexNet도 FC1(4096→1024) 한 층이 4,195,328개로 전체의 60%였고, Conv층 다섯 개를 다 합쳐도 FC1보다 적었습니다. Conv는 가중치를 공유하지만 FC는 펼친 특징 하나하나를 모든 노드와 연결하기 때문입니다.

### 자세히
| 모델 | 전체 | FC 비중 |
|---|---|---|
| 작은 CNN (1×28×28) | 52,138 | 첫 FC 하나가 50,240 |
| LeNet-5 | 61,706 | FC 95.8% (C5만 78%) |
| Mini-AlexNet | 6,976,842 | FC1만 60% |

- FC 첫 층 = (C × H × W) × 출력 노드라서, 마지막 특성맵이 클수록 폭발한다.

### 꼬리질문
#### 그럼 연산량도 FC층이 대부분인가요?
아닙니다. Conv층은 파라미터는 적지만 같은 필터를 모든 위치에서 반복 계산하므로 곱셈 횟수는 보통 Conv층이 훨씬 많습니다. 파라미터 수(메모리)와 연산량(속도)은 따로 봐야 합니다.

#### FC층 파라미터를 줄이려면 어떻게 하나요?
Flatten 대신 Global Average Pooling으로 채널마다 숫자 하나만 남기면 첫 FC의 입력이 C개로 줄어듭니다. GoogLeNet과 ResNet 등 이후 모델들이 이 방식으로 큰 FC층을 없앴습니다.

## Q. PyTorch에서 학습한 모델은 어떻게 저장하고 불러오나요?
id: cnn-save-load
type: 개념
level: 기본
tags: state_dict, 모델 저장, PyTorch
source: 12. AlexNet › 학습한 모델 저장하고 불러오기

### 30초 답변
보통 `model.state_dict()`를 `torch.save`로 저장합니다. state_dict에는 층별 weight와 bias 같은 값만 들어 있고 모델 구조는 없기 때문에, 불러올 때는 같은 구조의 모델을 먼저 만든 다음 `load_state_dict`로 값을 채워 넣습니다. Colab처럼 세션이 끝나면 다 날아가는 환경에서는 오래 학습한 뒤 꼭 저장해 둬야 합니다.

### 자세히
```python
torch.save(model.state_dict(), './alexnet.pt')         # 가중치만 저장

net = AlexNet(num_classes=10).to(device)               # 같은 구조를 먼저 만들고
net.load_state_dict(torch.load('./alexnet.pt', map_location=device))
net.eval()                                              # 추론 전 평가 모드
```
- `map_location`: GPU에서 저장한 가중치를 CPU에서 여는 등 장치가 다를 때 맞춰 준다.
- state_dict는 이름 → 텐서 사전이다. BatchNorm의 running mean/var 같은 버퍼도 함께 들어간다.

### 꼬리질문
#### `torch.save(model)`로 모델 전체를 저장하면 안 되나요?
가능하지만 클래스 정의와 파일 경로까지 pickle로 묶이기 때문에, 코드 구조가 바뀌거나 다른 환경에서 불러올 때 깨지기 쉽습니다. 그래서 state_dict 저장이 권장 방식입니다.

#### 학습을 이어서 하려면 무엇을 더 저장해야 하나요?
모델 state_dict와 함께 옵티마이저의 state_dict와 에폭 수를 저장합니다. momentum이나 Adam의 이동 평균 같은 옵티마이저 상태가 없으면 이어서 학습할 때 처음과 다르게 움직입니다.

## Q. LeNet-5와 AlexNet 이후 CNN은 어떤 방향으로 발전했나요?
id: cnn-architecture-lineage
type: 개념
level: 기본
tags: CNN 계보, VGG, GoogLeNet, ResNet, MobileNet, EfficientNet, ViT
source: 13. 그 뒤의 CNN들

### 30초 답변
AlexNet 이후에는 더 깊게, 더 효율적으로 가는 방향으로 발전했습니다. VGG는 3×3 Conv만 깊게 쌓았고, GoogLeNet은 여러 크기의 필터를 한 층에서 병렬로 썼으며, ResNet은 잔차 연결로 100층 이상도 학습할 수 있게 했습니다. 이후 MobileNet은 경량화, EfficientNet은 깊이·너비·해상도를 균형 있게 키우는 방법을 제시했고, ViT는 CNN 대신 Transformer를 이미지에 적용했습니다.

### 자세히
| 이름 | 연도 | 핵심 아이디어 |
|---|---|---|
| LeNet-5 | 1998 | Conv+Pool 구조의 원형 |
| AlexNet | 2012 | ReLU, Dropout, GPU로 ImageNet 우승 |
| VGG | 2014 | 3×3 Conv만 깊게 쌓는 단순한 설계 |
| GoogLeNet | 2014 | Inception 모듈로 여러 크기 필터 병렬 |
| ResNet | 2015 | 잔차 연결(skip connection) |
| MobileNet | 2017 | Depthwise Separable Conv로 경량화 |
| EfficientNet | 2019 | 깊이·너비·해상도 함께 스케일링 |
| ViT | 2020 | 이미지 패치에 Transformer 적용 |

### 꼬리질문
#### 그냥 층만 계속 쌓으면 안 되나요?
일정 깊이를 넘으면 기울기가 잘 전달되지 않아 오히려 학습 오차까지 커지는 문제가 있었습니다. 이 문제를 잔차 연결로 푼 것이 ResNet이고, 그래서 이후 깊은 모델 대부분이 이 구조를 씁니다.

## Q. VGG는 왜 큰 필터 대신 3×3 Conv를 여러 번 쌓았나요?
id: cnn-vgg-3x3
type: 이유
level: 심화
tags: VGG, 3×3 Conv, receptive field, 파라미터
source: 13. 그 뒤의 CNN들

### 30초 답변
3×3 Conv를 두 번 쌓으면 5×5 하나와 같은 receptive field를, 세 번 쌓으면 7×7과 같은 receptive field를 가지면서 파라미터는 더 적기 때문입니다. 층 사이마다 ReLU가 들어가서 비선형성이 늘어나 더 복잡한 함수를 표현할 수 있다는 장점도 있습니다. VGG는 이 단순한 규칙으로 16~19층까지 깊게 쌓았습니다.

### 자세히
입출력 채널이 모두 C일 때 (bias 제외)

| 구성 | Receptive field | 가중치 수 | ReLU 수 |
|---|---|---|---|
| 5×5 한 층 | 5×5 | 25C² | 1 |
| 3×3 두 층 | 5×5 | 18C² | 2 |
| 7×7 한 층 | 7×7 | 49C² | 1 |
| 3×3 세 층 | 7×7 | 27C² | 3 |

- 이후 대부분의 CNN이 3×3을 기본 필터로 쓰게 됐다.

### 꼬리질문
#### VGG의 단점은 무엇인가요?
VGG16은 파라미터가 약 1억 3,800만 개로 매우 무겁고, 대부분이 마지막 FC층에 있습니다. 첫 FC층 하나가 7×7×512 = 25,088개 입력을 4,096개 노드에 연결해 약 1억 개를 차지합니다.

## Q. GoogLeNet의 Inception 모듈은 어떤 아이디어인가요?
id: cnn-inception
type: 개념
level: 심화
tags: GoogLeNet, Inception, 멀티스케일
source: 13. 그 뒤의 CNN들

### 30초 답변
Inception 모듈은 한 층에서 1×1, 3×3, 5×5 Conv와 3×3 Max Pooling을 병렬로 적용하고, 결과를 채널 방향으로 이어 붙이는 구조입니다. 물체가 이미지에서 크게도 작게도 나타나니 필터 크기를 하나로 정하지 않고 여러 크기를 한꺼번에 보고, 어떤 쪽을 쓸지는 다음 층이 학습으로 정하게 한 것입니다. 연산량이 커지는 문제는 3×3, 5×5 앞에 1×1 Conv를 둬서 채널을 줄이는 방식으로 해결했습니다.

### 자세히
```
            ┌─ 1×1 Conv ─────────────┐
입력 ───────┼─ 1×1 → 3×3 Conv ───────┼─ 채널 방향 concat → 출력
            ├─ 1×1 → 5×5 Conv ───────┤
            └─ 3×3 MaxPool → 1×1 ────┘
```
- 모든 갈래는 same padding으로 공간 크기를 맞춰야 이어 붙일 수 있다.
- 2014 ILSVRC 분류 부문 우승, 22층
- 마지막에 큰 FC 대신 Global Average Pooling을 써서 AlexNet보다 파라미터가 훨씬 적다.

### 꼬리질문
#### 갈래마다 출력 채널이 다르면 어떻게 합치나요?
공간 크기만 같으면 채널 수는 달라도 채널 방향으로 이어 붙일 수 있습니다. 출력 채널은 네 갈래 출력 채널의 합이 됩니다.

## Q. 1×1 Convolution은 무슨 의미가 있나요?
id: cnn-1x1-conv
type: 개념
level: 심화
tags: 1×1 Conv, 채널 축소, bottleneck, 연산량
source: 보충 (블로그 밖 내용)

### 30초 답변
1×1 Conv는 공간 방향으로는 한 칸만 보지만, 채널 방향으로는 모든 입력 채널을 가중합합니다. 그래서 위치마다 채널끼리 섞는 작은 FC층과 같고, 주된 용도는 채널 수를 줄이거나 늘리는 것입니다. 큰 필터 앞에서 채널을 먼저 줄이면 연산량과 파라미터가 크게 줄고, 뒤에 ReLU를 붙이면 비선형성도 더해집니다.

### 자세히
```
입력 (C_in, H, W) → 1×1 Conv, 필터 C_out개 → (C_out, H, W)   # 공간 크기 그대로
파라미터: C_in · C_out + C_out
```
예: 입력 192채널을 5×5 Conv로 32채널로 만들 때 (bias 제외)

| 방식 | 가중치 수 |
|---|---|
| 5×5 바로 적용 | 5·5·192·32 = 153,600 |
| 1×1로 16채널 축소 → 5×5 | 192·16 + 5·5·16·32 = 15,872 |

- 약 10배 줄어든다. 이런 구조를 bottleneck이라고 부른다.

### 꼬리질문
#### 1×1 Conv와 FC층은 어떤 관계인가요?
각 위치의 채널 벡터에 같은 FC층을 적용하는 것과 같습니다. 그래서 입력 크기에 상관없이 쓸 수 있고, 마지막 FC를 1×1 Conv로 바꾸면 임의 크기 입력을 받는 완전 합성곱 신경망(FCN)이 됩니다.

## Q. Depthwise Separable Convolution을 간단히 설명해 보세요.
id: cnn-depthwise-separable
type: 개념
level: 심화
tags: Depthwise Separable, MobileNet, 경량화
source: 보충 (블로그 밖 내용)

### 30초 답변
일반 합성곱이 한 번에 하던 "공간 방향 필터링"과 "채널 섞기"를 두 단계로 나눈 것입니다. 먼저 depthwise conv로 채널마다 따로 K×K 필터를 하나씩 적용하고, 그다음 pointwise conv(1×1 Conv)로 채널을 섞어 원하는 출력 채널 수를 만듭니다. 성능은 조금 손해 볼 수 있지만 연산량과 파라미터가 크게 줄어서 MobileNet 같은 경량 모델의 핵심이 됐습니다.

### 자세히
| | 가중치 수 (bias 제외) |
|---|---|
| 일반 Conv | K·K·C_in·C_out |
| Depthwise | K·K·C_in |
| Pointwise (1×1) | C_in·C_out |

- 비율 = 1/C_out + 1/K². 3×3이면 대략 8~9배 줄어든다.
- 예: K=3, C_in = C_out = 256 → 일반 589,824 vs 분리 2,304 + 65,536 = 67,840

```python
nn.Conv2d(256, 256, 3, padding=1, groups=256)   # depthwise
nn.Conv2d(256, 256, 1)                          # pointwise
```

### 꼬리질문
#### depthwise만 쓰고 pointwise를 빼면 안 되나요?
depthwise는 채널끼리 전혀 섞지 않아서 출력 채널 하나가 입력 채널 하나의 정보만 담습니다. 채널 사이의 조합을 만들고 출력 채널 수를 바꾸려면 pointwise 단계가 꼭 필요합니다.
