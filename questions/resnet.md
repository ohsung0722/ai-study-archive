## Q. 데이터 증강이란 무엇이고, 일반화·과적합과 어떤 관계가 있나요?
id: aug-what-why
type: 개념
level: 기본
tags: 데이터 증강, 일반화, 과적합
source: 1. 데이터를 먼저 생각하자 › 증강, 일반화, 과적합

### 30초 답변
데이터 증강은 원본 이미지를 뒤집거나 돌리거나 밝기를 바꿔서 학습 이미지를 다양하게 만드는 방법입니다. 데이터가 적거나 한 가지 촬영 조건에 몰려 있으면 모델이 대상이 아니라 그 조건을 외워서 과적합이 생기는데, 증강은 부족한 변화를 채워 처음 보는 데이터에서도 성능을 유지하는 일반화를 돕습니다. 단, 바꾼 뒤에도 정답이 그대로여야 하고, 새 데이터를 모으는 것을 대신하지는 못합니다.

### 자세히
- **일반화**: 학습에 쓰지 않은 새 데이터에서도 성능을 유지하는 것.
- **과적합**: 학습 데이터에서는 잘하지만 새 데이터에서는 못하는 상태. 데이터가 적거나, 다양성이 부족하거나, 데이터에 비해 모델이 복잡할 때 생긴다.
- 같은 고양이도 품종, 자세, 배경, 조명이 다 다르다. 증강은 이런 변화에 대해 "이 정도 바뀌어도 같은 클래스"라는 불변성을 모델에 가르치는 셈이다.
- 증강은 정규화(regularization) 기법의 하나로 볼 수 있다. 모델이 아니라 데이터 쪽에서 과적합을 줄인다.
- 실제로 존재할 수 없는 변형(예: 거꾸로 선 고양이)은 오히려 분포를 흐린다. 실제 환경에서 나올 법한 변화만 넣는다.

### 꼬리질문
#### 증강을 미리 해서 파일로 저장하는 방식과 학습 중에 즉석으로 하는 방식은 어떻게 다른가요?
미리 저장하면 정해진 몇 장의 변형만 반복해서 보게 되고 저장 공간도 늘어납니다. 학습 중에 즉석으로 하면 에포크마다 새 무작위 값이 뽑혀서 같은 사진을 매번 다른 모습으로 보게 되므로 보통 이 방식을 씁니다.

#### 증강을 너무 세게 하면 어떻게 되나요?
학습 데이터가 실제 데이터와 동떨어져서 학습 손실 자체가 잘 안 떨어지는 과소적합이 생길 수 있습니다. 밝기를 크게 올려 털 무늬가 사라지는 것처럼 정답 판단에 필요한 정보까지 지워질 수도 있어서, 강도는 작게 시작해 검증 성능을 보며 올립니다.

## Q. 이미지 분류 데이터의 클래스와 라벨은 어떻게 정하고, 폴더는 어떻게 구성하나요?
id: aug-classes-imagefolder
type: 개념
level: 기본
tags: 클래스, 라벨, ImageFolder, 데이터셋 구성
source: 1. 데이터를 먼저 생각하자 › 클래스와 라벨, 폴더 구성

### 30초 답변
클래스는 구분할 대상의 종류이고, 라벨은 각 클래스에 붙인 번호입니다. 사진은 `train/cat/`, `train/dog/`처럼 클래스별 폴더로 정리하고, `val/` 아래에도 같은 이름의 폴더를 만듭니다. PyTorch의 `ImageFolder`는 폴더 이름을 정렬한 순서로 번호를 붙여서 cat이 0, dog이 1이 되고, 이 번호는 학습부터 추론까지 똑같이 유지해야 합니다.

### 자세히
```
data/
├── train/
│   ├── cat/   (라벨 0)
│   └── dog/   (라벨 1)
└── val/
    ├── cat/
    └── dog/
```

- `ImageFolder(root)`는 하위 폴더 이름을 알파벳순으로 정렬해 `class_to_idx = {"cat": 0, "dog": 1}`을 만든다.
- 한 사진에 구분할 대상이 하나로 명확해야 한다. 개와 고양이가 함께 찍힌 사진은 기본 학습 자료에서 뺐다.
- 클래스 이름과 번호의 대응은 체크포인트에 같이 저장해 둔다. 추론 코드에서 순서가 바뀌면 예측이 통째로 뒤집힌다.

### 꼬리질문
#### 클래스별 사진 수가 크게 다르면 어떤 문제가 있나요?
모델이 많은 쪽 클래스로 찍기만 해도 정확도가 높게 나와서 성능이 과대평가됩니다. 클래스별 가중치를 손실에 주거나, 적은 클래스를 더 자주 뽑는 샘플링을 하고, 정확도 대신 클래스별 재현율이나 F1을 함께 봅니다.

## Q. Train과 Val은 어떻게 나누고, 데이터 누수는 왜 조심해야 하나요?
id: aug-split-leakage
type: 개념
level: 기본
tags: train/val 분리, 데이터 누수, 시드
source: 1. 데이터를 먼저 생각하자 › Train과 Val, 그리고 데이터 누수

### 30초 답변
Train은 모델을 학습하는 데, Val은 학습 중 성능을 확인하고 설정을 고르는 데 씁니다. 데이터 누수는 학습에 쓴 정보가 검증 데이터에 섞여서 검증 성능이 실제보다 높게 나오는 현상입니다. 같은 원본의 증강본이 Train과 Val에 나뉘어 들어가면 모델은 사실상 본 사진을 맞히는 셈이라, 반드시 원본을 먼저 나누고 그다음 Train에만 증강을 적용합니다.

### 자세히
- 순서: **원본 정리 → Train/Val 분리 → Train에만 증강**
- 클래스별로 80 / 20으로 나누고 난수 시드를 고정해 재현 가능하게 한다.
- 실습: 고양이 100장, 개 80장 → 고양이 80 / 20, 개 64 / 16. 겹침과 누락 0장을 직접 확인했다.
- 같은 사진의 복사본은 하나로 취급하고, 연속 촬영한 비슷한 사진은 같은 쪽에 넣는다.
- 분리 전에 `cv2.imread()`가 `None`을 돌려주는 깨진 파일부터 걸러 낸다.

### 꼬리질문
#### 클래스별로 나누는 이유는 무엇인가요?
전체를 무작위로 나누면 우연히 한 클래스가 Val에 적게 들어가 비율이 틀어질 수 있습니다. 클래스별로 같은 비율로 나누면(층화 분리) Train과 Val의 클래스 구성이 원본과 같아집니다.

#### 정규화 통계를 직접 계산한다면 어떤 데이터로 계산해야 하나요?
Train 데이터로만 계산하고 Val과 Test에는 그 값을 그대로 씁니다. Val까지 포함해 계산하면 검증 데이터의 정보가 전처리를 통해 학습에 새어 들어가는 누수가 됩니다.

#### Val과 Test는 왜 따로 두나요?
Val은 학습률이나 에포크를 고르는 데 반복해서 쓰이므로 그 결과에 맞춰진 만큼 낙관적으로 나옵니다. 최종 성능은 어떤 결정에도 쓰지 않은 Test로 한 번만 확인해야 실제 성능에 가깝습니다.

## Q. 왜 증강은 Train에만 적용하고 Val에는 적용하지 않나요?
id: aug-train-only
type: 이유
level: 기본
tags: 데이터 증강, 검증, 재현성
source: 5. 입력 전처리 › Train과 Val은 다르게

### 30초 답변
검증의 목적은 같은 조건에서 모델들의 성능을 비교하는 것인데, 무작위 증강이 들어가면 같은 모델도 평가할 때마다 점수가 달라집니다. 또 실제 사용 환경에서 들어올 사진과 비슷한 원본 상태로 평가해야 의미가 있습니다. 그래서 Train에는 무작위 증강 뒤 전처리를, Val에는 정해진 전처리만 적용합니다.

### 자세히
| | Train | Val |
|---|---|---|
| 증강 | 무작위 (매번 다름) | 없음 |
| 전처리 | 같은 규격 | 같은 규격 |
| DataLoader | `shuffle=True` | `shuffle=False` |

- 실험: 같은 사진을 네 번씩 넣었더니 Train 입력은 매번 달랐고, Val 입력 네 개는 숫자까지 완전히 같았다.
- 전처리(크기, RGB 변환, 정규화)는 증강과 달리 Train, Val, 추론 모두 똑같이 적용한다.

### 꼬리질문
#### 테스트 때 증강을 쓰는 TTA(Test-Time Augmentation)는 무엇인가요?
테스트 사진 하나에 좌우 반전 같은 정해진 변형 여러 개를 적용해 예측을 평균 내는 방법입니다. 무작위가 아니라 고정된 변형 집합이라 결과는 재현되고 정확도가 조금 오르는 경우가 많지만, 추론 비용이 변형 수만큼 늘어납니다.

## Q. 반전 증강을 설명하고, 상하 반전은 언제 쓰면 안 되는지 말해 보세요.
id: aug-flip
type: 개념
level: 기본
tags: 기하학적 증강, 반전, OpenCV
source: 2. 기하학적 증강 › 반전

### 30초 답변
반전은 이미지를 좌우 또는 상하로 뒤집는 증강으로, 크기와 정답이 그대로 유지되어 가장 기본적으로 씁니다. 좌우 반전은 개·고양이처럼 왼쪽을 보든 오른쪽을 보든 같은 대상에 잘 맞습니다. 상하 반전은 바닥과 동물의 위아래까지 뒤집어서, 실제로 거꾸로 찍힌 사진이 들어올 일이 없다면 존재하지 않는 데이터를 만드는 셈이라 쓰지 않습니다.

### 자세히
```python
flipped = cv2.flip(img, 1)    # 1: 좌우 반전
flipped = cv2.flip(img, 0)    # 0: 상하 반전
flipped = cv2.flip(img, -1)   # -1: 둘 다 (180도 회전과 같음)
```

- 상하 반전이 자연스러운 데이터: 위성·항공 사진, 현미경 세포 사진처럼 위아래 방향이 정해져 있지 않은 경우.
- 좌우 반전도 문자, 표지판처럼 방향에 의미가 있는 대상에는 쓰면 안 된다.

### 꼬리질문
#### torchvision에서는 반전을 어떻게 적용하나요?
`transforms.RandomHorizontalFlip(p=0.5)`처럼 확률을 주고 Train 변환에만 넣습니다. 그러면 사진을 읽을 때마다 절반 정도의 확률로 좌우가 뒤집힙니다.

## Q. 아핀 변환 행렬로 회전, 확대, 이동, 기울이기를 어떻게 표현하나요?
id: aug-affine-matrix
type: 개념
level: 심화
tags: 아핀 변환, warpAffine, 회전, 기울이기
source: 2. 기하학적 증강 › 변환 행렬 하나로 회전, 확대, 이동, 기울이기

### 30초 답변
아핀 변환은 픽셀 좌표 (x, y)를 2행 3열 행렬로 새 좌표로 옮기는 변환이고, 회전, 확대·축소, 이동, 기울이기를 모두 이 행렬 하나와 `cv2.warpAffine()`으로 처리합니다. 앞의 2×2 부분이 회전·배율·기울임을, 마지막 열이 이동량을 담습니다. 직선은 직선으로, 평행선은 평행선으로 유지된다는 것이 특징입니다.

### 자세히
```
[x']   [a  b  tx] [x]
[y'] = [c  d  ty] [y]
                  [1]
```

| 변환 | 행렬 | 의미 |
|---|---|---|
| 회전 | `cv2.getRotationMatrix2D(center, 20, 1.0)` | 중심 기준 반시계 20도 |
| 확대·축소 | `cv2.getRotationMatrix2D(center, 0, 1.2)` | 각도 0, 배율 1.2 |
| 이동 | `[[1, 0, tx], [0, 1, ty]]` | 오른쪽 tx, 아래 ty |
| 기울이기 | `[[1, s, -s*cy], [0, 1, 0]]` | 아래로 갈수록 옆으로 밀림 |

- 출력 크기를 원본과 같게 두면 1.2배 확대는 가장자리가 잘리고, 0.8배 축소는 바깥에 빈 곳이 생긴다.
- 기울이기의 `-s*cy`: x' = x + s(y − cy)라서 가운데 높이 cy의 행은 제자리, 위는 왼쪽, 아래는 오른쪽으로 대칭으로 기운다. s는 각도가 아니라 기울임 계수다.

### 꼬리질문
#### 회전 행렬에 왜 이동 성분이 들어가나요?
그냥 회전하면 원점, 즉 이미지 왼쪽 위 모서리를 기준으로 돌아갑니다. 중심 기준으로 돌리려면 중심을 원점으로 옮기고, 회전한 뒤, 다시 제자리로 옮겨야 해서 그 이동량이 세 번째 열에 합쳐져 들어갑니다.

#### 아핀 변환과 원근(투시) 변환은 어떻게 다른가요?
아핀 변환은 2×3 행렬로 평행선이 평행하게 유지됩니다. 원근 변환은 3×3 행렬(`cv2.warpPerspective`)을 써서 평행선이 한 점으로 모일 수 있고, 비스듬히 찍은 문서를 정면으로 펴는 데 씁니다.

## Q. 보간법 nearest, bilinear, bicubic의 차이를 설명해 보세요.
id: aug-interpolation
type: 비교
level: 기본
tags: 보간법, 리사이즈, OpenCV
source: 2. 기하학적 증강 › 보간법

### 30초 답변
회전하거나 크기를 바꾸면 원래 픽셀 사이의 정수가 아닌 위치의 값이 필요해지는데, 그 값을 주변 픽셀로 계산하는 방법이 보간법입니다. nearest는 가장 가까운 픽셀 하나를 그대로 써서 빠르지만 계단처럼 깨지고, bilinear는 주변 4개 픽셀에 거리 가중치를 줘서 부드럽고, bicubic은 주변 16개 픽셀을 3차 함수로 이어 더 선명하지만 느립니다. 회전·이동에는 보통 bilinear를 쓰고, 크게 줄일 때는 area 방식을 씁니다.

### 자세히
| 방법 | OpenCV | 참조 픽셀 | 특징 |
|---|---|---|---|
| 최근접 | `INTER_NEAREST` | 1개 | 가장 빠름, 계단 현상 |
| 쌍선형 | `INTER_LINEAR` | 2×2 | 부드러움, `warpAffine`·`resize` 기본값 |
| 쌍삼차 | `INTER_CUBIC` | 4×4 | 선명함, 느림 |
| 면적 | `INTER_AREA` | 영역 평균 | 축소할 때 물결무늬(앨리어싱)가 적음 |

- 실험: 고양이 눈 주변을 6배로 키워 보니 NEAREST는 계단처럼 깨지고 LINEAR는 부드러웠다.

### 꼬리질문
#### 분할(segmentation) 마스크를 함께 변환할 때는 어떤 보간법을 써야 하나요?
마스크는 클래스 번호라서 nearest를 써야 합니다. bilinear로 보간하면 0번과 2번 클래스 경계에 1.0 같은 존재하지 않는 클래스 값이 생깁니다.

## Q. 변환 뒤 생긴 빈 영역은 어떻게 채우고, 방식마다 어떤 차이가 있나요?
id: aug-border-mode
type: 비교
level: 심화

### 30초 답변
회전이나 축소 후 원본 범위를 벗어난 곳을 무엇으로 채울지는 `borderMode`로 정합니다. 기본값인 상수 채우기는 검은 모서리를 만드는데, 원래 사진에 없던 무늬라 모델이 그걸 특징으로 배울 수 있습니다. 끝 픽셀을 늘리는 REPLICATE는 줄무늬가 생기고, 거울처럼 접는 REFLECT_101이 가장 자연스럽지만 귀나 털이 하나 더 비치기도 해서, 데이터에 따라 고릅니다.

### 자세히
```python
cv2.warpAffine(img, M, (w, h),
               borderMode=cv2.BORDER_CONSTANT, borderValue=(0, 0, 0))
```

| 모드 | 채우는 방식 (`abcdefgh` 기준) | 결과 |
|---|---|---|
| `BORDER_CONSTANT` | `000 [abcdefgh] 000` | 검은 모서리 |
| `BORDER_REPLICATE` | `aaa [abcdefgh] hhh` | 끝 픽셀이 줄무늬로 늘어남 |
| `BORDER_REFLECT_101` | `dcb [abcdefgh] gfe` | 거울 반사, 가장 자연스러움 |

- 실습의 무작위 증강에는 `BORDER_REFLECT_101`을 썼다.

### 꼬리질문
#### 검은 모서리가 왜 문제가 될 수 있나요?
특정 클래스 사진만 많이 회전되는 등 검은 모서리가 한쪽에 치우치면, 모델이 대상 대신 모서리 유무를 단서로 쓸 수 있습니다. 실제 테스트 사진에는 그런 모서리가 없으니 그 단서는 쓸모가 없습니다.

## Q. 8비트 이미지에 밝기 값을 더할 때 왜 float으로 바꾸고 클리핑하나요?
id: aug-value-range
type: 이유
level: 기본
tags: uint8, 오버플로, 클리핑, 색상 증강
source: 3. 색상 증강 › 먼저 값 범위

### 30초 답변
8비트 이미지는 0~255 정수(`uint8`)라서, numpy에서 그대로 250에 10을 더하면 260이 아니라 256을 넘어 다시 0부터 세어 4가 됩니다. 밝은 픽셀이 갑자기 어두워지는 오류가 생기는 것입니다. 그래서 계산은 `float32`로 바꿔서 하고, `np.clip`으로 0~255 범위에 가둔 뒤 다시 `uint8`로 돌립니다.

### 자세히
```python
work = img.astype(np.float32) + 30           # 1. 실수로 바꿔 계산
bright = np.clip(work, 0, 255).astype(np.uint8)   # 2. 범위 가두고 되돌리기

values = np.array([-20, 100, 280], dtype=np.float32)
np.clip(values, 0, 255).astype(np.uint8)     # [  0 100 255]
```

- 오버플로(wrap-around): 255를 넘으면 256으로 나눈 나머지가 된다.
- 음수도 마찬가지로 -20이 236처럼 밝은 값으로 바뀐다.

### 꼬리질문
#### `cv2.add`를 쓰면 어떻게 되나요?
OpenCV의 `cv2.add`는 포화 연산을 해서 255를 넘으면 255로, 0 아래는 0으로 잘라 줍니다. numpy의 `+` 연산과 결과가 다르므로 어느 쪽을 쓰는지 알고 있어야 합니다.

### 30초 답변
색상 증강은 같은 대상도 조명이나 카메라에 따라 색과 밝기가 다르게 찍히는 차이를 학습에 반영하는 방법입니다. 밝기 조절은 모든 채널에 같은 값을 더해 분포 전체를 평행 이동시키고, 채널 이동은 R 같은 한 채널에만 값을 더해 색감을 바꿉니다. torchvision에서는 밝기, 대비, 채도, 색조를 한 번에 무작위로 바꾸는 `ColorJitter`를 많이 씁니다.

### 자세히
```python
work = img.astype(np.float32) + beta          # 밝기: 모든 채널에 같은 값

work[:, :, 2] += 20                           # 채널 이동: BGR이라 2번이 R
```

| 증강 | 바뀌는 것 |
|---|---|
| 밝기 | 전체 값이 같이 이동 |
| 대비 | 평균 기준으로 값이 퍼지거나 모임 |
| 채도 | 색의 진하기 |
| 색조(hue) | 색 자체가 바뀜 |
| 채널 이동 | 특정 채널 분포만 이동 |

- OpenCV는 BGR 순서라 R 채널이 인덱스 2다.

### 꼬리질문
#### 색상 증강을 하면 안 되는 경우도 있나요?
색이 정답을 결정하는 문제에는 조심해야 합니다. 잘 익은 과일과 덜 익은 과일, 신호등 색처럼 색조가 바뀌면 라벨이 달라지는 경우에는 색조 증강을 빼거나 아주 약하게 줍니다.

## Q. 여러 증강을 이어 붙일 때 순서가 왜 중요한가요?

type: 경험
level: 심화
tags: 증강 조합, 적용 순서, Compose
source: 4. 증강 조합 › 적용 순서

### 30초 답변
여러 증강을 이어 붙이면 앞의 결과가 다음 증강의 입력이 되어서 순서에 따라 결과가 달라집니다. 실습에서 회전한 뒤 밝기를 +60 올리면 회전으로 생긴 검은 모서리까지 밝아져 회색(60)이 됐고, 밝기를 먼저 올리고 회전하면 새로 생긴 영역은 경계 설정대로 검은색(0)으로 남았습니다. 그래서 순서를 고정해 두고 설정값만 바꿔 가며 비교했습니다.

### 자세히
```
회전 → 밝기 +60  :  빈 모서리 0 → 60 (회색)
밝기 +60 → 회전  :  빈 모서리 0 그대로 (검은색)
```

- 일반적인 순서: 기하학적 변환(크롭·반전·회전) → 색상 변환 → `ToTensor` → `Normalize`
- `Normalize`는 마지막에 둔다. 정규화한 값에 밝기를 더하면 의도한 크기와 다른 변화가 된다.

### 꼬리질문
#### torchvision의 `Compose`는 순서를 어떻게 처리하나요?
리스트에 넣은 순서대로 변환을 하나씩 적용합니다. 그래서 `ToTensor`가 필요한 변환과 PIL 이미지가 필요한 변환이 섞여 있으면 순서를 잘못 두는 순간 에러가 나거나 결과가 달라집니다.

## Q. 무작위 증강에서 변환 값과 적용 확률은 어떻게 다루나요?

level: 기본
tags: 무작위 증강, 적용 확률, 시드
source: 4. 증강 조합 › 무작위 값과 적용 확률

### 30초 답변
학습할 때는 변환 값을 정해진 범위에서 매번 새로 뽑습니다. 예를 들어 회전은 -15~15도, 밝기는 -30~30에서 뽑고, 좌우 반전은 확률 0.5로 적용합니다. 에포크마다 사진을 읽을 때 새 값이 뽑히니까 모델은 같은 사진을 매번 조금 다른 모습으로 보게 되고, 시드는 준비 단계에서 한 번만 고정해 재현성을 확보합니다.

### 자세히
```python
rng = random.Random(42)            # 시드는 한 번만
def augment(image):
    out = image.copy()
    if rng.random() < 0.5:         # p = 0.5로 좌우 반전
        out = cv2.flip(out, 1)
    angle = rng.uniform(-15, 15)
    ...
```

- 사진 한 장에 12번 적용하니 조금씩 다른 12장이 나왔다.
- p = 0.5라도 정확히 절반은 아니다. 직접 세어 보니 10번 중 7번, 100번 중 55번, 1,000번 중 529번, 10,000번 중 4,993번으로 횟수가 많을수록 50%에 가까워졌다.

### 꼬리질문
#### 시드를 증강 함수 안에서 매번 고정하면 어떻게 되나요?
호출할 때마다 같은 난수가 나와서 모든 사진, 모든 에포크에 똑같은 변환이 적용됩니다. 무작위 증강의 의미가 사라지므로 시드는 프로그램 시작 시 한 번만 고정합니다.

#### DataLoader에서 `num_workers`를 여러 개 쓸 때 난수는 주의할 점이 있나요?
워커는 별도 프로세스라 난수 상태를 복사해 시작합니다. 예전 PyTorch(1.9 이전)에서는 numpy 난수를 쓰는 증강이 워커끼리 같은 값을 뽑는 문제가 있었고, 지금은 PyTorch가 워커마다 시드를 다르게 넣어 줍니다. 재현성이 중요하면 `worker_init_fn`과 `generator`로 시드를 직접 관리합니다.

## Q. 라벨을 바꿔 버리는 증강은 어떤 경우이고, 탐지 문제에서는 무엇을 함께 바꿔야 하나요?

- 보충: Albumentations, torchvision `transforms.v2`는 이미지와 박스·마스크를 한 번에 변환해 준다.

## Q. Mixup, CutMix, AutoAugment는 무엇인가요?
id: aug-mixup-cutmix
type: 개념
level: 심화
tags: Mixup, CutMix, AutoAugment, RandAugment
source: 보충 (블로그 밖 내용)

### 30초 답변
Mixup은 두 이미지를 비율 λ로 섞고 라벨도 같은 비율로 섞는 방법이고, CutMix는 한 이미지의 사각형 영역을 다른 이미지에 붙여 넣고 라벨을 면적 비율로 섞는 방법입니다. 둘 다 정답을 0과 1이 아닌 비율로 주기 때문에 모델이 지나치게 확신하는 것을 막는 정규화 효과가 있습니다. AutoAugment는 어떤 증강을 어떤 강도로 쓸지 탐색으로 찾는 방법이고, RandAugment는 이를 증강 개수와 강도 두 값만 정하도록 단순화했습니다.

### 자세히
```
Mixup:   x = λ·x_a + (1 − λ)·x_b,   y = λ·y_a + (1 − λ)·y_b,   λ ~ Beta(α, α)
CutMix:  x = 마스크 영역은 x_b, 나머지는 x_a,   y = 면적 비율로 섞음
```

| 방법 | 특징 |
|---|---|
| Mixup (2017) | 이미지 전체를 반투명하게 겹침, 부자연스러운 이미지 |
| CutMix (2019) | 국소 영역 교체, 자연스러운 픽셀 유지, 물체 일부만 봐도 맞히게 함 |
| AutoAugment (2018) | 강화학습으로 증강 정책 탐색, 탐색 비용이 큼 |
| RandAugment (2019) | 증강 개수 N과 강도 M만 정함 |

### 꼬리질문
#### Cutout과 CutMix는 어떻게 다른가요?
Cutout은 사각형 영역을 0 같은 값으로 지우기만 해서 그 픽셀의 정보가 버려집니다. CutMix는 그 자리에 다른 이미지 조각을 채우고 라벨도 섞어서 픽셀을 낭비하지 않습니다.

## Q. 사전학습 ResNet에 넣기 위한 입력 전처리 과정을 설명해 보세요.
id: resnet-preprocess-pipeline
type: 개념
level: 기본
tags: 전처리, Resize, CenterCrop, ToTensor, Normalize
source: 5. 입력 전처리: 모델의 입력 규격 맞추기

### 30초 답변
사전학습 모델은 학습할 때 받던 입력과 똑같은 형태로 넣어야 합니다. `ResNet18_Weights.IMAGENET1K_V1` 기준으로 짧은 변을 256으로 맞추고, 가운데 224×224를 자르고, RGB 순서로 바꾼 뒤, 0~255를 0~1로 나누고, 채널별로 ImageNet 평균을 빼고 표준편차로 나눕니다. torchvision으로는 `Resize(256)`, `CenterCrop(224)`, `ToTensor()`, `Normalize(mean, std)`로 같은 일을 합니다.

### 자세히
| 단계 | OpenCV 직접 구현 | torchvision |
|---|---|---|
| 1. 짧은 변 256 | `cv2.resize` (비율 유지) | `Resize(256)` |
| 2. 가운데 224 | 슬라이싱 | `CenterCrop(224)` |
| 3. BGR → RGB | `cv2.cvtColor` | PIL은 원래 RGB |
| 4. ÷ 255, HWC → CHW | `astype`, `permute` | `ToTensor()` |
| 5. 표준화 | `(x − mean) / std` | `Normalize(mean, std)` |

- mean = (0.485, 0.456, 0.406), std = (0.229, 0.224, 0.225)
- 451 × 300 사진 → 385 × 256 → 가운데 224 × 224. 가장자리에 있는 대상은 잘릴 수 있다.
- 표준화 후 값 범위는 -2.05 ~ 1.91. 그대로 그리면 색이 이상하게 나오니 사진 확인은 `cropped`로 한다.

### 꼬리질문
#### `weights.transforms()`는 무엇인가요?
torchvision 가중치 객체에 들어 있는 그 모델의 추론용 전처리입니다. 크기, 크롭, 정규화 값을 직접 외워 쓰지 않아도 학습 때와 같은 규격을 그대로 가져올 수 있어서 실수를 줄입니다.

#### 학습용 전처리에서는 CenterCrop 대신 무엇을 많이 쓰나요?
ImageNet 학습에서는 무작위 위치와 크기로 자른 뒤 224로 맞추는 `RandomResizedCrop(224)`와 `RandomHorizontalFlip()`을 많이 씁니다. 검증과 추론에는 무작위성이 없는 `Resize(256)` + `CenterCrop(224)`를 씁니다.

## Q. 왜 ImageNet의 평균과 표준편차로 정규화하나요?
id: resnet-imagenet-normalize
type: 이유
level: 기본
tags: Normalize, 표준화, ImageNet, 사전학습
source: 5. 입력 전처리: 모델의 입력 규격 맞추기

### 30초 답변
mean (0.485, 0.456, 0.406)과 std (0.229, 0.224, 0.225)는 ImageNet 사진 전체에서 구한 R, G, B 채널별 평균과 표준편차입니다. 사전학습 모델의 첫 층 가중치는 이 기준으로 맞춘 입력에 맞춰 학습됐기 때문에, 새 데이터도 같은 값으로 바꿔야 모델이 보던 분포와 같아집니다. 그래서 내 데이터의 통계가 아니라 ImageNet 값을 학습·검증·추론 모두에 똑같이 씁니다.

### 자세히
```
x_norm = (x / 255 − mean) / std        # 채널별로 계산
```

- 일반적인 정규화 이유: 입력이 0 근처에 모이고 채널별 크기가 비슷해지면 기울기 크기가 고르게 되어 최적화가 안정된다.
- 사전학습 모델에서의 이유: 값의 기준 자체가 가중치에 새겨져 있다. 기준이 바뀌면 첫 층의 출력부터 학습 때와 다른 분포가 된다.
- 히스토그램으로 보면 값의 모양은 그대로이고 눈금만 바뀐다.

### 꼬리질문
#### 처음부터 학습하는 모델이라면 어떤 값을 쓰나요?
사전학습 가중치를 쓰지 않으면 내 Train 데이터에서 직접 채널별 평균과 표준편차를 구해 써도 됩니다. 다만 사전학습 모델을 쓰는 경우에는 데이터가 달라도 모델이 학습한 ImageNet 값을 그대로 쓰는 것이 원칙입니다.

## Q. 이미지를 PyTorch 모델에 넣을 때 텐서 모양은 어떻게 맞추나요?
id: resnet-tensor-batch
type: 개념
level: 기본
tags: 텐서, permute, 배치, DataLoader
source: 5. 입력 전처리 › 텐서, 배치, 데이터로더

### 30초 답변
OpenCV와 numpy 배열은 (높이, 너비, 채널) 순서인데 PyTorch 합성곱은 (채널, 높이, 너비)를 받아서 `permute(2, 0, 1)`로 채널 축을 앞으로 옮깁니다. 모델에는 여러 장을 묶은 배치로 넣으니 앞에 이미지 수 차원이 붙어 (배치, 3, 224, 224)가 됩니다. 데이터셋은 사진 한 장과 라벨을 돌려주고, 데이터로더가 그걸 배치로 묶습니다.

### 자세히
```python
tensor = torch.from_numpy(normalized).permute(2, 0, 1)   # (3, 224, 224)
single = tensor.unsqueeze(0)                             # (1, 3, 224, 224)
```

| 구성 요소 | 역할 |
|---|---|
| Dataset | `__getitem__`으로 (이미지, 라벨) 하나 반환 |
| DataLoader | 배치로 묶기, 섞기, 병렬 로딩 |
| Train 로더 | `shuffle=True` |
| Val 로더 | `shuffle=False` |

- `ToTensor()`는 HWC `uint8`을 CHW `float32`로 바꾸면서 255로 나누는 일까지 한 번에 한다.

### 꼬리질문
#### 사진 한 장만 예측할 때 `unsqueeze(0)`를 빼먹으면 어떻게 되나요?
모델이 (3, 224, 224)를 받으면 배치 차원이 없어서 에러가 나거나 버전에 따라 다르게 해석됩니다. 학습 때와 같은 4차원 모양으로 맞추는 게 안전합니다.

|---|---|
| 올바름 | tiger cat 43%, Egyptian cat 34%, tabby 23% |

| 표준화 누락 | Persian cat 12%까지 상승 |

### 꼬리질문
#### 이런 전처리 실수는 어떻게 미리 잡나요?
모델에 넣기 직전 배열의 모양, 자료형, 최솟값·최댓값·평균을 출력해서 기대한 범위인지 확인합니다. 체크포인트에 전처리 기준을 함께 저장해 두고 추론 코드가 그 값을 읽어 쓰게 하면 학습과 추론의 불일치를 막을 수 있습니다.

## Q. CNN으로 이미지를 분류하는 구조를 입력부터 출력까지 설명해 보세요.
id: resnet-cnn-classifier
type: 개념
level: 기본
tags: CNN, 분류, 전역 평균 풀링, 로짓
source: 6. CNN 분류 구조

### 30초 답변
CNN 분류는 합성곱 층들로 특징맵을 계산한 뒤, 그 특징을 클래스별 점수로 바꾸는 과정입니다. 합성곱, 배치 정규화, ReLU, 풀링을 거쳐 특징맵을 만들고, 전역 평균 풀링으로 특징맵마다 숫자 하나로 줄여 특징 벡터를 만든 다음, 선형 층이 클래스 수만큼의 로짓을 냅니다. 로짓은 Softmax를 거쳐야 확률이 됩니다.

### 자세히
| 단계 | 출력 모양 |
|---|---|
| 입력 | (1, 3, 224, 224) |
| `Conv2d(3, 8, 3, padding=1)` → BN → ReLU | (1, 8, 224, 224) |
| `MaxPool2d(2, 2)` | (1, 8, 112, 112) |
| `AdaptiveAvgPool2d((1, 1))` | (1, 8, 1, 1) |
| `flatten` | (1, 8) |
| `Linear(8, 2)` | (1, 2) |

- 커널 가중치 모양은 (출력 채널, 입력 채널, 높이, 너비) = (8, 3, 3, 3).
- 출력 채널 수 8과 클래스 수 2는 서로 상관없는 설정이다.
- 무작위 가중치일 때 로짓은 고양이 -0.122, 개 0.392였고, Softmax 후 (0.374, 0.626)이 됐다.

### 꼬리질문
#### 전역 평균 풀링을 쓰면 무엇이 좋은가요?
특징맵 한 장 전체를 평균 하나로 줄여서 입력 크기와 상관없이 특징 벡터 길이가 채널 수로 고정됩니다. 펼쳐서 거대한 FC층에 넣는 방식보다 파라미터가 훨씬 적어 과적합도 줄어듭니다.

#### 로짓과 확률은 어떻게 다른가요?
로짓은 음수일 수 있고 합이 1일 필요가 없는 원래 점수입니다. Softmax를 적용해야 0~1 사이이고 합이 1인 확률이 되며, 가장 큰 클래스는 로짓이든 확률이든 같습니다.

ImageNet으로 학습한 ResNet18의 첫 합성곱 층은 7×7 필터 64개인데, 열어 보니 대부분 특정 방향의 줄무늬나 특정 색 덩어리처럼 생겼습니다. Sobel 같은 경계 검출기가 여러 방향으로 들어 있는 셈이고, 사람이 설계한 게 아니라 데이터에서 저절로 배운 것입니다. 고양이 사진을 통과시키면 어떤 특징맵은 눈동자의 반사만, 어떤 건 털의 결이나 눈 테두리만 밝게 나와 필터마다 반응하는 모양이 달랐습니다.

깊은 층의 필터는 RGB가 아니라 이전 층의 수십~수백 채널 특징맵을 입력으로 받아서 사진처럼 그릴 수 없습니다. 그래서 특징맵을 보거나, 그 필터를 가장 강하게 활성화하는 입력을 찾는 방식으로 해석합니다.

## Q. 네트워크를 깊게 쌓으면 생기는 degradation 문제란 무엇이고, 과적합과 어떻게 다른가요?
id: resnet-degradation
type: 개념
level: 기본
tags: degradation, 최적화, 과적합, 깊은 네트워크
source: 8. ResNet › 더 깊게 쌓으면 더 좋아질까

### 30초 답변
degradation은 층을 더 깊게 쌓았는데 학습 데이터의 오차부터 더 커지는 현상입니다. ResNet 논문에서 20층과 56층 일반 네트워크를 비교했더니 56층이 학습 오차부터 더 높았습니다. 과적합이라면 학습 오차는 낮고 검증 오차만 높아야 하므로, 이는 표현력 부족이나 과적합이 아니라 깊은 망의 가중치를 제대로 맞추지 못하는 최적화 문제라는 뜻입니다.

### 자세히
| | 과적합 | degradation |
|---|---|---|
| 학습 오차 | 낮음 | 높음 |
| 검증 오차 | 높음 | 높음 |
| 원인 | 데이터 대비 모델이 복잡 | 깊은 망의 최적화가 어려움 |
| 대처 | 증강, 정규화, 데이터 추가 | 잔차 연결 |

- 논리: 56층은 20층에 항등 층 36개를 더한 해를 이론상 가질 수 있으니 최소한 20층만큼은 해야 한다. 그런데 못 한다면 그 해를 찾지 못한 것이다.

### 꼬리질문
#### degradation은 기울기 소실 때문인가요?
논문은 배치 정규화를 써서 순전파·역전파 신호가 사라지지 않는 일반망에서도 degradation이 생긴다고 보고, 기울기 소실만으로는 설명이 안 되는 최적화의 어려움으로 봤습니다. 잔차 연결은 이 최적화를 쉽게 만들고, 부가적으로 기울기가 흐를 길도 열어 줍니다.

## Q. 잔차 학습(residual learning)이란 무엇이고, 왜 학습이 쉬워지나요?
id: resnet-residual-learning
type: 개념
level: 기본
tags: 잔차 학습, ResNet, 항등 매핑
source: 8. ResNet › 잔차 학습: 차이만 배우자

### 30초 답변
잔차 학습은 층이 목표 출력 H(x) 전체를 배우는 대신 입력과의 차이 F(x) = H(x) − x만 배우게 하고, 출력은 F(x) + x로 만드는 방법입니다. 깊은 망이 최소한 얕은 망만큼 하려면 늘어난 층이 입력을 그대로 내보내기만 하면 되는데, 일반 층은 이것조차 학습으로 맞춰야 합니다. 잔차 층은 가중치가 0 근처일 때 이미 출력이 x라서, 시작부터 "입력을 그대로 넘기는" 상태에서 필요한 만큼만 차이를 더하면 됩니다.

### 자세히
```
H(x) = F(x) + x        F(x) = H(x) − x  (잔차)
```

층을 숫자 하나 w로 단순화하면 (입력 x = 1):

| | 일반 층 | 잔차 층 |
|---|---|---|
| 출력 | w·x | w·x + x |
| w ≈ 0일 때 | 0 | x |
| 항등이 되려면 | w를 1까지 키워야 함 | w = 0이면 됨 |

- 가중치는 보통 0 근처 작은 값에서 시작하므로 잔차 쪽이 출발점이 유리하다.

### 꼬리질문
#### ResNet은 언제, 누가 발표했나요?
2015년 Microsoft Research의 Kaiming He 등이 발표했고, 152층 모델로 ILSVRC 2015 분류 부문에서 우승했습니다. 이후 대부분의 깊은 모델이 잔차 연결을 기본으로 씁니다.

## Q. ResNet18의 기본 잔차 블록 구조를 설명해 보세요.
id: resnet-residual-block
type: 개념
level: 기본
tags: 잔차 블록, skip connection, BasicBlock
source: 8. ResNet › 잔차 블록

### 30초 답변
기본 블록은 3×3 합성곱, 배치 정규화, ReLU, 3×3 합성곱, 배치 정규화로 F(x)를 계산하고, 지름길(skip connection)이 입력 x를 그대로 보내 둘을 같은 위치끼리 더합니다. 더한 F(x) + x에 마지막으로 ReLU를 한 번 더 적용해 y = ReLU(F(x) + x)가 출력입니다. 지름길이 있어도 합성곱 연산은 다 하므로, 계산을 건너뛰는 게 아니라 입력을 하나 더 더하는 것입니다.

### 자세히
```
x ─┬─ 3×3 conv → BN → ReLU → 3×3 conv → BN ─┐
   │                                        ⊕ → ReLU → y
   └────────────── 지름길 (x 그대로) ────────┘
```

- 더하기는 원소별 합이라 파라미터가 늘지 않고 계산도 거의 들지 않는다.
- ReLU를 더한 뒤에 두는 이유: 덧셈 전에 F(x)를 ReLU로 자르면 잔차가 0 이상만 될 수 있어 표현이 제한된다.

### 꼬리질문
#### 더하기 대신 이어 붙이기(concatenate)를 하면 어떻게 되나요?
DenseNet처럼 채널을 이어 붙이면 이전 특징을 그대로 보존하지만 층을 지날수록 채널 수가 늘어 메모리와 계산이 커집니다. ResNet의 덧셈은 채널 수를 유지하면서 정보와 기울기가 지나갈 길을 냅니다.

#### pre-activation ResNet은 무엇이 다른가요?
BN과 ReLU를 합성곱 앞으로 옮기고 덧셈 뒤의 ReLU를 없애서, 지름길이 처음부터 끝까지 아무 변환 없는 순수한 항등 경로가 되도록 한 구조입니다. 매우 깊은 망에서 학습이 더 안정적이라고 보고됐습니다.

## Q. skip connection은 역전파에서 어떤 효과가 있나요?
id: resnet-skip-gradient
type: 이유
level: 심화
tags: skip connection, 역전파, 기울기 소실
source: 8. ResNet › 지름길은 역전파에도 길을 낸다

### 30초 답변
y = F(x) + x를 x로 미분하면 1 + ∂F/∂x가 되어서, 합성곱 경로의 기울기가 아무리 작아도 지름길 몫 1이 그대로 전달됩니다. 그래서 층을 거슬러 올라가도 기울기가 곱셈으로 줄어들지 않고 입력 쪽 층까지 살아서 도달합니다. 20층 망으로 재 보니 일반망은 1층 기울기가 8.4 × 10⁻¹⁹까지 줄었는데, 지름길망은 1층까지 0.81로 거의 줄지 않았습니다.

### 자세히
```
∂y/∂x = 1 + ∂F/∂x
∂L/∂x = ∂L/∂y · (1 + ∂F/∂x)
```

| 20층, sigmoid | 1층 가중치 기울기 크기 |
|---|---|
| 일반망 | 8.4 × 10⁻¹⁹ |
| 지름길망 | 0.81 |

- 차이가 잘 보이게 sigmoid로 실험했다. 실제 ResNet은 ReLU를 쓴다.
- LSTM이 셀 상태를 곱셈이 아닌 덧셈으로 갱신해 기울기를 살린 것과 같은 아이디어다.

### 꼬리질문
#### 일반망에서는 왜 기울기가 그렇게까지 작아지나요?
역전파는 층마다 국소 기울기를 곱해 나가는데, sigmoid의 미분은 최대 0.25라서 20층을 거치면 작은 수가 계속 곱해져 지수적으로 줄어듭니다. 잔차 연결은 이 곱셈 사슬 옆에 덧셈 경로를 하나 더 만들어 줍니다.

## Q. 입력과 출력의 모양이 다를 때 지름길은 어떻게 처리하나요?
id: resnet-projection-shortcut
type: 이유
level: 심화
tags: projection shortcut, 1x1 합성곱, downsample
source: 8. ResNet › 더하려면 모양이 같아야 한다

### 30초 답변
F(x) + x는 같은 위치끼리 더하는 것이라 두 텐서 모양이 완전히 같아야 합니다. layer2의 첫 블록은 stride 2로 크기를 줄이고 채널을 64에서 128로 늘려서, x는 [64, 56, 56], F(x)는 [128, 28, 28]이 되어 그대로는 못 더합니다. 그래서 지름길에 1×1 합성곱(stride 2)과 배치 정규화를 넣어, stride로 크기를 줄이고 1×1 합성곱으로 채널 수를 맞춥니다.

### 자세히
```python
model.layer2[0].downsample
# Sequential(
#   Conv2d(64, 128, kernel_size=1, stride=2, bias=False),
#   BatchNorm2d(128))
```

- 이 블록에서만 지름길이 순수한 항등이 아니게 된다. 나머지 블록은 x를 그대로 더한다.
- 논문의 선택지: (A) 늘어난 채널을 0으로 채우는 항등 지름길, (B) 모양이 바뀔 때만 projection, (C) 모든 지름길에 projection. 차이가 작아서 보통 B를 쓴다.

### 꼬리질문
#### 왜 모든 지름길에 projection을 쓰지 않나요?
성능 차이는 작은데 파라미터와 계산이 늘고, 항등 지름길이 주는 "그대로 전달되는 경로"의 장점이 약해지기 때문입니다. 모양을 맞춰야 하는 곳에만 쓰는 게 효율적입니다.

## Q. ResNet18의 전체 구조를 단계별로 설명해 보세요.
id: resnet18-architecture
type: 개념
level: 기본
tags: ResNet18, 구조, 특징맵 크기
source: 8. ResNet › ResNet18 전체 구조

### 30초 답변
ResNet18은 7×7 stride 2 합성곱과 맥스풀링으로 224 입력을 56까지 줄인 뒤, 기본 블록 2개씩으로 된 layer1부터 layer4를 지납니다. layer2부터는 단계마다 공간 크기가 절반, 채널이 두 배가 되어 마지막에 [512, 7, 7]이 되고, 전역 평균 풀링으로 길이 512 벡터를 만든 뒤 fc가 1,000개 클래스 점수를 냅니다. 이름의 18은 합성곱 17개와 fc 1개, 가중치가 있는 층 수이고 파라미터는 약 1,170만 개입니다.

### 자세히
| 단계 | 출력 [C, H, W] |
|---|---|
| 입력 | [3, 224, 224] |
| conv1 (7×7, stride 2) → BN → ReLU | [64, 112, 112] |
| maxpool | [64, 56, 56] |
| layer1 (기본 블록 2개) | [64, 56, 56] |
| layer2 | [128, 28, 28] |
| layer3 | [256, 14, 14] |
| layer4 | [512, 7, 7] |
| avgpool | [512, 1, 1] |
| fc | [1000] |

- 층 수: conv1 1 + 블록 8개 × 합성곱 2 = 16 + fc 1 = 18 (downsample의 1×1 합성곱은 세지 않음).
- 크기를 절반으로 줄일 때 채널을 두 배로 늘려 층별 계산량을 비슷하게 유지한다.

### 꼬리질문
#### 각 단계의 출력 모양은 어떻게 확인했나요?
forward hook을 각 단계에 걸어 사진 한 장을 통과시키며 출력 모양을 기록했습니다. 모델 코드를 고치지 않고 중간 출력을 볼 수 있어서 구조를 이해하거나 특징을 뽑을 때 유용합니다.

## Q. Basic block과 Bottleneck block의 차이는 무엇인가요?
id: resnet-basic-vs-bottleneck
type: 비교
level: 심화
tags: Bottleneck, BasicBlock, 1x1 합성곱, 연산량
source: 8. ResNet › 병목 블록

### 30초 답변
ResNet18과 34는 3×3 합성곱 두 개로 된 기본 블록을 쓰고, ResNet50 이상은 병목 블록을 씁니다. 병목 블록은 1×1 합성곱으로 채널을 줄이고, 3×3 합성곱을 한 뒤, 다시 1×1로 채널을 늘리는 구조입니다. 비싼 3×3 합성곱을 채널이 적은 곳에서만 해서, 깊이를 크게 늘려도 계산량을 감당할 수 있습니다.

### 자세히
| | 기본 블록 | 병목 블록 |
|---|---|---|
| 구성 | 3×3 → 3×3 | 1×1 (축소) → 3×3 → 1×1 (확장) |
| 사용 | ResNet18, 34 | ResNet50, 101, 152 |

출력 한 픽셀당 곱셈 수:

| 블록 | 곱셈 수 |
|---|---|
| 256채널 기본 블록 | 약 118만 |
| 병목 256 → 64 → 256 | 69,632 (약 17분의 1) |
| 64채널 기본 블록 | 73,728 |

- 병목: 256·64 + 9·64·64 + 64·256 = 69,632

### 꼬리질문
#### 1×1 합성곱은 무슨 일을 하나요?
공간 방향으로는 섞지 않고 픽셀마다 채널들을 선형 결합해서 채널 수를 줄이거나 늘립니다. 병목 블록의 채널 조절과 projection 지름길의 채널 맞추기가 모두 이 역할입니다.

## Q. AlexNet과 ResNet18을 비교하면 무엇이 다른가요?
id: resnet-vs-alexnet
type: 비교
level: 기본
tags: AlexNet, 파라미터 수, 전역 평균 풀링, FC층
source: 8. ResNet › AlexNet과 비교

### 30초 답변
ResNet18이 훨씬 깊은데도 파라미터는 약 1,169만 개로 AlexNet의 약 6,110만 개의 5분의 1도 안 됩니다. AlexNet은 마지막 특징맵을 펼쳐 거대한 FC층 세 개에 넣어 파라미터의 96%가 FC층에 있지만, ResNet18은 전역 평균 풀링으로 512개 숫자만 남기고 FC 하나만 써서 FC 비율이 4.4%입니다. 또 ResNet은 합성곱마다 배치 정규화를 붙이고 잔차 연결을 써서 깊게 쌓아도 학습이 됩니다.

### 자세히
| | AlexNet | ResNet18 |
|---|---|---|
| 발표 | 2012 | 2015 |
| 파라미터 | 약 6,110만 | 약 1,169만 |
| FC 비율 | 96% (FC 3개) | 4.4% (512 → 1000 하나) |
| 특징 → 분류 | flatten → 큰 FC | 전역 평균 풀링 → 작은 FC |
| 정규화 | 배치 정규화 없음 | 합성곱마다 배치 정규화 |
| 지름길 | 없음 | 잔차 연결 |

### 꼬리질문
#### 파라미터가 적은데 왜 성능은 더 좋나요?
파라미터 대부분을 공간 위치마다 공유되는 합성곱에 쓰고, 깊이로 표현력을 얻기 때문입니다. FC층에 몰린 파라미터는 위치마다 따로 가중치를 두어 과적합되기 쉽고 효율이 낮습니다.

## Q. 전이학습이란 무엇이고, 백본과 헤드는 무엇인가요?
id: resnet-transfer-learning
type: 개념
level: 기본
tags: 전이학습, 사전학습, 백본, 헤드
source: 9. 전이학습 › 미리 배운 모델 가져다 쓰기

### 30초 답변
전이학습은 다른 데이터로 미리 학습한 가중치를 새 문제에 다시 쓰는 방법입니다. 마지막 분류기 앞까지의 특징 추출부를 백본, 그 뒤 분류기를 헤드라고 하는데, 앞쪽 층은 선, 모서리, 질감처럼 어떤 사진에도 쓰이는 특징을 배우기 때문에 ImageNet으로 배운 백본을 개·고양이 분류에 그대로 쓸 수 있습니다. 바꿔야 하는 건 1,000개 클래스를 고르던 헤드뿐이라, 사진이 적어도 좋은 성능을 낼 수 있습니다.

### 자세히
```python
from torchvision.models import resnet18, ResNet18_Weights
weights = ResNet18_Weights.IMAGENET1K_V1
model = resnet18(weights=weights)       # weights=None이면 무작위 초기값
model.fc.in_features                    # 512
```

- ImageNet: 사진 약 128만 장, 1,000개 클래스
- 백본 = conv1 ~ layer4 + avgpool, 헤드 = fc
- 장점: 적은 데이터, 빠른 학습, 과적합 감소

### 꼬리질문
#### 전이학습이 잘 안 통하는 경우는 언제인가요?
의료 영상, 위성 사진, 흑백 산업 영상처럼 ImageNet 사진과 분포가 크게 다르면 뒤쪽 층의 고수준 특징이 잘 맞지 않습니다. 이때는 더 많은 층을 미세조정하거나, 같은 도메인 데이터로 사전학습한 모델을 찾는 게 좋습니다.

## Q. 백본을 고정하고 분류기만 교체하는 방법을 코드 수준에서 설명해 보세요.
id: resnet-freeze-backbone
type: 개념
level: 기본
tags: 전이학습, requires_grad, 분류기 교체, 특징 추출
source: 9. 전이학습 › 백본 고정, 분류기 교체

### 30초 답변
먼저 모든 파라미터의 `requires_grad`를 False로 바꿔 고정하고, `model.fc`를 `nn.Linear(512, 2)`로 새로 만들어 끼웁니다. 새로 만든 층은 기본이 학습 가능 상태라 fc만 학습되고, 옵티마이저에도 `model.fc.parameters()`만 넘깁니다. 학습할 값이 1,026개뿐이라 1,100만 개 넘는 모델의 약 0.01%만 학습하는 셈이어서 사진이 적어도 과적합이 덜하고 학습이 빠릅니다.

### 자세히
```python
for p in model.parameters():
    p.requires_grad = False              # 1. 전부 고정
model.fc = nn.Linear(model.fc.in_features, 2)   # 2. 새 분류기 (cat 0, dog 1)
optimizer = torch.optim.Adam(model.fc.parameters(), lr=0.001)
```

| 방식 | 학습 가능 파라미터 |
|---|---|
| fc만 | 1,026 (512 × 2 + 2) |
| layer4 + fc | 약 839만 |
| 전체 | 약 1,170만 |

### 꼬리질문
#### 고정한 층은 역전파 때 계산이 생략되나요?
고정한 파라미터의 가중치 기울기는 계산하지 않아서 메모리와 시간이 줄어듭니다. 다만 고정한 층보다 앞에 학습할 층이 있으면 그 층까지 기울기를 전달하기 위해 입력에 대한 기울기는 계산합니다.

## Q. 백본을 requires_grad=False로 고정했는데 배치 정규화는 왜 막히지 않나요?
id: resnet-bn-freeze
type: 이유
level: 심화
tags: 배치 정규화, running stats, eval 모드, 전이학습
source: 9. 전이학습 › 배치 정규화는 requires_grad로 못 막는다

### 30초 답변
배치 정규화 층은 train 모드에서 forward가 일어날 때마다 `running_mean`, `running_var`를 갱신하는데, 이건 옵티마이저가 아니라 forward가 바꾸는 버퍼라서 `requires_grad=False`로는 막을 수 없습니다. 실제로 백본을 고정하고 train 모드로 고양이 사진 16장을 통과시키자 첫 배치 정규화 층의 기록이 최대 0.27이나 바뀌었습니다. `model.eval()`로 백본을 평가 모드에 두고 `model.fc.train()`으로 분류기만 학습 모드로 두자 바뀐 양이 정확히 0이었습니다.

### 자세히
| 값 | 종류 | 바꾸는 주체 | 막는 법 |
|---|---|---|---|
| `weight`, `bias` (γ, β) | 파라미터 | 옵티마이저 | `requires_grad=False` |
| `running_mean`, `running_var` | 버퍼 | train 모드 forward | `eval()` |

```python
model.eval()        # 백본: BN이 저장된 통계 사용, 갱신 안 함
model.fc.train()    # 분류기만 학습 모드
```

- `eval()`은 BN, 드롭아웃의 동작만 바꾸고 기울기 계산은 끄지 않는다. fc의 기울기는 정상 계산된다.
- 문제점: ImageNet 128만 장으로 쌓은 통계가 작은 배치 몇 개의 평균 쪽으로 끌려간다.

### 꼬리질문
#### 에포크마다 검증 후 `model.train()`을 부르면 어떻게 되나요?
모델 전체가 다시 train 모드가 되어 백본의 배치 정규화 통계가 또 갱신됩니다. 그래서 학습 에포크를 시작할 때마다 `model.eval()`과 `model.fc.train()`을 다시 불러야 합니다.

#### `eval()`과 `torch.no_grad()`는 어떻게 다른가요?
`eval()`은 배치 정규화와 드롭아웃의 동작 방식을 추론용으로 바꾸고, `no_grad()`나 `inference_mode()`는 기울기 계산 기록을 끕니다. 검증할 때는 둘 다 써야 하고, 백본을 고정해 학습할 때는 `eval()`만 씁니다.

## Q. 미세조정(fine-tuning)은 어떤 전략으로 하고, 왜 낮은 학습률을 쓰나요?
id: resnet-fine-tuning
type: 개념
level: 심화
tags: 미세조정, fine-tuning, 학습률, 전이학습
source: 9. 전이학습 › 미세조정

### 30초 답변
미세조정은 새 분류기를 학습한 뒤 백본의 일부나 전체까지 다시 학습시키는 방법으로, 데이터가 어느 정도 있고 대상이 ImageNet과 많이 다를 때 씁니다. 보통 출력에 가까운 layer4부터 풀고, 이미 잘 학습된 가중치가 망가지지 않도록 새 분류기보다 작은 학습률을 줍니다. 처음부터 함께 풀면 무작위로 초기화된 분류기의 큰 기울기가 백본으로 흘러가 사전학습 특징을 망칠 수 있어서, 분류기를 먼저 학습한 뒤 푸는 순서를 씁니다.

### 자세히
| | 데이터 적음 | 데이터 많음 |
|---|---|---|
| ImageNet과 비슷 | fc만 학습 | 뒤쪽 층 미세조정 |
| ImageNet과 다름 | fc + 일부 층을 신중히 | 많은 층 또는 전체 미세조정 |

```python
for p in model.layer4.parameters():
    p.requires_grad = True
optimizer = torch.optim.Adam([
    {"params": model.layer4.parameters(), "lr": 1e-4},
    {"params": model.fc.parameters(), "lr": 1e-3},
])
```

- layer4와 fc를 함께 학습하면 학습할 값이 약 839만 개로 늘어난다.
- 뒤쪽 층부터 푸는 이유: 앞쪽 층은 범용 특징, 뒤쪽 층은 원래 과제에 특화된 특징이다.

### 꼬리질문
#### 일부 층을 풀어 미세조정할 때 배치 정규화는 어떻게 하나요?
배치가 작으면 배치 통계가 불안정해서 BN 층은 eval 모드로 계속 두는 경우가 많습니다. 데이터와 배치가 충분하다면 푼 층의 BN을 train 모드로 두어 새 데이터의 통계에 맞춥니다.

## Q. 학습·검증 루프는 어떻게 구성하나요?
id: resnet-train-val-loop
type: 개념
level: 기본
tags: 학습 루프, 검증, CrossEntropyLoss, 에포크
source: 10. 학습, 검증, 저장 › 한 배치, 한 에포크

### 30초 답변
배치마다 모델에 넣어 로짓을 얻고, 손실을 계산하고, `zero_grad`, `backward`, `step` 순서로 파라미터를 한 번 갱신하며, Train 전체를 한 번 다 쓰면 1에포크입니다. 에포크가 끝날 때마다 `model.eval()`과 `torch.inference_mode()` 안에서 Val 성능을 잽니다. 에포크 손실과 정확도는 배치 평균을 다시 평균 내지 않고, 마지막 배치가 작을 수 있으니 전체 사진 수 기준으로 계산합니다.

### 자세히
```python
for images, labels in train_loader:
    images, labels = images.to(device), labels.to(device)
    logits = model(images)                 # (배치, 2)
    loss = criterion(logits, labels)       # labels: (배치,) long
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

loss_sum += loss.item() * len(labels)      # 배치 평균 × 장수
correct += (logits.argmax(1) == labels).sum().item()
epoch_loss = loss_sum / image_count
```

- `CrossEntropyLoss`에는 Softmax 전의 로짓을 넣는다. Softmax는 손실 안에서 처리된다.
- 옵티마이저는 반복문 밖에서 한 번만 만든다.
- 사진 10장, 배치 4 → 4, 4, 2장. 배치 평균의 평균은 마지막 2장을 과대 반영한다.

### 꼬리질문
#### `zero_grad()`를 빼먹으면 어떻게 되나요?
PyTorch는 기울기를 덮어쓰지 않고 누적하기 때문에 이전 배치의 기울기가 계속 더해져 갱신이 엉뚱해집니다. 일부러 누적해서 큰 배치 효과를 내는 기울기 누적 기법이 아니라면 매 배치마다 초기화합니다.

## Q. 어느 에포크의 모델을 저장해야 하고, 체크포인트에는 무엇을 담나요?
id: resnet-best-checkpoint
type: 이유
level: 기본
tags: 모델 선택, 체크포인트, 조기 종료, state_dict
source: 10. 학습, 검증, 저장 › 어느 에포크를 저장할까

### 30초 답변
Train 손실은 계속 내려가도 Val 손실이 다시 오르기 시작하면 과적합이 시작된 것이라, Val 손실이 가장 낮은 에포크의 모델을 저장합니다. 수업 예시에서 Val 손실은 2에포크 0.55가 가장 낮고 3에포크에 0.63으로 올라서, 정확도가 80%로 같아도 2에포크 모델을 골랐습니다. 저장할 때는 `state_dict()`를 `deepcopy`로 따로 복사하고, 체크포인트에는 가중치뿐 아니라 클래스 정보와 전처리 기준, 선택 기록까지 담습니다.

### 자세히
| 에포크 | Train 손실 | Val 손실 | Val 정확도 |
|---|---|---|---|
| 1 | 0.80 | 0.72 | 70% |
| 2 | 0.55 | **0.55** | 80% |
| 3 | 0.40 | 0.63 | 80% |

```python
if val_loss < best_val_loss:
    best_val_loss = val_loss
    best_state = deepcopy(model.state_dict())
```

- `deepcopy` 이유: `state_dict()`는 현재 가중치를 가리키기만 해서 다음 에포크 학습과 함께 바뀐다.
- 체크포인트: 모델 상태(가중치, BN 통계), 분류 설정(구조, 클래스 이름·번호, 전처리 기준), 선택 기록(에포크, Val 손실).

### 꼬리질문
#### 정확도가 같은데 왜 Val 손실로 고르나요?
정확도는 맞았는지만 보지만 손실은 정답에 얼마나 확신했는지까지 반영합니다. 3에포크는 정답 수는 같아도 틀린 사진에 더 강하게 확신하는 등 예측이 나빠지기 시작했다는 신호입니다.

#### 조기 종료(early stopping)는 이것과 어떤 관계인가요?
Val 손실이 정해진 에포크 수 동안 개선되지 않으면 학습을 멈추고 가장 좋았던 모델로 돌아가는 방법입니다. 최적 모델 저장과 함께 쓰면 쓸데없는 학습 시간을 줄이고 과적합된 모델을 쓰는 일을 막습니다.
