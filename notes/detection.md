## 개념 지도

### 분류만으로는 부족하다: 무엇이 어디에
related: det-task-comparison
핵심: 탐지는 사진 한 장에 이름 하나를 붙이는 게 아니라, 객체마다 "어디에(박스)"와 "무엇(Class)"을 함께 찾는다.
- 같은 버스 사진에 분류 모델(`yolo11n-cls`)은 minibus 0.57, police_van 0.34라고만 답했다. 사람이 네 명 찍혀 있는데 사람에 대한 정보는 하나도 없다.
- 탐지 모델(`yolo11n`)은 버스 1개와 사람 4명을 각각 박스로 찾았다. 결과가 객체마다 한 줄(박스, Class, 점수)씩 나온다.

| | 분류 | 탐지 |
|---|---|---|
| 출력 | 이미지 전체에 Class 1개 | 객체마다 박스 좌표 4개 + Class + 점수 |
| 결과 개수 | 항상 1개 | 0개 이상 (없으면 빈 결과) |
| 위치 정보 | 없음 | 있음 |

- 위치를 알면 개수를 세고, 객체 사이 거리를 재고, 찾은 영역을 추적·분할·자세 추정의 입력으로 넘길 수 있다.
- 쓰이는 곳: 자율주행(보행자, 신호등), 제조 라인(결함 위치), CCTV(사람, 차량), 의료 영상(병변 후보), 매대(진열 상태)
막힌 점: "어디에"를 숫자로 적는 약속부터 정해야 한다.

### Bounding Box와 좌표 형식
related: det-box-format
핵심: 박스는 객체의 보이는 영역 전체를 감싸는 가장 작은 직사각형이고, 같은 박스를 꼭짓점(xyxy)이나 중심과 크기(xywh)로 적는다.
- 이미지 좌표계는 원점이 **왼쪽 위**이고 y가 **아래로** 갈수록 커진다. 수학 시간의 좌표계와 y 방향이 반대다.
- **xyxy** `(x1, y1, x2, y2)`: 왼쪽 위와 오른쪽 아래 꼭짓점. IoU처럼 꼭짓점이 필요한 계산에 쓴다.
- **xywh** `(x_center, y_center, w, h)`: 중심점과 너비, 높이. YOLO 라벨 파일이 이 형식이다.
- **정규화 버전**(`xyxyn`, `xywhn`): x 방향 값은 너비 W로, y 방향 값은 높이 H로 나눈 0~1 값. 이미지를 resize해도 값이 그대로다.
- 예: bus.jpg(810×1080)의 가운데 남자는 xyxy `[223, 409, 344, 860]`, xywh `[284, 635, 121, 452]`, xywhn `[0.350, 0.588, 0.150, 0.418]`이다(원래 값에 소수점이 있어 반올림한 숫자).
- 한계: 직사각형이라 객체의 실제 윤곽은 표현하지 못한다.
막힌 점: 위치만으로는 결과가 아니다. 그 박스가 무엇이고, 모델이 얼마나 확신하는지도 붙어야 한다.

### Class와 Confidence Score
related: det-output-confidence
핵심: 박스마다 Class ID와 0~1 Confidence Score가 붙고, 점수는 모델의 자기 추정일 뿐 정답이라는 보장이 아니다.
- Class는 모델 안에서 정수 ID로 다루고, 이름 대응(`0: person, 2: car, ...`)은 따로 둔다. 모델은 학습한 Class만 낼 수 있다. COCO 사전학습 모델은 80개다.
- `boxes.cls`는 float Tensor라서 이름을 찾을 때 `int()`로 바꿔야 한다.
- Confidence Score는 "이 박스에 이 Class 객체가 있을 가능성"을 **모델이** 예측한 값이다. 실제로 맞았는지는 평가 단계에서 정답과 비교해 따로 판정한다.
- 같은 사진의 같은 사람에게 n 모델은 0.62, s 모델은 0.66을 줬다. 점수 크기는 모델마다 다르니, 점수 자체로 모델의 정확도를 비교하면 안 된다.
- 결국 탐지 결과 하나 = (박스 4개 값, Class, Score) 한 세트다.
막힌 점: 출력 형태는 정했다. 신경망이 이런 결과를 어떻게 만들어 내는가? 처음에는 두 단계로 나눠서 풀었다.

### Two-stage와 One-stage
related: det-two-vs-one-stage, det-rcnn-rpn
핵심: 객체가 있을 만한 후보 영역을 먼저 만들고 하나씩 분류하던 두 단계 방식에서, 이미지 전체를 한 번 통과시켜 박스와 Class를 동시에 내는 한 단계 방식으로 왔다.
- **Two-stage**: 1단계에서 후보 영역을 만들고, 2단계에서 후보마다 Class를 분류하고 박스를 보정한다. R-CNN, Fast R-CNN, Faster R-CNN(후보 생성도 신경망인 RPN이 맡음)
- **One-stage**: 후보 단계가 없다. 신경망 출력이 곧바로 검출 후보다. YOLO 계열, SSD, RetinaNet
- YOLO(You Only Look Once, 2016, Joseph Redmon 등)는 이름처럼 이미지당 forward 한 번으로 끝난다.
- 초기에는 Two-stage가 더 정확하다고 평가받았지만, 지금 YOLO는 실시간 속도에서 높은 정확도를 낸다. 모델 크기(n~x)로 속도와 정확도를 고를 수도 있다.
- 직관: Two-stage는 "의심 가는 곳을 먼저 추리고 하나씩 자세히 보기", One-stage는 "사진 전체를 한 번 훑으며 동시에 답하기"
막힌 점: 후보 단계 없이 한 번에 낸다면, 이미지의 어느 부분이 어느 객체를 책임질지 정해야 한다.

### YOLOv1: 7×7 Grid와 그 한계
related: det-yolov1-grid
핵심: 이미지를 7×7 칸으로 나누고 객체 중심이 들어간 칸이 그 객체를 맡게 했지만, 칸 하나가 Class 하나만 고르니 작고 붙어 있는 객체에 약했다.
- 448×448 입력을 7×7로 나누고, 칸마다 박스 2개와 Class 확률을 예측한다.
- 그래서 이미지 한 장에서 최대 49 × 2 = **98개** 박스만 낼 수 있다.
- 작은 객체 여러 개의 중심이 같은 칸에 들어가면 하나밖에 못 찾는다. 새 떼나 군중처럼 붙어 있는 객체에 약했던 이유다.
- 박스의 크기와 비율도 아무 기준 없이 처음부터 맞혀야 했다.
- 직관: 학생 49명에게 "네 자리 앞에 있는 물건 하나만 말해"라고 시킨 것. 한 자리 앞에 물건이 셋이면 둘은 빠진다.
막힌 점: 가로로 긴 버스와 세로로 긴 사람을 아무 기준 없이 맞히기는 어렵다.

### Anchor Box: 기준 박스에서 고쳐 나간다
related: det-anchor-box
핵심: 미리 정한 크기와 비율의 기준 박스(Anchor)를 위치마다 두고, 객체와 가장 비슷한 Anchor에서 조금씩 고쳐 예측한다(YOLOv2, 2017).
- 가로로 긴 것, 세로로 긴 것, 정사각형에 가까운 것 등을 격자 위치마다 둔다.
- 블로그 예: 가로가 세로의 1.6배인 버스에는 2:1 Anchor가 IoU **0.80**, 세로가 가로의 3.7배인 사람에는 1:3 Anchor가 IoU **0.81**로 가장 잘 맞았다. 넓이가 같아도 비율이 안 맞으면 IoU가 0.2~0.3대로 떨어진다.
- 직관: 백지에 그리는 대신 비슷한 본을 대고 조금만 고치는 것
- 대가: 데이터셋에 맞는 Anchor 크기와 비율을 골라야 하고, 개수와 형태가 하이퍼파라미터로 늘고, 위치마다 여러 개라 후보가 많아지고, 어떤 Anchor가 어떤 객체를 맡을지 정하는 과정 때문에 학습이 복잡해진다.
막힌 점: 비율 문제는 줄었지만, 격자 한 장으로는 아주 작은 객체와 아주 큰 객체를 함께 다루기 어렵다.

### 여러 Feature Map과 Backbone, Neck, Head
related: det-multiscale-feature, det-backbone-neck-head, det-fpn-pan, det-anchor-free
핵심: 해상도가 다른 여러 Feature Map에서 동시에 예측하고(높은 해상도는 작은 객체, 낮은 해상도는 큰 객체), 이를 Backbone이 뽑고 Neck이 섞고 Head가 예측한다.
- **Backbone**: Conv를 쌓아 Feature Map을 뽑는다. 깊어질수록 해상도는 낮아지고 채널은 늘어난다. 얕은 층은 경계와 질감(위치가 정확), 깊은 층은 객체 단위 의미를 담는다. YOLO11은 C3k2, SPPF, C2PSA 블록을 쓴다.
- 문제: 얕은 층은 위치는 정확하지만 "무엇인지"를 잘 모르고, 깊은 층은 그 반대다.
- **Neck**: FPN(top-down)은 깊은 층을 키워 얕은 층과 합쳐 의미를 아래로 내려보내고, PAN(bottom-up)은 합친 결과를 다시 줄여 위치 정보를 위로 올려보낸다. Neck을 지난 Feature Map은 위치와 의미를 함께 갖는다.
- **Head**: 세 크기의 Feature Map마다 박스 branch와 Class branch가 따로 예측한다. 박스는 격자점에서 왼쪽, 위, 오른쪽, 아래 경계까지의 거리 `(l, t, r, b)`로 예측해서 Anchor가 필요 없다(**anchor-free**).
- Class 점수는 Class마다 **sigmoid**를 씌워 0~1로 낸다. softmax가 아니라서 Class 점수끼리 합이 1일 필요가 없다.
막힌 점: 구조는 알았다. 실제 YOLO11에서 후보가 몇 개 나오고, 어떻게 최종 박스가 되는지 따라가 볼 차례다.

### YOLO11: 3개 Feature Map, 8,400개 위치
related: det-yolo11-8400, det-model-size
핵심: 640×640 입력이 stride 8, 16, 32의 격자 80×80, 40×40, 20×20이 되어, 모두 8,400개 위치에서 각각 박스 하나와 Class 점수를 낸다.
- 6,400 + 1,600 + 400 = **8,400**. 신경망 출력 shape은 `(1, 84, 8400)`이고, 84 = 박스 4개(xywh) + COCO 80개 Class 점수다.
- 추론 5단계: 640×640으로 바꾸고 비율 유지로 남는 곳은 padding → forward 한 번으로 후보 8,400개 → 점수 낮은 후보 삭제 → 중복 박스 삭제(NMS) → 좌표를 원본 크기로 되돌리기
- bus.jpg에서 버스와 크게 찍힌 사람 셋은 전부 **stride 32**에서, 몸이 반쯤 잘려 작게 보이는 사람만 stride 16에서 나왔다. stride 8에는 후보가 하나도 없었다.
- 크기 n, s, m, l, x는 같은 구조에서 층 반복 횟수(depth)와 채널 수(width)만 다르다. n은 262만 개, s는 946만 개로 3.6배다. 실시간이나 CPU는 n, s, 정확도 우선이면 m~x. 데이터가 적으면 큰 모델은 과적합되기 쉽다.
- `yolo11n.pt`는 COCO(80개 Class)로 학습을 마친 사전학습 가중치다.
막힌 점: 8,400개 후보 대부분은 배경이다. 쓸모없는 후보부터 걸러야 한다.

### Confidence Threshold: 낮은 점수를 걸러 낸다
related: det-conf-threshold
핵심: 점수가 기준(기본 0.25)보다 낮은 후보를 버리며, 기준을 낮추면 놓치는 객체가 줄고 잘못된 검출이 늘고, 높이면 반대다.
- bus.jpg에서 8,400개 중 0.25 이상은 47개였다.
- `model("image.jpg", conf=0.5)`처럼 바꾼다.

| conf | 검출 수 | 바뀐 것 |
|---|---|---|
| 0.10 | 6 | 발밑에 `skateboard 0.12`가 생김. 실제로는 신발 |
| 0.25 | 5 | 버스 1, 사람 4 |
| 0.50 | 5 | 그대로 |
| 0.80 | 4 | 몸이 잘린 사람(0.62)이 빠짐 |

- 정답인 값은 없다. 놓치면 안 되는 일(병변 후보)은 낮게, 잘못된 경보가 비싼 일은 높게 잡는다.
막힌 점: 남은 47개를 그려 보면 같은 사람에게 박스가 겹겹이 쌓여 있다. 다 점수가 높아서 Threshold로는 지울 수 없다.

### 중복 박스와 NMS
related: det-nms, det-nms-iou-threshold, det-nms-alternatives
핵심: 점수가 가장 높은 박스를 남기고, 그 박스와 많이 겹치는 같은 Class 박스를 지우는 일을 반복한다.
- 중복이 생기는 이유: 같은 객체 주변의 여러 격자 위치가 각자 그 객체를 보고 비슷한 박스를 낸다.
- 절차: ① 점수 내림차순 정렬 ② 가장 높은 박스를 결과로 선택 ③ 선택한 박스와 IoU가 기준보다 큰 박스 삭제 ④ 남은 박스가 없을 때까지 ②~③ 반복
- 가운데 남자 주변 person 후보는 9개(0.72~0.83)였다. 0.83을 고르자 나머지 8개와 IoU가 0.95~0.99라 한 번에 지워졌다. 사진 전체로는 47개 → 5개(버스 1, 사람 4)로 라이브러리 결과와 같았다.
- Ultralytics는 **같은 Class끼리만** NMS를 한다. 사람 박스가 겹친 자전거 박스를 지우지 않는다.
- **IoU Threshold**(기본 0.7): 낮추면 가까이 선 다른 객체까지 지우고, 높이면 중복이 남는다. zidane.jpg는 두 사람 박스 IoU가 0.333이라, 0.1로 낮추자 지단의 0.78 박스가 지워지고 더 나쁜 0.34 후보가 대신 남았다.
막힌 점: "많이 겹친다"를 재는 IoU를 제대로 정의해야 한다. 이 숫자는 평가에서도 그대로 다시 쓰인다.

### IoU: 겹침을 0~1로 잰다
related: det-iou, det-small-object
핵심: IoU = 겹친 면적 / 합친 면적이고, 같은 픽셀 오차라도 박스가 작을수록 IoU가 훨씬 크게 떨어진다.
- 교집합: 왼쪽 위는 두 박스 왼쪽 위 중 더 안쪽(큰 값), 오른쪽 아래는 더 안쪽(작은 값). 가로나 세로가 음수면 안 겹친 것이니 0
- 합집합: 두 면적을 더하면 겹친 부분이 두 번 들어가니 한 번 뺀다. `union = area1 + area2 − intersection`
- 0이면 전혀 안 겹침, 1이면 위치와 크기가 완전히 같음. 작은 박스가 큰 박스 안에 **완전히** 들어가도 크기 차이가 크면 0.111이다. 다 포함했다고 잘 맞힌 게 아니다.
- 크기가 같은 박스를 가로·세로로 밀었을 때 IoU가 0.5 아래로 떨어지는 거리: 200×200은 37px, 100×100은 19px, 50×50은 10px, 20×20은 **4px**. 작은 객체의 mAP가 낮게 나오는 이유 중 하나다.
- 쓰이는 곳: NMS 중복 판단, 평가의 TP 판정, mAP50-95, box_loss(CIoU), 추적에서 박스 잇기
막힌 점: 이제 예측과 정답의 겹침을 잴 수 있다. 이것으로 예측 하나하나를 맞음, 틀림으로 판정하는 규칙이 필요하다.

### TP, FP, FN: 예측을 채점한다
related: det-tp-fp-fn, det-matching
핵심: Class가 같고 IoU가 기준 이상인 정답(GT)과 짝지어진 예측은 TP, 짝을 못 찾은 예측은 FP, 짝을 못 찾은 GT는 FN이다.
- **GT(Ground Truth)**: 사람이 그린 정답 박스와 Class. GT 품질이 낮으면 평가도 믿을 수 없다.
- 매칭 절차: 예측을 점수 내림차순으로 → 같은 Class GT 중 IoU가 가장 큰 것 → 기준 이상이고 아직 짝이 없으면 TP, 아니면 FP → 끝까지 짝 없는 GT는 FN
- GT 하나에는 TP가 **최대 1개**다. FP는 네 가지다: 빈 곳에 예측, Class 틀림, IoU 부족, 이미 짝지어진 GT에 또 예측(중복)
- 블로그 예(GT 3, 예측 6): P2는 P1과 같은 dog를 잡았지만 늦게 와서 중복 FP, P3는 위치는 맞는데 cat이라 FP, P5는 IoU가 모자라 FP이고 그 GT2는 FN. **TP 2, FP 4, FN 1**
- 판정은 기준에 따라 바뀐다. IoU 0.6짜리 예측은 기준 0.5에서 TP, 0.75에서 FP다. 예측이 나빠진 게 아니라 채점이 까다로워진 것이다.
막힌 점: 판정 결과를 몇 개의 숫자로 요약해야 모델을 말할 수 있다.

### Precision과 Recall
related: det-precision-recall
핵심: Precision은 낸 예측 중 맞은 비율(헛것을 덜 보는가), Recall은 실제 객체 중 찾은 비율(덜 놓치는가)이고, Confidence Threshold를 바꾸면 서로 반대로 움직인다.
- **Precision** = TP / (TP + FP), **Recall** = TP / (TP + FN)
- 위 예: Precision 2/6 = 0.33, Recall 2/3 = 0.67. 실습의 TP 6, FP 2, FN 4는 0.75, 0.6
- Threshold를 높이면 예측이 줄어 Precision은 오르고 Recall은 내려간다. 낮추면 반대다.
- 알약 모델은 conf 0.25~0.6에서 둘 다 0.95 이상이었고, 0.8을 넘기면 Recall이 급격히 무너졌다.
- Ultralytics 로그에 찍히는 P, R은 **특정 Threshold 하나**에서 잰 값이다.
막힌 점: Threshold 하나에서 잰 두 숫자로는 모델끼리 공정하게 비교하기 어렵다. 모든 Threshold를 한 번에 봐야 한다.

### PR Curve, AP, mAP
related: det-pr-curve-ap, det-map
핵심: Threshold를 바꿔 가며 얻은 (Recall, Precision) 점을 이은 곡선 아래 면적이 AP이고, Class별 AP의 평균이 mAP다.
- 그리는 법: 한 Class의 예측을 점수순으로 정렬 → 각각 TP/FP 판정 → 위에서부터 하나씩 포함하며 누적 TP, FP를 셈 → 매 시점의 (Recall, Precision)을 점으로
- x축 Recall, y축 Precision, 오른쪽 위에 붙을수록 좋은 모델이다.
- 실제 곡선은 지그재그라서, 각 Recall의 Precision을 **그 뒤 구간의 최대 Precision**으로 바꿔 계단 모양으로 다듬고 넓이를 잰다. COCO와 Ultralytics는 Recall 0~1의 101개 점을 쓴다.
- **mAP**는 Class마다 같은 비중으로 평균한다. 데이터가 적은 Class 하나의 AP가 낮으면 mAP도 같이 내려간다.
- 직접 해 봄: 알약 val 23장(399개)에 conf 0.001로 예측 1,451개를 모아 계산한 AP50이 0.993으로 `model.val()`과 같았다.
막힌 점: AP는 IoU 기준을 하나 정해야 계산된다. 0.5로 정하면 "찾았는가"만 보고 "얼마나 정확한 자리에 쳤는가"는 보지 못한다.

### mAP50과 mAP50-95
related: det-map50-vs-5095, det-exp-n-vs-s
핵심: mAP50은 IoU 0.5에서 "찾았는가"를, mAP50-95는 IoU 0.50~0.95 열 개 기준의 평균으로 "박스를 얼마나 정확히 쳤는가"까지 본다.
- mAP50-95 = IoU 0.50, 0.55, ..., 0.95에서 구한 mAP 10개의 평균. COCO 벤치마크의 대표 지표다.
- 기준이 까다로워질수록 TP가 FP로 바뀌니, 같은 모델에서 mAP50-95가 mAP50보다 낮게 나온다.
- 알약 모델 IoU별 AP: 0.50 → 0.993, 0.75 → 0.983, 0.85 → 0.734, 0.95 → 0.031. 0.95에서는 곡선이 Recall 0.1에서 끝났다. 위치는 거의 다 맞히지만 딱 맞게 친 건 열에 하나꼴이다.
- yolo11n은 mAP50 0.854, mAP50-95 0.631, yolo11s는 0.935, 0.745였다. 차이는 IoU 0.85~0.90 구간에서 가장 벌어졌다(검증 4장짜리라 모양만 볼 것).
- 해석: **mAP50은 높고 mAP50-95가 낮으면** 객체는 찾지만 박스 위치가 부정확하다.
- 직접 계산한 mAP50-95는 0.801, `model.val()`은 0.793이었다. 매칭 순서(점수순 vs IoU 큰 짝부터)가 달라 높은 기준에서 짝이 몇 개 달라지는 것으로 보인다.
막힌 점: 무엇을 잴지는 정해졌다. 이제 COCO에 없는 객체(알약, 안전모)를 찾는 모델을 적은 데이터로 만들려면 어디서 시작해야 할까?

### 전이학습과 Fine-tuning
related: det-finetune-process, det-overfitting-hparams
핵심: COCO로 학습한 가중치에서 출발해 Head의 Class 부분만 새로 만들고 나머지는 복사한 뒤, 새 데이터로 계속 학습한다.
- **Training from Scratch**: 무작위 가중치에서 모든 Feature를 처음부터 배운다. 데이터도 시간도 많이 필요하고, 데이터가 적으면 성능이 낮고 과적합되기 쉽다.
- 전이학습이 통하는 이유: Backbone이 뽑는 경계, 질감, 형태 Feature는 처음 보는 이미지에도 그대로 쓸모가 있다.
- **Transfer Learning**(가중치를 다른 작업에 재사용하는 방법 전체) 안에 **Feature Extraction**(사전학습 층 고정, 끝만 학습)과 **Fine-tuning**(전체 또는 일부 층 갱신)이 있다. Ultralytics는 기본이 전체 학습이고 `freeze`로 고정할 층 수를 정한다.
- 내부 순서: `yolo11n.pt` 로드 → 새 Class 수에 맞게 Head의 Class 예측 부분을 새로 만듦 → 구조와 크기가 같은 부분에 사전학습 가중치 복사(`Transferred N/M items` 메시지) → 새 데이터로 학습
- 하이퍼파라미터: `epochs=100`, `batch=16`, `lr0`·`lrf`. 기본 `optimizer='auto'`는 이번 학습에서 `lr0=0.01`을 무시하고 AdamW(lr=0.002)를 골랐다.
- 과적합 신호: Train Loss는 계속 주는데 Val Loss가 늘거나 Val mAP가 멈추거나 떨어진다. 데이터 추가, Augmentation, `patience`로 조기 종료한다.
막힌 점: 시작 가중치는 준비됐다. 남은 것은 모델이 그대로 정답으로 배울 데이터다.

### 데이터셋: 형식, 분할, 라벨링 일관성
related: det-dataset-format, det-train-val-test, det-labeling-criteria
핵심: 이미지마다 같은 이름의 `.txt`에 객체당 한 줄(class_id와 정규화된 xywh)을 적고, Train/Val/Test로 나누고, 모든 작업자가 같은 기준으로 라벨링해야 한다.
- 구성: 이미지 파일, 라벨 파일, Class ID와 이름 대응, Train/Val/Test 분할 정보
- 라벨 한 줄 예(1920×1080 알약 사진): `0 0.177344 0.804167 0.110937 0.150926` → 픽셀로 바꾸면 xyxy `[234, 787, 447, 950]`
- 폴더: `images/`와 `labels/`의 하위 구조가 같아야 한다(이미지 경로의 `images`를 `labels`로 바꿔 라벨을 찾음). 객체 없는 이미지는 라벨을 비우면 배경 이미지로 학습된다.
- `data.yaml`: `path`, `train`/`val`/`test`, `names`. Class ID는 0부터 연속이고 `names` 순서가 라벨의 class_id와 맞아야 한다.
- **분할**: Train은 학습, Val은 에폭마다 평가하고 `best.pt`와 하이퍼파라미터를 고름, Test는 마지막에 한 번. 보통 7:2:1이나 8:1:1. Val도 선택에 썼으니 실제보다 조금 높게 나올 수 있다.
- **라벨링 기준**: 가려진 객체, 잘린 객체, 최소 크기를 어떻게 할지 미리 정하고 모두가 같게 지킨다. 누락된 객체는 배경으로 학습되어 Recall이 내려가고, 들쭉날쭉한 경계는 mAP50-95를 떨어뜨린다. CVAT에서 YOLO 형식으로 내보낼 때 Class 순서를 확인하고, 모델이 구분해야 할 것은 Attribute가 아니라 Label로 정의한다.
막힌 점: 데이터와 시작 가중치가 준비됐다. 실제로 학습해서 앞에서 배운 지표로 결과를 읽어 볼 차례다.

### 내 데이터로 학습하고 결과 읽기
related: det-loss, det-exp-pretrain-scratch-freeze, det-best-vs-last, det-exp-coco-vs-finetuned, det-exp-manual-ap, det-exp-confusion-matrix
핵심: 알약 92장으로 학습해 보니 사전학습 가중치가 결정적이었고, 결과는 mAP 두 개, best.pt 선택 기준, Confusion Matrix로 읽는다.
- Loss: **box_loss**(CIoU, 위치 차이), **cls_loss**(BCE, Class 오차), **dfl_loss**(박스 경계 위치 분포). Train Loss와 Val Loss를 함께 본다.
- 같은 설정(30 에폭, batch 16, imgsz 640)에 시작 가중치만 바꾼 결과:

| 시작 | mAP50 | mAP50-95 |
|---|---|---|
| pretrained | 0.993 | 0.792 |
| freeze10 (Backbone 고정) | 0.994 | 0.780 |
| scratch | 0.954 | 0.535 |

- pretrained는 첫 에폭부터 mAP50-95 0.38, scratch는 15 에폭까지 0이었다. 첫 에폭 Val box_loss도 1.16 대 5.8. scratch는 "찾지만 위치가 부정확한" 모양 그대로다.
- `best.pt`는 fitness `0.1 × mAP50 + 0.9 × mAP50-95`가 가장 높은 에폭(29 에폭, 0.813), `last.pt`는 마지막 에폭(30 에폭, 0.812)이다. 추론과 배포는 best, 이어서 학습은 last.
- COCO 모델은 알약을 `cup`(0.38, 0.27)이라 불렀고, Fine-tuning 모델은 `{0: 'pill'}`만 아는 모델이 되어 17개를 찾았다. 대신 사람이나 버스는 더 이상 못 찾는다.
- Confusion Matrix(conf 0.25, IoU 0.5): 399개 중 TP 396, FN 3(background 행), FP 17(background 열) → Precision 0.959, Recall 0.992. 반쯤 가려진 알약의 0.32, 0.56 박스는 라벨 기준에 따라 TP도 FP도 될 수 있다.
막힌 점: 박스는 객체를 직사각형으로만 감싼다. 객체의 실제 윤곽(픽셀 마스크)이나 사람의 관절 위치가 필요하면, 같은 Backbone과 Neck 위에 다른 Head를 얹는 Segmentation·Pose 주제로 이어진다.

## 한 장 요약

### 한 문장 흐름
분류(무엇만) → 박스 + Class + 점수(무엇이 어디에) → 두 단계에서 한 번에(YOLO) → 7×7 격자 → Anchor → 여러 Feature Map(Backbone·Neck·Head) → YOLO11 후보 8,400개 → Confidence Threshold → NMS로 중복 제거 → IoU로 겹침 측정 → TP/FP/FN 판정 → Precision·Recall → PR Curve·AP·mAP → mAP50과 mAP50-95 → 사전학습에서 Fine-tuning → 일관된 라벨의 데이터셋 → 내 데이터로 학습하고 결과 읽기

### 공식과 핵심 숫자
| 무엇 | 식 / 값 | 예 |
|---|---|---|
| IoU | 겹친 면적 / (면적1 + 면적2 − 겹친 면적) | 큰 박스 안의 작은 박스 → 0.111 |
| Precision | TP / (TP + FP) | 2 / 6 = 0.33 |
| Recall | TP / (TP + FN) | 2 / 3 = 0.67 |
| AP | PR Curve 아래 면적 (계단 보간, 101점) | 알약 AP50 0.993 |
| mAP | Class별 AP의 평균 | |
| mAP50-95 | IoU 0.50~0.95(0.05 간격) mAP 10개 평균 | 알약 0.792 |
| fitness | 0.1 × mAP50 + 0.9 × mAP50-95 | 29 에폭 0.813 |
| YOLO11 위치 수 | (640/8)² + (640/16)² + (640/32)² | 6,400 + 1,600 + 400 = 8,400 |
| YOLO11 출력 | `(1, 4 + Class 수, 8400)` | COCO → `(1, 84, 8400)` |
| YOLOv1 최대 박스 | 7 × 7 × 2 | 98 |
| Ultralytics 기본값 | `conf=0.25`, `iou=0.7` | |
| IoU 0.5 아래로 떨어지는 이동 | 변 길이의 약 18% | 200px → 37px, 20px → 4px |

### 헷갈리는 용어
| 용어 | 뜻 |
|---|---|
| Confidence Threshold | 결과에 남길 최소 점수. Precision과 Recall을 맞바꾼다 |
| NMS의 IoU Threshold | 두 박스를 "같은 객체의 중복"으로 볼 겹침 기준 (기본 0.7) |
| 평가의 IoU Threshold | 예측을 TP로 인정할 겹침 기준 (mAP50이면 0.5) |
| xyxy / xywh | 꼭짓점 두 개 / 중심과 크기. 뒤에 n이 붙으면 0~1 정규화 |
| Transfer Learning | 다른 작업의 가중치를 재사용하는 방법 전체 |
| Feature Extraction / Fine-tuning | 사전학습 층 고정 / 일부 또는 전체 층 갱신 |
| AP / mAP | 한 Class의 PR Curve 면적 / 모든 Class의 AP 평균 |
| 로그의 P, R / mAP | Threshold 하나에서 잰 값 / 모든 Threshold를 합친 값 |
| best.pt / last.pt | fitness 최고 에폭(배포용) / 마지막 에폭(이어 학습용) |
| Label / Attribute (CVAT) | 객체의 Class / 같은 Class 안의 추가 속성. YOLO 형식은 Label만 저장 |

### 모델 흐름
| 모델 | 연도 | 한 줄 |
|---|---|---|
| R-CNN 계열 | 2014~2015 | 후보 영역 → 후보별 분류 (Faster R-CNN은 RPN으로 후보 생성) |
| YOLOv1 | 2016 | 7×7 격자, 칸마다 박스 2개, 한 번의 forward |
| YOLOv2 | 2017 | Anchor Box 도입 |
| YOLO11 | 2024 | stride 8·16·32 세 Feature Map, anchor-free, 8,400개 위치 |

## 이해 확인

### Q. 분류 모델은 버스 사진에 minibus라고만 답했습니다. 사람이 네 명 찍혀 있는데도 사람 정보가 없는 이유는 무엇이고, 탐지는 출력이 어떻게 달라야 하나요?
id: detc-why-not-classification
type: 개념
level: 기본
related: det-task-comparison

#### 풀이
분류 모델의 출력은 **이미지 전체에 대한 Class 점수 한 묶음**이기 때문입니다. 1,000개 Class 중 사진 전체를 가장 잘 설명하는 이름 하나를 고르는 구조라서, 무엇이 몇 개 어디에 있는지 적을 자리가 처음부터 없습니다.
- 분류 출력은 개수가 **항상 1개**로 고정이다. 사람이 0명이든 4명이든 출력 모양이 같다.
- 탐지는 출력 개수가 **0개 이상으로 가변**이어야 하고, 결과마다 **위치(박스 값 4개)**, Class, 점수가 함께 붙어야 한다.
- 개수가 정해지지 않은 출력을 내려고, 탐지 모델은 후보를 넉넉히(YOLO11은 8,400개) 낸 뒤 Threshold와 NMS로 걸러 내는 구조를 쓴다.

### Q. 1920×1080 알약 사진의 YOLO 라벨 한 줄이 `0 0.177344 0.804167 0.110937 0.150926`입니다. 이 박스를 픽셀 단위 xyxy로 바꿔 보세요.
id: detc-label-to-pixel
type: 계산
level: 기본
related: det-box-format, det-dataset-format

#### 풀이
값 순서는 class_id, x_center, y_center, width, height이고, x 방향은 너비 1920, y 방향은 높이 1080을 곱합니다.
- x_center = 0.177344 × 1920 ≈ **340.5**, y_center = 0.804167 × 1080 ≈ **868.5**
- w = 0.110937 × 1920 ≈ **213**, h = 0.150926 × 1080 ≈ **163**
- x1 = 340.5 − 106.5 = 234, x2 = 340.5 + 106.5 = 447
- y1 = 868.5 − 81.5 = 787, y2 = 868.5 + 81.5 = 950
- 결과: **`[234, 787, 447, 950]`**
- 흔한 실수: y에도 1920을 곱하면 0.804 × 1920 ≈ 1,544로 이미지 높이 1080을 넘는다. 이미지 밖 좌표가 나오면 W와 H를 바꿔 쓴 것부터 의심한다.

### Q. "Confidence Score가 0.9인 박스는 90% 확률로 맞는 박스다."
id: detc-ox-confidence-probability
type: OX
level: 기본
related: det-output-confidence

#### 풀이
**X.** Confidence Score는 모델이 스스로 매긴 **추정값**이고, 맞았는지는 평가 단계에서 GT와 Class, IoU를 비교해 따로 판정합니다.
- 같은 사진의 같은 사람에게 yolo11n은 0.62, yolo11s는 0.66을 줬다. 점수의 크기는 모델과 가중치마다 다르다.
- 점수 0.9인 박스들을 모았을 때 실제로 90%가 맞는지(보정, calibration)는 모델이 보장하지 않는다.

### Q. One-stage 탐지기가 Two-stage보다 빠른 이유는 무엇이고, 대신 어떤 부담을 떠안나요?
id: detc-one-stage-tradeoff
type: 개념
level: 기본
related: det-two-vs-one-stage, det-rcnn-rpn, det-class-imbalance

#### 풀이
후보 영역을 따로 만들고 후보마다 다시 분류·보정하는 단계 없이, **이미지를 한 번 통과시킨 출력이 곧 검출 후보**이기 때문입니다.
- Two-stage는 후보 생성과 후보별 분류라는 두 단계를 거친다. Faster R-CNN은 후보 생성도 RPN이라는 신경망이 맡지만, 여전히 후보마다 두 번째 단계가 돈다.
- One-stage의 부담은 **모든 격자 위치가 예측을 낸다**는 데서 온다. YOLO11의 8,400개 위치 중 bus.jpg에서 실제 객체로 남은 것은 5개뿐이다.
- 학습할 때는 배경 위치가 압도적으로 많아 객체 쪽 신호가 묻히기 쉽다(전경과 배경의 불균형). RetinaNet의 Focal Loss가 이 문제를 겨냥한 방법이다.
- 추론할 때는 많은 후보를 Confidence Threshold와 NMS로 걸러 내는 후처리가 필요하다.

### Q. YOLOv1의 격자를 7×7에서 14×14로 늘리면 어떤 한계가 줄고, 어떤 한계는 그대로 남을까요?
id: detc-v1-finer-grid
type: 만약에
level: 심화
related: det-yolov1-grid, det-multiscale-feature

#### 풀이
- **줄어드는 것**: 칸이 196개라 최대 박스가 392개로 는다. 칸이 작아지니 가까이 붙은 두 객체의 중심이 같은 칸에 들어갈 가능성이 줄어, 붙은 객체를 덜 놓친다.
- **그대로인 것**: 칸 하나가 Class 하나만 고르는 구조는 같다. 더 작고 더 촘촘한 객체가 한 칸에 몰리면 같은 문제가 다시 생긴다. 박스 비율을 기준 없이 맞혀야 하는 문제도 그대로다.
- **새로 생기는 것**: 객체를 맡지 않는 빈 칸이 훨씬 많아진다.

격자 크기를 하나로 정하면 작은 객체와 큰 객체에 동시에 맞추기 어렵습니다. 그래서 이후 모델은 비율 문제를 Anchor로, 크기 문제를 촘촘한 격자(80×80)와 성긴 격자(20×20)를 함께 쓰는 여러 Feature Map으로 풀었습니다.

### Q. Anchor Box를 두면 왜 박스 예측이 쉬워지고, 그런데도 YOLO11은 왜 Anchor 없이 가나요?
id: detc-anchor-why
type: 개념
level: 심화
related: det-anchor-box, det-anchor-free

#### 풀이
박스를 아무것도 없는 데서 맞히는 대신, **모양이 비슷한 기준 박스에서 조금 고친 값**만 예측하면 되기 때문입니다.
- 버스에는 2:1 Anchor가 IoU 0.80, 사람에는 1:3 Anchor가 0.81로 이미 정답에 가까웠다. 비율이 틀린 Anchor는 0.2~0.3대였다. 좋은 출발점에서 시작하니 고칠 양이 작다.
- 대가: Anchor 크기와 비율을 데이터셋마다 골라야 하고(하이퍼파라미터), 위치마다 여러 개라 후보가 늘고, 어떤 Anchor가 어떤 GT를 맡을지 정하는 규칙이 학습을 복잡하게 만든다. 내 데이터의 객체 모양이 Anchor와 다르면 오히려 불리하다.
- YOLO11은 격자점에서 네 변까지의 거리 `(l, t, r, b)`를 바로 예측한다. 크기 분담은 여러 Feature Map이 맡고, 거리를 예측하니 비율을 미리 가정할 필요가 없다. "기준 박스"가 "기준 점"으로 바뀐 셈이다.

### Q. Backbone의 Feature Map을 바로 Head에 넣지 않고 Neck에서 섞는 이유는 무엇인가요?
id: detc-neck-why-mix
type: 개념
level: 심화
related: det-fpn-pan, det-backbone-neck-head

#### 풀이
Backbone의 얕은 층과 깊은 층이 **서로 반대의 약점**을 갖기 때문입니다.
- 얕은 층(stride 8): 해상도가 높아 위치는 정확하지만, 본 범위가 좁고 층을 덜 거쳐 "이게 무엇인지"는 약하다.
- 깊은 층(stride 32): 객체 단위의 의미는 강하지만 해상도가 낮아 위치가 거칠다.
- 작은 객체는 stride 8 map이 맡는데, Backbone 그대로라면 의미가 약한 map으로 Class를 정해야 한다. **FPN(top-down)**이 깊은 층을 키워 내려보내 의미를 보태 준다.
- **PAN(bottom-up)**은 합친 결과를 다시 줄여 올려보내, 큰 객체를 맡는 깊은 map에도 정확한 위치 정보를 준다.
- 그래서 Neck을 지난 세 map은 모두 위치와 의미를 함께 갖는다.

### Q. bus.jpg에서 버스와 크게 찍힌 사람은 전부 stride 32 map에서 나왔고 stride 8에는 후보가 없었습니다. CNN에서 배운 receptive field로 설명해 보세요.
id: detc-big-object-stride32
type: 연결
level: 기본
related: det-multiscale-feature, cnn-receptive-field, cnn-feature-hierarchy

#### 풀이
stride 32 map의 한 칸은 Conv와 다운샘플링을 여러 번 거친 뒤라 **입력에서 보는 영역(receptive field)이 넓어서**, 버스나 크게 찍힌 사람 전체를 한 번에 볼 수 있기 때문입니다.
- 한 칸이 객체의 일부만 본다면 전체 박스의 네 변을 판단하기 어렵다. 그래서 큰 객체는 주로 해상도가 낮은 map이 맡게 된다.
- 반대로 작은 객체에는 stride 32가 불리하다. 한 칸이 32×32 픽셀이라 20px짜리 물체는 한 칸보다 작고, 여러 번 줄이는 동안 세부가 뭉개진다. CNN 주제에서 본 "Pooling과 stride는 정확한 위치를 잃는다"가 탐지에서 문제가 되는 지점이다.
- CNN 분류는 마지막 map 하나로 충분했지만, 탐지는 크기가 제각각인 객체를 위해 깊이가 다른 map 여러 개를 함께 쓴다.

### Q. YOLO11에 640 대신 1280×1280 입력을 쓰면 예측 위치는 몇 개가 되고, 무엇이 좋아지고 무엇을 치르나요?
id: detc-imgsz-1280
type: 만약에
level: 기본
related: det-yolo11-8400, det-small-object

#### 풀이
stride는 8, 16, 32 그대로라 격자가 160×160, 80×80, 40×40이 되어 25,600 + 6,400 + 1,600 = **33,600개**, 640일 때의 4배입니다.
- **좋아지는 것**: 같은 객체가 두 배 큰 픽셀 크기로 들어간다. 작은 객체가 stride 8 map에서 더 여러 칸에 걸치고 세부가 덜 뭉개져 찾기 쉬워진다.
- **치르는 것**: 위치 수와 계산량, 메모리가 대략 4배로 늘어 느려진다. 640으로 학습한 모델이라면 객체가 학습 때보다 크게 보여 분포가 달라질 수도 있다.
- 항공 사진이나 작은 결함처럼 작은 객체가 중요한 일에서 고려할 만한 선택이다.

### Q. Confidence Threshold만 적용하면 같은 사람에게 박스가 겹겹이 남습니다. 왜 Threshold로는 이 중복을 못 지우고, NMS는 어떻게 지우나요?
id: detc-why-nms-needed
type: 개념
level: 기본
related: det-nms, det-conf-threshold

#### 풀이
Threshold는 박스 **하나하나를 따로** 보고 점수만 판단하는데, 중복 박스는 모두 진짜 객체를 보고 낸 것이라 점수가 다 높기 때문입니다. 가운데 남자 주변 후보 9개는 0.72~0.83이었습니다.
- 원인: 같은 객체 주변의 여러 격자 위치가 각자 그 객체를 보고 비슷한 박스를 낸다.
- 필요한 것은 박스 **사이의 관계**, 즉 "이 둘이 같은 객체를 가리키는가"를 보는 판단이다. NMS는 이걸 IoU로 본다.
- 점수 순으로 가장 높은 박스를 고르고, 그것과 IoU가 기준(0.7)보다 큰 박스를 지우고, 반복한다.
- 0.83을 고르자 나머지 8개와 IoU가 0.95~0.99라 한 번에 지워졌다. 사진 전체로는 47개가 5개가 됐다.

### Q. zidane.jpg에서 NMS IoU Threshold를 0.7에서 0.1로 낮췄더니 사람 수는 그대로 2명인데 결과는 나빠졌습니다. 무슨 일이 일어났나요?
id: detc-nms-iou-too-low
type: 만약에
level: 심화
related: det-nms-iou-threshold, det-nms

#### 풀이
두 사람 박스의 IoU는 0.333입니다. 기준이 0.1이면 "조금만 겹쳐도 같은 객체"로 보므로, 점수가 더 높은 안첼로티 박스(0.84)가 먼저 선택되고 그것과 0.333 겹치는 **지단의 0.78 박스가 중복으로 지워졌습니다**.
- 지단 쪽은 안첼로티 쪽으로 덜 뻗은 0.34짜리 다른 후보가 우연히 살아남아 2명이 됐다.
- 개수는 같아도 지단의 박스는 가장 좋은 박스에서 더 나쁜 박스로 바뀌었다. 개수만 보면 놓치는 실패다.
- 그 후보마저 겹쳤다면 지단은 아예 사라졌을 것이다. 기준을 너무 낮추면 가까이 선 **다른 객체**가 지워진다.
- 반대로 너무 높이면 같은 객체의 중복이 남는다.

### Q. 사람이 빽빽하게 겹쳐 선 군중 사진에서는 NMS의 IoU Threshold를 어떻게 잡아도 문제가 남습니다. 왜 그렇고, 어떤 방향으로 풀 수 있을까요?
id: detc-crowd-nms
type: 생각해보기
level: 심화
related: det-nms-iou-threshold, det-nms-alternatives

#### 풀이
NMS는 "많이 겹치면 같은 객체"라는 가정 하나로 판단하는데, 군중에서는 **서로 다른 사람의 박스가 많이 겹치는 일**이 흔해서 그 가정이 깨집니다.
- 기준을 낮추면: 뒤에 선 사람 박스가 앞사람 박스에 지워진다 → FN이 늘어 Recall이 떨어진다.
- 기준을 높이면: 진짜 중복도 살아남는다 → FP가 늘어 Precision이 떨어진다.
- 즉 IoU 숫자 하나로는 "같은 객체의 중복"과 "겹쳐 선 다른 객체"를 구분할 수 없다.

풀어 볼 방향은 여러 가지입니다.
1. **Soft-NMS**: 겹친 박스를 지우는 대신 점수를 깎는다. 많이 겹쳐도 점수가 충분히 높으면 살아남는다.
2. **NMS를 없애는 구조**: DETR처럼 처음부터 객체 하나에 예측 하나가 대응하도록 학습하면 중복 제거 단계가 필요 없다.
3. **데이터 쪽**: 겹친 사람을 일관되게 라벨링해 모델이 그런 장면을 충분히 보게 한다.

Ultralytics가 같은 Class끼리만 NMS를 하는 것도 같은 고민에서 나온 선택입니다. 사람과 자전거는 많이 겹쳐도 서로 지우지 않습니다.

### Q. 두 쌍의 박스(xyxy)에 대해 IoU를 구해 보세요.
id: detc-iou-calc
type: 계산
level: 기본
related: det-iou

```
(1) A = [0, 0, 100, 100],   B = [50, 50, 150, 150]
(2) A = [0, 0, 300, 300],   B = [100, 100, 200, 200]
```

#### 풀이
1. 교집합은 x 50~100, y 50~100이라 50 × 50 = **2,500**. 합집합은 10,000 + 10,000 − 2,500 = **17,500**. IoU = 2,500 / 17,500 ≈ **0.143**. 가로세로로 반 칸씩만 어긋났는데 0.5에 한참 못 미친다.
2. B가 A 안에 완전히 들어 있어 교집합은 B 전체 10,000. 합집합은 90,000 + 10,000 − 10,000 = 90,000. IoU = 10,000 / 90,000 ≈ **0.111**. 블로그의 포함 예시도 0.111이었다.
- IoU가 높으려면 **위치와 크기를 둘 다** 맞혀야 한다. 객체를 다 감싸도 박스가 너무 크면 낮게 나온다.

### Q. 정답과 크기가 같은 예측 박스를 가로·세로로 똑같이 d픽셀씩 밀었습니다. 20×20 박스에서 IoU가 처음으로 0.5 아래로 떨어지는 정수 d는 얼마이고, 200×200 박스라면 어떤가요?
id: detc-iou-shift-small
type: 계산
level: 심화
related: det-iou, det-small-object

#### 풀이
변 길이가 s인 박스를 d만큼 밀면 교집합은 (s − d)², 합집합은 2s² − (s − d)²입니다.
- 20×20, d = 3: 교집합 17² = 289, 합집합 800 − 289 = 511 → IoU ≈ 0.566
- 20×20, d = 4: 교집합 16² = 256, 합집합 800 − 256 = 544 → IoU ≈ 0.471 → **4px**
- 일반식: IoU < 0.5 ⇔ (s − d)² < 2s²/3 ⇔ d > s(1 − √(2/3)) ≈ **0.18s**. 변 길이의 약 18%만 밀려도 기준 아래다.
- 200×200이면 d > 36.7이라 **37px**. 블로그 측정값(200 → 37, 100 → 19, 50 → 10, 20 → 4px)과 같다.

비율로는 같지만 픽셀로는 열 배 차이입니다. 라벨러의 손떨림이나 모델의 몇 픽셀 오차가 작은 객체에서는 곧바로 FP와 FN이 되는 이유입니다.

### Q. 같은 dog를 거의 똑같이 잡은 예측 P1, P2 중 점수가 낮은 P2는 왜 FP인가요? 그리고 탐지 평가에 TN이 없는 이유는 무엇인가요?
id: detc-duplicate-is-fp
type: 개념
level: 기본
related: det-tp-fp-fn, det-matching

#### 풀이
GT 하나에는 TP가 **최대 하나만** 매칭되기 때문입니다. 점수 순으로 처리하니 P1이 먼저 GT1과 짝지어졌고, P2가 왔을 때 GT1은 이미 짝이 있어서 P2는 FP가 됩니다.
- 이 규칙이 없으면 같은 객체에 박스를 열 개 쳐서 TP 열 개를 받을 수 있다. 중복을 FP로 세야 NMS가 덜 된 모델이 Precision에서 손해를 본다.
- **TN**은 "객체가 없는 곳에 박스를 치지 않은 경우"인데, 박스를 칠 수 있는 위치와 크기의 조합은 사실상 무한해서 셀 수 없다. 그래서 TN이 들어가지 않는 Precision과 Recall로 평가한다.

### Q. Confidence Threshold를 올리면 Precision과 Recall이 왜 반대로 움직이고, 그 때문에 어떤 문제가 생기나요?
id: detc-pr-tradeoff
type: 개념
level: 기본
related: det-precision-recall, det-conf-threshold

#### 풀이
Threshold를 올리면 점수 낮은 예측이 빠집니다. 빠지는 것 중에는 FP가 많아 **Precision은 오르지만**, 함께 빠진 TP는 그 GT를 FN으로 바꿔 **Recall은 내려갑니다**.
- bus.jpg: 0.80에서는 몸이 잘린 사람(0.62)이 빠져 놓친 객체가 늘고, 0.10에서는 신발을 `skateboard 0.12`로 잡아 잘못된 검출이 늘었다.
- 알약 모델은 0.25~0.6에서 둘 다 0.95 이상이었지만 0.8을 넘기면 Recall이 무너졌다.
- 문제: Threshold 하나에서 잰 P, R은 모델의 한 단면일 뿐이고, 모델마다 점수 크기가 달라 같은 Threshold에서 비교해도 공정하지 않다. 그래서 모든 Threshold를 합친 PR Curve와 AP가 필요하다.

### Q. AP를 구할 때 예측을 점수순으로 정렬해 누적하는 이유와, 지그재그 곡선을 계단 모양으로 다듬는 이유는 무엇인가요? mAP는 Class별로 어떤 성질이 있나요?
id: detc-ap-mechanics
type: 개념
level: 심화
related: det-pr-curve-ap, det-map

#### 풀이
- **점수순 누적**: 위에서 k개까지 포함한다는 건 k번째 점수를 Threshold로 둔 것과 같다. 정렬 한 번으로 모든 Threshold의 (Recall, Precision)을 얻는 방법이다.
- **지그재그**: TP가 오면 Recall이 오르고 Precision도 오르거나 유지되며, FP가 오면 Recall은 그대로인 채 Precision만 내려간다. 그래서 톱니 모양이 생긴다.
- **계단 보간**: 각 Recall의 Precision을 그 뒤 구간의 최대값으로 바꾸면 "이 Recall 이상을 얻으면서 가질 수 있는 최선의 Precision"이 되어 곡선이 오른쪽으로 갈수록 내려가는 계단이 된다. COCO와 Ultralytics는 Recall 101개 점에서 이 값을 읽어 넓이를 잰다.
- **mAP**: Class마다 같은 비중으로 평균한다. 객체가 많은 Class가 숫자를 지배하지 않는 대신, 데이터가 적은 Class 하나의 AP가 낮으면 mAP가 그만큼 내려간다.
- 블로그에서는 이 과정을 직접 구현해 AP50 0.993으로 `model.val()`과 같은 값을 얻었다.

### Q. "mAP50-95가 낮은 모델은 객체를 잘 못 찾는 모델이다."
id: detc-ox-low-5095
type: OX
level: 기본
related: det-map50-vs-5095, det-exp-pretrain-scratch-freeze

#### 풀이
**X.** mAP50-95는 찾았는지와 **박스 위치의 정확도**를 함께 반영합니다. mAP50이 높고 mAP50-95만 낮다면 찾긴 하는데 박스가 어긋난 것입니다.
- 처음부터 학습한 알약 모델이 딱 이 경우였다. mAP50 0.954, mAP50-95 0.535
- 찾는지 자체는 mAP50(또는 Recall)으로 본다. 둘 다 낮아야 검출 자체가 부족하다는 뜻이다.

### Q. yolo11n과 yolo11s를 IoU 기준별로 비교했더니 차이가 0.85~0.90 구간에서 가장 컸습니다. 이 결과가 말해 주는 것은 무엇이고, 어떤 상황에서 s를 고를까요?
id: detc-n-vs-s-gap
type: 생각해보기
level: 심화
related: det-exp-n-vs-s, det-model-size

#### 풀이
n은 mAP50 0.854, mAP50-95 0.631, s는 0.935, 0.745였습니다. s가 모든 구간에서 위에 있지만 기준이 엄격해질수록 차이가 벌어졌으니, 큰 모델의 이득이 "찾느냐"보다 **"얼마나 정확한 자리에 박스를 치느냐"**에서 더 크다는 뜻입니다.

고를 때는 일에 필요한 것부터 생각해 봅니다.
- 개수를 세거나 "있다/없다"만 알리면 되는 일은 n으로도 충분할 수 있다.
- 박스로 크기를 재거나, 박스를 잘라 다음 모델(분류, 포즈)에 넘기는 일은 위치 정확도가 결과를 좌우하니 s 이상이 낫다.
- 비용도 함께 본다. 파라미터는 262만 대 946만으로 3.6배이고, CPU나 임베디드 장비에서는 속도가 먼저 문제가 된다.
- 이 숫자는 검증 4장짜리 연습 데이터에서 나왔다. 실제 결정은 내 데이터의 Test mAP로 한다.

### Q. 사전학습 가중치에서 시작한 알약 모델은 첫 에폭부터 mAP50-95가 0.38이었는데, 처음부터 학습한 모델은 15에폭까지 0이었습니다. 왜 이렇게 차이가 나나요?
id: detc-pretrained-head-start
type: 개념
level: 기본
related: det-finetune-process, det-exp-pretrain-scratch-freeze

#### 풀이
사전학습 모델은 Backbone, Neck, 박스 예측 부분이 이미 쓸 만한 상태라 **새로 배울 것이 적기** 때문입니다.
- Fine-tuning을 시작하면 Head의 Class 부분만 새 Class 수(80 → 1)에 맞게 새로 만들고, 구조와 크기가 같은 나머지에는 COCO 가중치를 복사한다. 박스 branch는 Class 수와 상관없는 모양이라 그대로 넘어온다.
- COCO에서 배운 경계, 질감, 형태 Feature가 알약에도 통한다. 그래서 첫 에폭 Val box_loss가 pretrained 1.16, scratch 5.8로 출발점부터 달랐다.
- scratch는 무작위 필터에서 경계부터 다시 배워야 하는데, 92장은 그러기에 턱없이 부족하다. 30 에폭 끝에도 mAP50-95가 0.535였다.
- Backbone을 고정한 freeze10도 0.780으로 거의 따라왔다. Backbone을 바꾸지 않아도 될 만큼 COCO Feature가 잘 통했다는 뜻이다.

### Q. ResNet 분류에서 한 전이학습(fc 교체, 백본 고정)과 YOLO 탐지의 Fine-tuning은 무엇이 같고 무엇이 다른가요?
id: detc-resnet-vs-yolo-transfer
type: 연결
level: 심화
related: det-finetune-process, resnet-transfer-learning, resnet-freeze-backbone

#### 풀이
- **같은 점**: 앞쪽(백본)의 일반적인 시각 Feature를 재사용하고, **Class 수에 묶인 부분만 새로 만든다**. ResNet은 fc를 `nn.Linear(512, 2)`로 바꾸고, YOLO는 Head의 Class branch를 새 Class 수로 바꾼다. 백본을 고정하는 선택지(`requires_grad=False` / `freeze=10`)도 같은 생각이다. Class를 바꾸면 원래 Class(ImageNet 1,000개 / COCO 80개)를 더 못 낸다는 점도 같다.
- **다른 점**:
  - 탐지 Head에는 Class 말고 **박스 branch**가 있다. 이 부분은 Class 수와 무관해서 사전학습 가중치를 그대로 물려받고, 위치를 잡는 능력도 함께 넘어온다.
  - ResNet 예에서 fc만 학습하면 학습할 값이 1,026개뿐이지만, YOLO의 freeze10은 Backbone만 고정하고 Neck과 Head는 계속 학습한다. Ultralytics 기본은 아예 전체 층 학습이다.

### Q. 알약 데이터의 라벨러 절반은 다른 포장에 반쯤 가려진 알약에도 박스를 그리고, 나머지 절반은 그리지 않았다면 어떻게 될까요?
id: detc-inconsistent-labels
type: 만약에
level: 심화
related: det-labeling-criteria, det-exp-confusion-matrix

#### 풀이
- **학습**: 비슷하게 생긴 "가려진 알약"이 어떤 사진에서는 알약, 다른 사진에서는 배경으로 학습된다. 모델이 서로 반대인 신호를 받아 이런 객체에 애매한 점수(실험에서 본 0.32, 0.56 같은)를 내고, 라벨이 빠진 쪽은 배경으로 배우니 Recall이 내려간다.
- **평가**: val 라벨도 섞여 있으면, 모델이 가려진 알약을 잘 찾아도 라벨이 없는 사진에서는 **FP**, 못 찾으면 라벨이 있는 사진에서는 **FN**이 된다. 숫자가 모델 실력이 아니라 어느 라벨러가 맡았는지에 따라 흔들린다.

그래서 라벨링 전에 "가려진 객체는 보이는 부분만 그린다 / 전체를 추정해 그린다 / 그리지 않는다" 같은 기준을 정하고 모두가 같게 지켜야 합니다. 어느 쪽이든 일관되기만 하면 모델은 그 규칙을 배웁니다.

### Q. "Validation 데이터에서 가장 좋은 에폭을 골라 저장한 best.pt의 Validation mAP가 곧 이 모델의 최종 성능이다."
id: detc-ox-val-is-final
type: OX
level: 기본
related: det-train-val-test, det-best-vs-last

#### 풀이
**X.** Validation은 best 에폭을 고르고 하이퍼파라미터를 정하는 데 이미 쓰였으니, 그 위에서 잰 성능은 실제보다 조금 높게 나올 수 있습니다. 여러 에폭 중 최고를 고르는 것 자체가 Val에서 운 좋게 잘 나온 쪽을 고르는 효과도 있습니다.
- 최종 성능은 학습과 선택에 한 번도 쓰지 않은 Test로 잰다: `model.val(data="data.yaml", split="test")`
- Val mAP와 Test mAP의 차이가 크면 Val에 맞춰진 모델일 수 있다.

### Q. best.pt를 고르는 fitness는 0.1 × mAP50 + 0.9 × mAP50-95입니다. mAP50-95에 9배 비중을 두는 이유를 알약 실험 결과로 생각해 보세요.
id: detc-fitness-weight
type: 생각해보기
level: 심화
related: det-best-vs-last, det-map50-vs-5095

#### 풀이
알약 학습에서 mAP50은 10 에폭에 0.975를 넘긴 뒤 거의 변하지 않았고, mAP50-95는 끝까지 조금씩 올랐습니다. **찾는 건 금방 배우고, 정확한 자리에 박스를 치는 건 오래 걸린다**는 뜻입니다.
- mAP50 위주로 고르면 10~30 에폭이 거의 동점이라 사실상 아무 에폭이나 고르는 셈이다. 박스가 덜 다듬어진 초반 에폭이 뽑힐 수도 있다.
- mAP50-95는 끝까지 에폭 사이의 차이를 보여 주니, 에폭을 가르는 기준으로 쓸모가 있다.
- mAP50에 0.1을 남긴 것은 "찾기"도 완전히 무시하지 않으려는 장치로 볼 수 있다.
- 실제로 29 에폭(0.813)이 best, 30 에폭(0.812)은 last로 남았다. 마지막 에폭 값으로 확인하면 0.1 × 0.993 + 0.9 × 0.792 ≈ 0.812다.

생각해 볼 점: 개수 세기처럼 위치 정확도가 덜 중요한 일이라면, 이 기준이 내 목적과 꼭 맞지 않을 수도 있습니다.

### Q. 알약 모델의 Confusion Matrix는 TP 396, FN 3, FP 17이었습니다. Confidence Threshold를 올리는 것이 바로 정답일까요?
id: detc-fp-heavy-what-next
type: 생각해보기
level: 심화
related: det-exp-confusion-matrix, det-conf-threshold, det-labeling-criteria

#### 풀이
Precision은 396 / 413 ≈ 0.959, Recall은 396 / 399 ≈ 0.992입니다. FP가 FN보다 훨씬 많으니 **잘못된 검출 쪽부터 보는 것**은 맞지만, Threshold부터 올리는 건 순서가 아닐 수 있습니다.
- **Threshold를 올리면**: 점수 낮은 FP는 빠지지만 점수 낮은 TP도 함께 빠져 FN이 는다. 이 모델은 0.25~0.6에서 P, R이 둘 다 0.95 이상이라 조금 올릴 여유는 있다.
- **먼저 FP 17개가 무엇인지 본다**: 비교 그림에서 다른 포장에 반쯤 가려진 알약에 0.32, 0.56 박스가 붙어 있었다. 실제로 알약인데 라벨이 없는 것이라면 모델이 아니라 **라벨 기준** 문제이고, 라벨을 고치면 FP가 TP로 바뀐다.
- **진짜 배경 오검출이라면**: 그런 배경이 담긴 이미지를 빈 라벨(배경 이미지)로 학습 데이터에 넣어 볼 수 있다.
- **마지막으로 비용**: 알약 하나를 놓치는 것과 없는 알약을 세는 것 중 무엇이 더 나쁜지에 따라 Threshold를 정한다.

### Q. 탐지 다음 주제인 Segmentation과 Pose는 박스가 못 하는 무엇을 하고, 평가에서 IoU는 각각 무엇으로 바뀌나요?
id: detc-to-seg-pose
type: 연결
level: 기본
related: seg-three-tasks, seg-mask-iou, pose-oks, det-iou

#### 풀이
박스는 직사각형이라 객체의 **실제 윤곽**이나 **내부 구조(관절)**를 표현하지 못합니다. 두 주제가 이 빈자리를 채웁니다.
- **Segmentation**: 객체마다 픽셀 단위 마스크를 낸다. YOLO11-seg는 같은 Backbone과 Neck 위에 마스크 예측을 얹은 Head라 박스도 함께 낸다.
- **Pose**: 사람마다 관절 17개의 `(x, y, conf)`를 낸다.
- 평가: Mask IoU는 공식은 같고 넓이를 가로×세로 대신 **픽셀 개수**로 센다. Pose는 IoU 대신 **OKS**(관절 거리를 사람 크기로 정규화한 0~1 점수)로 맞음과 틀림을 가른다.
- 그 위의 틀, 즉 기준값으로 TP/FP를 정하고 점수순으로 누적해 PR Curve와 AP를 구하고 여러 기준을 평균해 mAP를 내는 흐름은 탐지와 같다.
