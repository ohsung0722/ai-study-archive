## 개념 지도

### CNN은 가까운 곳부터 본다
related: vit-vs-cnn, vit-inductive-bias
핵심: CNN은 작은 커널로 이웃 픽셀만 보며 층을 쌓아 넓혀 가고, 이 가정(귀납적 편향) 덕분에 적은 데이터로도 잘 배운다.
- 3×3 커널은 첫 층에서 바로 옆 픽셀만 본다. 먼 곳은 층을 쌓아 receptive field가 넓어진 뒤에야 한 칸 안에 들어온다.
- 구조에 박힌 가정이 두 개다. **지역성**(가까운 픽셀끼리 관련이 깊다)과 **가중치 공유**(같은 필터를 이미지 전체에 쓴다). 이런 가정을 **귀납적 편향**이라고 한다.
- 가정이 이미지에 잘 맞아서 데이터가 적어도 효율적으로 배운다. 분류, Object Detection, Segmentation 어디서나 CNN 계열 Backbone이 쓰였고 YOLO의 Backbone도 그랬다.
- 대가: "무엇과 무엇을 섞을지"가 입력과 상관없이 위치로 정해져 있다. 사진 왼쪽 끝의 귀와 오른쪽 끝의 꼬리는 여러 층을 지나야 비로소 같이 본다.
막힌 점: 멀리 떨어진 영역 사이의 관계를, 입력에 따라 필요한 곳을 골라 처음부터 직접 볼 수는 없을까? 문장에서는 Transformer의 Attention이 이미 그렇게 하고 있다.

### Attention 복습: Q로 찾고, K와 맞춰 보고, V를 섞는다
related: vit-encoder-block, vit-overview
핵심: 각 Token은 자기 Query를 다른 Token의 Key와 내적해 비중을 정하고, 그 비중대로 Value를 섞어 새 벡터를 만든다.
- **Q (Query)**: 지금 Token이 찾는 말. **K (Key)**: 비교당하는 이름표. **V (Value)**: 실제로 가져올 내용. 같은 입력 벡터에 학습되는 W_q, W_k, W_v를 각각 곱해 만든다.
- 계산 세 단계: ① Q와 각 K를 내적(벡터 길이 d의 제곱근으로 나눔) → ② Softmax로 합이 1인 비중 → ③ 비중대로 V를 가중합. 한 줄로 `softmax(QKᵀ/√d)V`
- 예: 영어 `apple`의 Q로 "나는 사과를 맛있게 먹었다"를 보면 `사과를`의 K와 가장 잘 맞아 비중 0.41을 가져가고, 결과 벡터에 `사과를`의 V가 가장 많이 섞인다.
- 음수 점수도 Softmax를 지나면 비중은 0보다 크다. 결과는 Q 자체가 아니라 V들을 섞은 새 벡터다.
- CNN과 가장 다른 점: 섞는 비중이 고정된 가중치가 아니라 **입력 문맥에 따라 매번 달라진다.**
막힌 점: 이 계산을 한 문장 안의 모든 Token끼리 하면 무엇이 나오고, 단어의 순서는 어떻게 알까?

### Self-Attention과 위치, Encoder 한 층
related: vit-encoder-block, vit-position-why
핵심: Q, K, V가 모두 같은 입력에서 나오는 것이 Self-Attention이고, 이 계산은 순서를 모르기 때문에 위치 정보를 따로 더해야 한다.
- 모든 Token이 각자 Q가 되어 모든 Token을 본다. 결과는 행 = Q, 열 = K인 N×N 표이고 행마다 합이 1이다.
- 같은 '인도'라도 주변 단어를 섞는 비중이 문장마다 달라 결과 벡터가 달라진다. 문맥이 반영되는 것이다.
- **순서 정보가 없다**: 단어 순서를 섞어도 각 단어가 섞는 값은 그대로다. "인도 사람이 인도를 걷는다"의 두 '인도'(나라, 길)를 가르려면 위치마다 다른 **위치 인코딩**을 입력에 더해야 한다.
- **Encoder 한 층** = Self-Attention + 잔차 연결 + 정규화 + 작은 MLP. 4개가 들어가면 4개가 나온다. **Multi-Head**는 계산을 여러 세트로 나눠 Head마다 다른 관계를 배우게 한다.
- Decoder는 미래 단어를 Softmax 전에 -∞로 가려 비중 0으로 만든다. 분류용 ViT는 Decoder 없이 Encoder만 쓴다.
막힌 점: Encoder는 Token의 줄을 받는다. 이미지는 2차원 픽셀 격자인데, 무엇을 Token으로 삼아야 할까?

### 아이디어: 이미지를 Patch로 잘라 단어처럼 줄 세운다
related: vit-overview, vit-patch-size
핵심: 이미지를 16×16 Patch로 잘라 Patch 하나를 Token 하나로 삼으면 Transformer가 그대로 읽을 수 있다.
- ViT-B/16은 224×224를 가로 14개 × 세로 14개, **196개** Patch로 자른다. 모델 이름 `vit-base-patch16-224`에 Patch 크기(16)와 입력 크기(224)가 들어 있다.
- 픽셀 하나를 Token으로 삼지 않는 이유: 224×224 = 50,176개 Token이면 모든 쌍을 비교하는 Attention 표가 감당할 수 없이 커진다. Patch로 묶어 Token 수를 줄인다.
- Patch를 32×32로 키우면(B/32) 7×7 = 49개다. Token이 약 1/4이 되어 Attention 계산은 197² → 50²로 약 1/15이 된다.
- 대신 Patch 한 칸이 큰 덩어리를 통째로 봐서 작은 물체나 세밀한 무늬에 불리하다.
- 직관: 사진을 타일로 잘라 왼쪽 위부터 줄 단위로 1~196번을 매겨 늘어놓은 "타일 문장"
막힌 점: Patch는 아직 16×16×3짜리 픽셀 덩어리다. Transformer가 받는 것은 길이가 정해진 벡터다.

### 펼치기와 Patch Embedding
related: vit-patch-embedding
핵심: Patch를 768개 숫자로 한 줄로 펼친 뒤, 학습되는 행렬 W를 곱해 768차원 Token 벡터로 만든다.
- **펼치기(Flatten)**: 16 × 16 × 3 = 768개 픽셀 값을 순서대로 늘어놓는다. 모양만 바꾸고 학습되는 값은 없다.
- **Patch Embedding**: 펼친 벡터에 W를 곱해(Linear Projection) 길이 768 벡터를 만든다. 196개 Patch가 모두 같은 W를 쓴다.
- **헷갈리는 숫자**: 펼친 길이 768(= 16×16×3)과 Hidden size 768은 다른 설정이다. B/16에서 우연히 같을 뿐이고, B/32는 펼친 길이가 3,072인데 Hidden size는 여전히 768이다.
- 전체로 보면 입력 `(B, 3, 224, 224)`가 `(B, 196, 768)`이 된다.
- 학습된 W는 16×16×3짜리 필터 768개(가중치 `(768, 3, 16, 16)`)와 같다. 주성분을 그려 보니 초록-보라 색 대비, 가로·세로 줄무늬, 점 모양이 나왔다. CNN 첫 층 필터와 꽤 닮았다.
막힌 점: Token 196개는 각자 자기 Patch만 안다. 분류에는 이미지 전체에 대한 답 하나가 필요한데, 무엇을 근거로 삼을까?

### [CLS] 토큰: 요약을 맡을 빈 자리
related: vit-cls-token, vit-cls-vs-gap
핵심: 맨 앞에 학습되는 특수 Token 하나를 붙여 197개로 만들고, 이 Token이 Encoder를 지나며 이미지 전체 정보를 모으게 한다.
- BERT의 [CLS]와 같은 아이디어다.
- 처음의 [CLS]는 이미지 내용과 상관없이 학습으로 정해진 벡터다. 어떤 사진이 들어와도 같은 값으로 시작한다.
- Encoder에서 [CLS]도 Q가 되어 196개 Patch의 V를 섞어 가져간다. 층마다 반복하며 사진마다 다른 요약 벡터가 된다.
- 손실은 [CLS] 출력에서만 나온다. 그래서 [CLS]는 "분류에 쓸모 있는 정보를 모으는" 쪽으로 학습된다.
- 대안은 Patch 출력 196개의 평균(GAP)이다. ViT 논문 부록에서 학습률을 맞추면 성능이 비슷했고, Swin Transformer는 GAP을 쓴다.
막힌 점: Self-Attention은 순서를 모른다. 지금 상태로는 196개 Patch가 원래 이미지의 어디에 있었는지 알 수 없다.

### Position Embedding: 위치를 더한다, 그리고 무엇을 배웠나
related: vit-position-why, vit-position-embedding, vit-position-interpolation
핵심: [CLS]를 포함한 197개 위치마다 768차원 위치 벡터를 더해 내용에 "어디에 있었는지"를 보태고, 학습된 위치 벡터는 스스로 2차원 격자 구조를 갖게 된다.
- 이어 붙이지 않고 **더한다**. 차원은 768 그대로다.
- 기본 ViT는 위치마다 학습되는 1차원 Position Embedding(번호 0~196)을 쓴다. 모양은 `(1, 197, 768)`
- 실험: 196개 위치 벡터끼리 코사인 유사도를 구해 위치마다 14×14 지도로 그렸더니 모든 칸에 **십자 모양**이 나왔다. 같은 행, 같은 열의 위치끼리 비슷하다.
- 아무도 "2차원 격자"라고 알려 주지 않았는데, 1차원 번호에 붙은 벡터가 학습만으로 행과 열 구조를 배웠다.
- 학습한 개수에 묶인다는 약점이 있다. 해상도를 올려 Token이 늘면(224 → 384면 196 → 576개) 위치 벡터를 2D 격자로 되돌려 보간한다.
막힌 점: 내용과 위치를 갖춘 197개 Token이 준비됐다. 이제 서로 참고하게 하고, 답을 꺼내야 한다.

### Encoder 12층을 지나 [CLS]로 분류한다
related: vit-shape-flow, vit-encoder-block
핵심: 197개 Token이 Encoder 12층을 지나며 서로 참고하고, 마지막에 [CLS] 출력 하나만 꺼내 Linear Head로 클래스별 점수를 낸다.
- Encoder는 문장용과 똑같고 입력만 단어 대신 [CLS]와 Patch다. 197개가 들어가 197개가 나온다.
- forward hook으로 찍은 shape 흐름:

| 단계 | shape |
|---|---|
| 입력 | (B, 3, 224, 224) |
| Patch Embedding | (B, 196, 768) |
| [CLS] 추가 + 위치 | (B, 197, 768) |
| Encoder 출력 | (B, 197, 768) |
| 최종 [CLS] | (B, 768) |
| Classifier | (B, num_labels) |

- ViT-B/16: Hidden 768, Encoder 12층, Head 12개(Head당 64차원), MLP 내부 3,072(4배), 전체 약 86M
- 직관: Patch 196개가 12번 회의를 하며 서로 의견을 섞고, 서기([CLS])가 회의록을 들고 나와 판정관(Head)에게 넘긴다.
막힌 점: 구조는 끝났다. 이 중 무엇을 학습해야 하고, 그걸 어떤 데이터로 학습해야 할까?

### 학습되는 부분과 대규모 사전학습
related: vit-trainable-parts, vit-pretraining-scale, vit-transfer-learning
핵심: 자르기·펼치기·[CLS] 꺼내기를 뺀 거의 모든 것이 학습되는데, 가정이 약한 ViT는 이것을 데이터에서 배워야 해서 큰 데이터로 먼저 사전학습한다.
- 학습 안 됨: ① 자르기, ② 펼치기, ⑦ [CLS]만 꺼내기. 학습됨: ③ Patch Embedding W, ④ [CLS] 벡터, ⑤ 위치 임베딩, ⑥ Encoder(W_q, W_k, W_v, MLP 등), ⑧ MLP Head
- CNN이 구조로 받는 "가까운 것끼리 본다"를 ViT는 받지 못한다. 위치 벡터의 격자 구조도, 어떤 Head가 주변을 볼지도 데이터로 배워야 한다.
- Patch 수가 늘면 Attention 계산이 제곱으로 커져 학습 비용도 크다.
- ViT 논문에서도 ImageNet-1k만으로는 비슷한 크기의 ResNet보다 조금 낮았고, 더 큰 데이터(ImageNet-21k, JFT-300M)로 사전학습해야 앞섰다.
- 그래서 순서가 정해진다: 큰 데이터로 전체 사전학습 → 분류 Head를 떼고 새 클래스 수의 Head 부착 → 작은 데이터로 파인튜닝(사전학습보다 높은 해상도로 하는 경우가 많다).
막힌 점: 사전학습을 직접 하기는 어렵다. 이미 학습된 모델을 가져와 바르게 쓰는 방법이 필요하다.

### Hugging Face: 모델과 Processor는 한 쌍
related: vit-hf-loading, vit-hf-pipeline
핵심: `from_pretrained`로 같은 Model ID의 모델과 전처리기를 함께 불러와야 모델이 학습 때 본 입력 분포가 맞는다.
- Hub 저장소의 파일: `config.json`(층 수, hidden size, 라벨 목록), `model.safetensors`(가중치), `preprocessor_config.json`(이미지 크기, 정규화 값). Git 기반이라 `revision`으로 버전을 고정할 수 있다.
- **Auto 클래스**가 이름만 보고 `ViTImageProcessor`와 `ViTForImageClassification`을 골라 준다. `model.config`는 hidden_size 768, 12층, 12 Head, patch_size 16, num_labels 1000
- **한 쌍인 이유**: 모델은 학습 때의 리사이즈와 정규화를 그대로 기대한다. 전처리가 다르면 에러 없이 성능만 떨어진다. ResNet에서 BGR 순서나 정규화 값을 틀렸을 때와 같은 이야기다.
- `pipeline` 한 줄 안에는 전처리(`pixel_values` `(1, 3, 224, 224)`) → 모델(`logits`) → softmax 후처리가 묶여 있다. 손으로 풀어도 같은 숫자가 나왔다.
- 결과: 버스 사진은 minibus 0.868, 개 사진은 malamute 0.316, Siberian husky 0.305, Eskimo dog 0.153으로 비슷한 견종끼리 확률을 나눠 가졌다.
- 고르는 기준은 공식 조직 계정, 모델 카드와 논문, 라이선스다. 인기보다 목적의 일치가 먼저다.
막힌 점: 답은 나온다. 그런데 모델이 이미지의 어디에서 정보를 가져와 답했는지 들여다볼 수 있을까?

### Attention 지도 읽기와 그 함정
related: vit-attention-map, vit-attention-distance
핵심: 층마다 나오는 `(1, 12, 197, 197)` Attention 표에서 [CLS] 행을 꺼내면 정보를 어디서 가져갔는지 볼 수 있지만, 그것을 "모델이 본 곳"으로 단정하면 안 된다.
- `output_attentions=True`에 `attn_implementation="eager"`가 필요하다. 기본값 `sdpa`는 빠른 함수를 써서 표를 내주지 않는다. `output_hidden_states=True`는 길이 13 튜플(임베딩 1 + 12층)을 준다.
- [CLS] 행을 Head 평균 내 14×14로 그리면 1층은 고르게 퍼지고 깊어질수록 특정 칸에 몰린다. 모든 층을 누적한 Rollout에서는 개, 버스 앞 사람들처럼 물체 쪽이 밝다.
- **함정**: 8층, 12층에서 개 사진의 바닥, 콩잎 사진의 흙처럼 **빈 배경 칸 몇 개가 유난히 밝다.** 정보가 적은 배경 Token을 계산용 메모리처럼 쓰는 현상으로 알려져 있다(Vision Transformers Need Registers, 2023).
- Head별 평균 Attention 거리: CNN 3×3은 첫 층에서 옆 픽셀만 본다. ViT는 **1층부터 Head마다 0~22px부터 110px 넘게까지 제각각**이고, 깊어지면 모든 Head가 115~120px로 모여 이미지 전체를 본다.
- 앞쪽 층의 일부 Head는 자기 주변만 보는, CNN 같은 지역적 역할을 스스로 배웠다.
막힌 점: 사전학습 모델은 ImageNet 1,000개 클래스로만 답한다. 내 문제(콩잎 세 클래스)에 맞추려면 어떻게 고쳐야 할까?

### 파인튜닝: Head만 바꿀까, 전부 고칠까
related: vit-freeze-vs-full, vit-finetune-strategy, vit-finetune-lr, vit-baseline-errors
핵심: 분류 Head를 새 클래스 수에 맞게 바꾼 뒤, Backbone을 고정하고 Head만 학습하거나(Head Only) 작은 학습률로 전체를 학습한다(Full).
- 데이터 `beans`: healthy, angular_leaf_spot(각반병), bean_rust(녹병). train 1,034 · validation 133 · test 128장
- Head 교체: [CLS] 768차원 → `Linear(768, 3)`. `from_pretrained`에 `num_labels`, `id2label`, `label2id`, `ignore_mismatched_sizes=True`를 함께 넘기는 게 안전하다. 출발점은 `vit-base-patch16-224-in21k`
- **Baseline**: 새 Head가 무작위라 학습 전 검증 정확도가 0.429(실습 노트북은 0.218)였다. 한쪽 클래스로 몰아 찍은 탓이다.
- 결과:

| | Head Only | Full |
|---|---|---|
| 설정 | lr 1e-3, 3 에폭 | lr 2e-5, 2 에폭 |
| 학습 파라미터 | 2,307 | 85,800,963 |
| 검증 정확도 | 0.812 → 0.850 → 0.880 | 첫 에폭 0.992 |
| test 정확도 | 0.875 | 0.961 |

- Head 2,307개만 학습해도 0.88 가까이 나온다는 건 사전학습 [CLS]에 잎 상태 정보가 이미 많다는 뜻이다. Full은 반점 같은 세밀한 특징까지 맞춰 더 올라갔다.
- 파라미터는 약 37,000배 차이인데 에폭당 시간은 1.4~1.7배뿐이었다. Head Only도 순전파는 Backbone 전체를 지나기 때문이다.
- Full 모델이 test에서 틀린 5장 중 4장은 각반병과 녹병 사이 혼동이었다. 224×224로 줄이면 갈색 반점이 몇 픽셀만 남는다.
막힌 점: 잘 맞히지만 답할 수 있는 것은 정해 둔 3개 클래스뿐이다. 새 클래스가 생기면 Head를 바꿔 다시 학습해야 하고, "갈색 반점이 있는 잎" 같은 문장으로 묻는 것은 아예 불가능하다.

### CLIP: 인코더 두 개, 공간 하나
related: clip-overview, clip-vs-classifier
핵심: 이미지 인코더와 텍스트 인코더가 같은 길이의 임베딩을 내게 해서, 이미지와 문장을 코사인 유사도로 직접 비교한다.
- 고정 클래스 분류기의 한계: 학습한 목록 안에서만 답하고, 새 클래스마다 재학습해야 하고, 문장과 비교할 수 없다. CLIP은 정해진 클래스 하나를 고르는 대신 **문장마다 점수**를 낸다.
- **Image Encoder**는 ViT 같은 모델(논문에서는 ResNet도 썼다), **Text Encoder**는 문장용 Transformer다. `clip-vit-base-patch32`는 둘 다 512차원을 낸다.
- 길이를 1로 정규화하면 두 임베딩의 내적이 코사인 유사도이고, 이게 점수다.
- CLIP은 그림이나 문장을 만들어 내지 않는다. 임베딩과 점수를 내서 검색이나 분류에 쓸 뿐이다.
- 실험: 이미지 6장 × 설명 문장 6개의 점수표에서 대각선(짝)이 0.26~0.35로 가장 크고 나머지는 0.08~0.19였다. 6장 모두 자기 짝 문장을 골랐다.
막힌 점: 두 인코더를 따로 학습하면 같은 공간에 있을 이유가 없다. 어떻게 학습해야 짝끼리 가까워질까?

### 대조 학습: 배치 안에서 짝 찾기
related: clip-contrastive-loss, clip-batch-size
핵심: 이미지 N장과 문장 N개로 N×N 점수표를 만들고, 대각선(정답 쌍)은 높이고 나머지는 상대적으로 낮추도록 두 인코더를 함께 학습한다.
- 순서: 이미지 N장 임베딩 → 문장 N개 임베딩 → N×N 점수표 → **대각선이 정답**
- 표를 행으로 읽으면 이미지에서 맞는 문장 찾기, 열로 읽으면 문장에서 맞는 이미지 찾기다.
- 라벨이 따로 필요 없다. i번째 이미지의 정답은 i번째 문장이니 라벨은 `[0, 1, ..., N-1]`이고, 손실은 행 방향과 열 방향 cross-entropy의 평균이다.
- 같은 배치의 다른 샘플이 오답이 된다. 블로그의 6쌍으로 계산한 손실은 0.0001로, 이미 잘 구분되는 쉬운 오답뿐이었다.
- 논문은 인터넷에서 모은 약 4억 개 이미지-문장 쌍을 배치 32,768, 32 에폭으로 학습했다. 문장은 "cat" 하나로는 알 수 없는 자세, 장소, 색까지 담는다.
막힌 점: 그런데 학습된 CLIP에서도 짝의 코사인 유사도는 0.3 근처뿐이다. 이 작은 차이를 그대로 softmax하면 확률이 거의 평평하다.

### 온도(logit_scale): 작은 차이를 벌린다
related: clip-logit-scale, clip-modality-gap
핵심: 코사인 유사도에 학습된 온도 값(여기서는 100)을 곱한 뒤 softmax를 해야 작은 점수 차이가 뚜렷한 확률 차이가 된다.
- 그대로 softmax하면 dog.jpg 기준 0.20 대 0.16으로 거의 구분이 안 된다.
- 100을 곱하면 0.35와 0.16의 차이 0.19가 19로 벌어져 짝 문장이 1.00을 가져간다.
- Hugging Face의 `logits_per_image`가 바로 `유사도 × 100`이고, `logits_per_image.softmax(dim=1)`이 확률이다.
- 곱하기는 순서를 바꾸지 않는다. 1등은 그대로이고 확률의 뾰족함만 바뀐다. 논문은 이 값을 1/0.07에서 시작해 함께 학습하고 100을 넘지 않게 제한했다.
- 짝인데 0.3인 이유는 **modality gap**이다. PCA로 찍으면 이미지는 왼쪽, 문장은 오른쪽에 따로 모인다. 짝끼리 코사인 평균 0.302, 이미지끼리 0.406, 문장끼리 0.524였다.
- 그래도 그룹 안의 상대 배치가 맞아서, 이미지 하나 기준으로 문장들을 줄 세우면 짝이 1등이다. CLIP 점수는 절댓값보다 **후보끼리의 비교**로 읽어야 한다.
막힌 점: 이 점수로 무엇을 할 수 있을까? 클래스 이름도, 자유로운 검색어도 결국 "문장"이니 그대로 비교하면 된다.

### Zero-shot 분류와 검색
related: clip-zeroshot, clip-prompt
핵심: 후보 클래스를 문장으로 만들어 이미지와 가장 가까운 문장을 고르면 분류(zero-shot)이고, 문장 하나로 이미지들을 점수순으로 줄 세우면 검색이다.
- **Zero-shot 분류**: 논문은 "A photo of a {label}." 틀을 썼다. 새 클래스가 생겨도 다시 학습하지 않고 후보 문장만 바꾼다. `pipeline("zero-shot-image-classification")`에 `candidate_labels`를 넘기면 된다.
- **검색**: 이미지 임베딩을 미리 계산해 두고, 검색 문장의 임베딩과 내적해 정렬한다. 클래스 이름이 아니라 아무 문장이나 넣을 수 있다.
- 결과: "something you can ride"에는 자전거 사진, "water"에는 항구 사진, "people at a football match"에는 관중석 앞 두 감독 사진이 1위였다. 'ride'나 'football' 라벨을 붙인 적은 없다.
- 주의: "an animal"은 개 사진이 1위지만 0.241 대 0.238로 콩잎 사진과 거의 차이가 없었다. 점수 차가 작으면 결과를 믿기 어렵다.
막힌 점: 인터넷 이미지-문장에서 배운 지식이 닿지 않는 전문 분야라면 어떨까?

### Zero-shot이 무너지는 곳
related: clip-zeroshot-limit
핵심: CLIP은 인터넷 캡션에 없던 세밀한 구분(콩잎의 병명)은 하지 못해 무작위 수준으로 떨어진다.
- beans test 128장: 라벨 그대로든 "a photo of a ..." 틀이든 정확도 0.336. 거의 전부 angular leaf spot으로 찍었다.
- 증상을 자세히 묘사한 문장(갈색 각진 반점, 주황-갈색 녹 가루, 균일한 초록 잎)으로 바꾸자 0.273으로 더 떨어졌고, 정상 잎은 한 장도 예측하지 않았다.
- 후보에 따라 답이 뒤집혔다. 녹병 잎을 "healthy / rust / car"와 비교하면 rust 0.89, "healthy / rust / angular leaf spot"이면 angular leaf spot 0.91
- "갈색 반점이 있는 상한 콩잎"으로 9장을 검색하자 정상 잎 두 장이 1, 2위였다. 점수가 0.305~0.356에 몰려 사실상 구분을 못 했다.
- 같은 데이터에 ViT를 파인튜닝하면 test 0.961이다. 범용 모델이 모든 것을 해결하지는 않는다.
막힌 점: 분류라면 ViT 파인튜닝으로 충분하다. 하지만 "문장으로 찾기" 자체가 목적이면 CLIP을 내 분야 데이터로 고쳐야 한다.

### 검색용 CLIP 파인튜닝, 그리고 그 뒤
related: clip-finetune-retrieval, clip-retrieval-metrics
핵심: 내 분야의 이미지-문장 쌍으로 같은 대조 손실을 다시 학습시킬 수 있지만, 데이터가 작으면 개선이 보장되지 않는다.
- 모델 `Bingsu/clip-vit-base-patch32-ko`(한국어·영어), H&M 상품 사진과 영어 설명. 정제 후 상품 651개, 쌍 1,147개. **상품 단위**로 train 531 / val 49 / test 71개로 나눠 학습 상품이 시험에 나오지 않게 했다.
- 클래스 라벨 없이 배치 안의 같은 자리가 정답이다. `model(**batch, return_loss=True)`가 N×N 양방향 손실을 계산하고, 루프는 zero_grad → loss → backward → step → scheduler 순서다.
- 배치 64, lr 1e-5, 8 에폭(64 step), 88초. 검증 손실 1.548 → 5 에폭 1.008 → 8 에폭 1.053, 학습 손실은 0.13까지. 마지막 에폭을 저장해서 검증 손실이 가장 낮은 모델이 아니었다.
- 질의 27개, 후보 71장 평가: Recall@1 영어 0.852 → 0.815, 한국어 0.778 → 0.815. MRR 영어 0.907 → 0.880, 한국어 0.865 → 0.875. 질의 하나가 Recall@1을 0.037씩 움직여서 좋아졌다고도 나빠졌다고도 단정하기 어렵다.
- 질의별로는 들쭉날쭉했다. "저녁 파티에 입을 검정 원피스"는 1, 2위가 모두 검정 원피스가 됐고, "편안한 회색 맨투맨"은 회색 맨투맨이 2위에서 4위로 내려갔다. 다음 실험은 최저 검증 에폭 저장, 이미지 인코더 고정(`freeze_vision`), 데이터 늘리기다.
- **그 뒤**: 이 노트북의 마지막 주제다. 이야기는 데이터를 덜 쓰는 효율적인 ViT(DeiT, Swin Transformer), 라벨 없이 학습하는 비전 Backbone(DINOv2), CLIP 계열을 발전시킨 SigLIP, 이미지를 보고 대화하는 LLaVA로 이어진다.

## 한 장 요약

### 한 문장 흐름
CNN은 가까운 곳부터(강한 가정) → Attention은 입력에 따라 골라 섞는다 → 이미지를 Patch로 잘라 Token으로 → 펼쳐서 768차원으로 투영 → [CLS] 붙이고 위치 더하기 → Encoder 12층 → [CLS]로 분류 → 가정이 약하니 대규모 사전학습 후 파인튜닝 → 고정 클래스의 한계 → CLIP: 두 인코더를 대조 학습으로 한 공간에 → 온도로 확률화 → 문장으로 zero-shot 분류와 검색 → 모르는 분야는 파인튜닝

### 숫자와 식
| 무엇 | 식 / 값 | 예 |
|---|---|---|
| Patch 수 | `(H/P) × (W/P)` | 224, P16 → 196 / P32 → 49 |
| Token 수 | Patch 수 + 1([CLS]) | 197 / 50 |
| 펼친 Patch 길이 | `P × P × 3` | 768 / 3,072 |
| Attention 표 크기 | `N²` (층·Head마다) | 197² = 38,809 / 50² = 2,500 |
| Attention | `softmax(QKᵀ/√d)V` | ViT-B/16은 Head당 d = 64 |
| ViT-B/16 | Hidden 768, 12층, 12 Head, MLP 3,072 | 약 86M |
| 새 분류 Head | `768 × C + C` | C = 3 → 2,307 |
| CLIP 점수 | `logit_scale × 코사인` | 100 × 0.35 = 35 |
| CLIP 손실 | (행 방향 CE + 열 방향 CE) / 2, 라벨 `[0..N-1]` | 6쌍 → 0.0001 |
| MRR | 정답 순위 역수의 평균 | 1등 1, 2등 0.5 |

### 헷갈리는 용어
| 용어 | 뜻 |
|---|---|
| 펼친 길이 768 vs Hidden 768 | 앞은 Patch 크기로 정해지는 입력 길이(P×P×3), 뒤는 설계로 정한 Token 차원. B/16에서만 우연히 같다 |
| Patch Embedding vs Position Embedding | 앞은 Patch 내용을 768차원으로 투영하는 W, 뒤는 위치마다 더하는 학습 벡터 |
| [CLS] vs GAP | 학습되는 Token이 Attention으로 모음 / Patch 출력의 단순 평균 |
| Attention 비중 | 정보를 어디서 얼마나 섞어 왔는가. 답에 대한 기여도나 근거와는 다르다 |
| `sdpa` vs `eager` | 빠른 기본 구현(Attention 표를 안 줌) / 표를 꺼낼 수 있는 구현 |
| Head Only vs Full | Backbone 고정 + Head만 학습 / 전체를 작은 학습률로 학습 |
| 코사인 유사도 vs `logits_per_image` | 원래 점수 / 점수 × logit_scale. softmax는 뒤의 것에 한다 |
| modality gap | 이미지 임베딩과 문장 임베딩이 공간의 다른 구역에 모이는 현상 |
| zero-shot | 그 클래스로 학습하지 않고 후보 문장만 바꿔 분류 |
| Recall@K | 정답이 K등 안에 든 질의의 비율 |

### 실험 숫자 한눈에
| 실험 | 결과 |
|---|---|
| ViT ImageNet 분류 | 버스 minibus 0.868, 개 malamute 0.316 / husky 0.305 |
| Attention 거리 | 1층 Head마다 0~22px부터 110px 이상, 깊은 층 115~120px |
| beans 학습 전 Baseline | 0.429 (실습 노트북 0.218) |
| beans Head Only / Full | test 0.875 / 0.961, 학습 파라미터 2,307 / 85,800,963 |
| CLIP 짝 유사도 | 대각선 0.26~0.35, 나머지 0.08~0.19 |
| modality gap | 짝 0.302, 이미지끼리 0.406, 문장끼리 0.524 |
| beans CLIP zero-shot | 0.336, 묘사 문장 0.273 |
| 옷 검색 Recall@1 | 영어 0.852 → 0.815, 한국어 0.778 → 0.815 |

| LLaVA | CLIP 이미지 인코더를 언어 모델에 연결해 이미지를 보고 대화 |

## 이해 확인

### Q. CNN이 "가까운 픽셀끼리 관련이 깊다"고 가정한다는 것은 구조의 어디에 들어 있고, 그 가정의 득과 실은 무엇인가요?
id: vitc-cnn-local-bias
type: 개념
level: 기본
related: vit-inductive-bias, vit-vs-cnn, cnn-local-connectivity-weight-sharing

#### 풀이
**작은 커널**(출력 한 칸이 이웃 몇 칸만 봄)과 **가중치 공유**(같은 필터를 모든 위치에 씀)에 들어 있습니다. 학습으로 바꿀 수 있는 값이 아니라 구조 자체에 박힌 가정입니다.
- **득**: 이미지에 대체로 맞는 가정이라 적은 데이터로도 효율적으로 배운다.
- **실**: 무엇과 무엇을 섞을지가 입력과 상관없이 위치로 정해져 있다. 멀리 떨어진 영역의 관계는 층을 쌓아 receptive field가 넓어진 뒤에야 본다.
- ViT는 반대다. 첫 층부터 아무 Patch끼리나 섞을 수 있고, 무엇을 볼지는 입력과 학습이 정한다. 대신 그 가정을 데이터에서 배워야 해서 데이터가 많이 필요하다.

### Q. Attention은 왜 입력 벡터 하나를 그대로 쓰지 않고 Q, K, V 세 벡터로 나누나요?
id: vitc-why-qkv
type: 개념
level: 기본
related: vit-encoder-block, nlp-attention, nlp-self-attention

#### 풀이
Token 하나가 맡는 역할이 셋이기 때문입니다. **무엇을 찾을지**(Q), **남에게 어떻게 찾아질지**(K), **찾아졌을 때 무엇을 건넬지**(V)는 서로 다른 정보입니다.
- W_q, W_k, W_v를 따로 학습하면 "어떤 기준으로 고를지"와 "골랐을 때 무엇을 가져올지"를 따로 정할 수 있다. apple 예에서 `사과를`이 뽑힌 이유는 K이고, 결과에 섞인 내용은 V다.
- Q와 K를 같은 벡터로 쓰면 점수표 QKᵀ가 대칭이 된다. A가 B를 높게 보면 B도 A를 똑같이 높게 봐야 한다. 실제 관계는 한쪽 방향일 때가 많다.
- 결과는 Q가 아니라 V들의 가중합이라, 찾는 데 쓰는 정보와 전달하는 정보가 분리된다.

### Q. "Q와 K의 내적 점수가 음수인 Token은 Attention 비중이 0이 된다."
id: vitc-ox-negative-score
type: OX
level: 기본
related: nlp-scaled-dot-product, vit-encoder-block

#### 풀이
**X.** Softmax는 점수를 e^x로 바꾸므로 음수 점수도 0보다 큰 비중을 받습니다. 작아질 뿐입니다.
- 블로그 그림에서도 음수 점수의 비중이 0보다 컸다.
- 비중을 정확히 0으로 만들려면 Decoder의 미래 가리기처럼 Softmax 전에 점수를 -∞로 바꿔야 한다. e^(-∞) = 0이기 때문이다.

### Q. 224×224 입력에서 Patch 크기 16과 32일 때 Token 수([CLS] 포함)와 층·Head 하나의 Attention 표 칸 수를 구하고 비교하세요.
id: vitc-patch-size-calc
type: 계산
level: 기본
related: vit-patch-size, nlp-attention-complexity

#### 풀이
- P16: 224 / 16 = 14 → 14×14 = 196, [CLS] 포함 **197**개. 표는 197² = **38,809**칸
- P32: 224 / 32 = 7 → 7×7 = 49, [CLS] 포함 **50**개. 표는 50² = **2,500**칸
- Token은 약 1/4인데 표는 38,809 / 2,500 ≈ **15.5배** 차이다. 모든 쌍을 비교하니 제곱으로 효과가 커진다.
- 펼친 Patch 길이는 오히려 768 → 3,072로 4배가 되지만 Hidden size는 둘 다 768이다.
- 대가: B/32는 한 Token이 32×32를 통째로 봐서 작은 물체와 세밀한 무늬에 불리하다. CLIP 실습의 `clip-vit-base-patch32`가 이쪽이다.

### Q. ViT-B/16에서 펼친 Patch 길이도 768, Hidden size도 768입니다. 같은 숫자인데 왜 "다른 설정"이라고 하나요?
id: vitc-768-twice
type: 개념
level: 기본
related: vit-patch-embedding, vit-shape-flow

#### 풀이
정해지는 방식이 다르기 때문입니다. 펼친 길이는 **Patch 크기로 자동으로 정해지는** 입력 크기(P×P×3)이고, Hidden size는 **모델 설계에서 고르는** Token 벡터의 크기입니다. Patch Embedding의 W가 앞의 것을 뒤의 것으로 바꿔 줍니다.
- B/16: 16×16×3 = 768 → W(768 → 768) → 768. 우연히 같다.
- B/32: 32×32×3 = 3,072 → W(3,072 → 768) → 768
- Encoder 이후 `(B, 197, 768)`의 768은 모두 Hidden size 쪽이다. Head가 `Linear(768, 3)`인 것도 Hidden size 때문이다.

### Q. Patch Embedding 가중치의 모양은 (768, 3, 16, 16)이었습니다. 이것을 CNN의 언어로 바꾸면 어떤 층이고, 학습된 필터가 CNN 첫 층과 닮은 이유는 무엇인가요?
id: vitc-patch-embed-as-conv
type: 연결
level: 심화
related: vit-patch-embedding, cnn-stride, cnn-filter-learning

#### 풀이
**커널 16×16, stride 16, 출력 채널 768인 Conv 한 층**입니다. 커널과 stride가 같아 창이 겹치지 않고, 224 입력에서 14×14 위치마다 768개 값이 나옵니다. 이것을 한 줄로 펴면 `(196, 768)`입니다.
- 필터 하나가 Patch와 내적하는 것은 펼친 768개 값에 W의 한 행을 곱하는 것과 같은 계산이다. 그래서 Linear Projection과 Conv가 같은 일을 한다. Hugging Face ViT도 Conv2d로 구현한다.
- `conv.weight` 모양 `(C_out, C_in, K, K)` = (768, 3, 16, 16)과 정확히 맞는다.
- **닮은 이유**: 둘 다 픽셀을 처음 받아 작은 영역의 저수준 특징(색 대비, 줄무늬, 점)을 뽑는 자리다. 맡은 일이 같으니 비슷한 모양으로 학습된다.
- **다른 점**: CNN은 이런 작은 Conv를 겹쳐 쌓으며 넓혀 가고, ViT는 이 한 번 뒤로는 공간 방향 Conv 없이 Attention이 Patch 사이를 잇는다.

### Q. [CLS]는 이미지와 상관없는 같은 벡터로 시작합니다. 그런데 어떻게 이미지 전체의 요약이 되나요?
id: vitc-cls-gathers
type: 개념
level: 심화
related: vit-cls-token, vit-cls-vs-gap

#### 풀이
Encoder의 매 층에서 [CLS]도 Query가 되어 **196개 Patch의 Value를 비중대로 섞어 가져오기** 때문입니다. 시작값은 같아도 섞어 오는 내용이 사진마다 다르니 층을 지날수록 사진마다 다른 벡터가 됩니다.
- 비중도 사진마다 다르다. Patch의 K가 사진 내용에 따라 달라지기 때문이다.
- 손실은 [CLS] 출력에서만 계산된다. 역전파가 [CLS] 시작값과 각 층의 W_q, W_k, W_v를 "분류에 쓸모 있는 정보를 모으는" 쪽으로 바꾼다.
- 요약 전용 자리가 있으니 Patch 하나에 요약을 떠맡기지 않아도 된다. 평균(GAP)으로 요약하는 대안도 있고, ViT 논문에서 둘의 성능은 비슷했다.

### Q. Position Embedding이 없는 ViT에 Patch 196개의 순서를 무작위로 섞어 넣으면 결과가 어떻게 될까요?
id: vitc-shuffle-patches
type: 만약에
level: 심화
related: vit-position-why, vit-position-embedding, nlp-positional-encoding

#### 풀이
**예측이 전혀 바뀌지 않습니다.** 원본과 직소 퍼즐처럼 뒤섞인 이미지를 구분하지 못합니다.
- Patch Embedding의 W는 모든 Patch에 같으니 Token도 순서만 섞인다.
- Self-Attention은 순서를 섞어도 각 Token이 섞는 값이 그대로이고, MLP와 정규화는 Token마다 따로 적용된다. 그래서 Patch 출력은 섞인 순서대로 같은 값이 나온다.
- [CLS]는 맨 앞에 그대로 있고 196개 Patch의 V를 비중대로 더해 가져간다. 더하는 순서가 바뀌어도 합은 같으니 [CLS] 출력도 같다.
- 결국 모델에게 이미지는 "Patch 196개가 든 주머니"다. 하늘이 위에 있는지, 눈 옆에 코가 있는지 같은 배치 정보를 쓸 수 없다.
- Position Embedding을 더하면 같은 Patch라도 몇 번 자리에 왔는지에 따라 벡터가 달라져, 섞인 이미지는 다른 입력이 된다.

### Q. 위치 벡터는 0~196 번호에 붙은 1차원 목록일 뿐인데, 학습 후 유사도 지도에 행과 열을 따라 십자 모양이 나타났습니다. 왜 그렇게 됐을까요?
id: vitc-pos-cross
type: 생각해보기
level: 심화
related: vit-position-embedding, vit-position-why

#### 풀이
정답이 하나로 정해진 문제는 아니지만, 이렇게 따라가 볼 수 있습니다.
- 위치 벡터는 손실을 줄이는 데 도움이 되는 쪽으로만 바뀐다. 십자 모양은 "행과 열을 아는 것이 분류에 도움이 됐다"는 흔적이다.
- 이미지에는 2차원 구조가 실제로 있다. 1번 Patch 바로 아래는 15번(번호 14 차이)이고 오른쪽 옆은 2번(번호 1 차이)이다. 같은 열의 Patch는 나무 기둥이나 사람 몸통 같은 세로 물체를 함께 덮고, 같은 행은 수평선이나 바닥처럼 가로로 이어진 것을 함께 덮는다.
- Attention이 "같은 행이나 열의 Patch를 함께 보는" 계산을 하려면, 그런 위치의 벡터가 비슷한 성분을 공유하는 편이 쉽다. 공유한 성분이 내적 점수를 함께 끌어올린다.
- 격자라는 사실은 아무도 알려 주지 않았다. 데이터에 있던 구조를 학습형 임베딩이 흡수한 것이다. 같은 이유로 데이터가 적으면 이 구조를 배우기 어렵고, ViT가 큰 데이터를 필요로 하는 이유 중 하나가 된다.
- ViT 논문에서도 2D를 의식한 위치 임베딩이 1D보다 뚜렷하게 낫지 않았다. 1D로도 2D 구조를 배우기 때문으로 해석할 수 있다.

### Q. 224로 사전학습한 ViT-B/16을 384×384로 파인튜닝하면, 어떤 부분은 그대로 쓰고 어떤 부분은 손봐야 할까요?
id: vitc-higher-res
type: 만약에
level: 심화
related: vit-position-interpolation, vit-patch-size

#### 풀이
- **Token 수**: 384 / 16 = 24 → 24×24 = 576개, [CLS] 포함 577개
- **그대로 쓰는 것**: Patch Embedding W(Patch 크기 16이 그대로라 입력 길이 768도 그대로), Encoder 전체(W_q, W_k, W_v, MLP는 Token 수와 무관), [CLS] 벡터, Head
- **손볼 것**: 위치 임베딩. 학습된 것은 197개뿐이다. Patch 위치 196개를 14×14 격자로 되돌려 24×24로 2D 보간하고, [CLS] 위치 벡터는 따로 그대로 둔다. Hugging Face는 `interpolate_pos_encoding=True`로 해 준다.
- **비용**: Attention 표가 577² = 332,929칸으로 197² = 38,809의 약 8.6배다.
- **얻는 것**: 같은 물체를 더 많은 Patch로 봐서 세밀한 특징을 잡기 좋다. beans의 각반병과 녹병 혼동을 줄일 후보로 블로그가 "더 높은 해상도로 파인튜닝"을 꼽은 이유다.

### Q. Encoder 12층을 지나도 Token 수는 197개 그대로입니다. 왜 줄지 않고, 마지막에 [CLS] 하나만 꺼내도 되는 이유는 무엇인가요?
id: vitc-shape-keeps
type: 개념
level: 기본
related: vit-shape-flow, vit-encoder-block

#### 풀이
Self-Attention은 **Query마다 결과 벡터 하나**를 내고, 잔차 연결과 MLP도 Token마다 적용되기 때문입니다. 197개가 들어가면 197개가 나옵니다. CNN처럼 Pooling으로 줄이는 단계가 없습니다.
- 층마다 출력은 `(B, 197, 768)`이고, `hidden_states` 13개도 모두 같은 모양이다.
- 개수는 그대로지만 정보는 섞인다. 마지막 층의 Token은 자기 Patch만이 아니라 다른 Patch 정보도 담고, [CLS]는 요약을 맡도록 학습됐다.
- 그래서 0번만 골라 `(B, 768)`, Linear Head로 `(B, num_labels)`를 만든다. 고르는 단계에는 학습되는 값이 없다.
- 나머지 196개는 버려지는 게 아니라 분류에 안 쓸 뿐이다. 위치별 답이 필요한 task라면 Patch 출력을 쓴다.

### Q. "ViT는 CNN보다 가정이 약해 더 유연하므로, 데이터 양과 상관없이 CNN보다 성능이 좋다."
id: vitc-ox-vit-always-better
type: OX
level: 기본
related: vit-pretraining-scale, vit-inductive-bias

#### 풀이
**X.** 가정이 약하다는 건 유연하다는 뜻이지만, 동시에 **데이터에서 배워야 할 것이 많다**는 뜻입니다.
- 데이터가 적으면 CNN의 지역성과 가중치 공유 가정이 오히려 도움이 된다. ViT 논문에서도 ImageNet-1k만으로 학습하면 비슷한 크기의 ResNet보다 조금 낮았고, 더 큰 데이터로 사전학습해야 앞섰다.
- 그래서 실무에서는 대규모 사전학습된 ViT를 가져와 파인튜닝한다. beans 실습도 ImageNet-21k로 사전학습한 모델에서 출발했다.

### Q. beans 1,034장으로 ViT-B/16을 사전학습 없이 무작위 초기화에서 학습하면 어떻게 될까요?
id: vitc-scratch-beans
type: 만약에
level: 기본
related: vit-pretraining-scale, vit-transfer-learning

#### 풀이
블로그에서 직접 재지는 않았지만, 파인튜닝 결과(test 0.961)보다 **크게 낮을 가능성이 높습니다.**
- 학습할 값이 약 8,580만 개인데 사진은 1,034장이다. 학습 데이터를 외우는 과적합이 쉽다.
- Patch Embedding 필터, 위치 벡터의 격자 구조, 주변을 보는 Head처럼 사전학습 모델이 이미 가진 것을 전부 처음부터 배워야 한다. 사전학습 모델은 Head 2,307개만 학습해도 test 0.875가 나왔다.
- 이 정도 데이터라면 사전학습 모델 파인튜닝이 기본이다. 꼭 처음부터 학습해야 한다면 귀납적 편향이 있는 작은 CNN이 더 유리할 수 있다.

### Q. ViT 모델에 다른 모델의 Processor로 만든 입력을 넣으면 어떤 일이 생기나요? ResNet 실습의 전처리 실수와 연결해 보세요.
id: vitc-wrong-processor
type: 연결
level: 기본
related: vit-hf-loading, resnet-wrong-preprocess, resnet-imagenet-normalize

#### 풀이
**에러가 나지 않을 가능성이 높아서 더 위험합니다.** 두 전처리기가 모두 `(1, 3, 224, 224)`를 내면 모델은 그대로 돌아가고 정확도만 조용히 떨어집니다.
- 모델은 학습 때의 리사이즈 방식과 정규화 값(평균, 표준편차)이 만든 숫자 분포를 기대한다. 예를 들어 `google/vit-base-patch16-224`의 전처리기는 평균 0.5, 표준편차 0.5로 정규화해 -1~1 범위를 만든다. ImageNet 평균·표준편차를 쓰는 전처리기를 붙이면 같은 사진이 다른 숫자로 들어간다.
- ResNet 실습에서 BGR 순서나 정규화 값을 틀렸을 때와 같은 문제다. 모양 검사는 통과하고 의미만 틀린다.
- 그래서 같은 Model ID로 `AutoImageProcessor`와 모델을 함께 불러온다. 파인튜닝한 모델을 저장할 때도 전처리기를 같이 저장해야 나중에 짝이 맞는다.

### Q. [CLS] Attention 지도에서 밝은 곳을 "모델이 보고 판단한 곳"이라고 단정하면 안 되는 이유는 무엇인가요?
id: vitc-attention-map-caution
type: 개념
level: 심화
related: vit-attention-map

#### 풀이
Attention 비중은 **정보를 어디서 얼마나 섞어 왔는가**일 뿐, 그 정보가 답에 얼마나 기여했는지와는 다르기 때문입니다.
- 실제로 8층, 12층에서 바닥이나 흙 같은 빈 배경 칸 몇 개가 유난히 밝았다. 큰 ViT가 정보가 적은 배경 Token을 계산용 메모리처럼 쓰는 현상으로 알려져 있다.
- 비중이 커도 그 Token의 V가 작거나 이후 층에서 쓰이지 않으면 결과에 대한 영향은 작다. 잔차 연결로 [CLS] 자신의 값도 그대로 이어진다.
- 한 층의 Head 평균 한 장은 일부만 보여 준다. 층마다 몰리는 곳이 다르고, Rollout으로 층을 누적해도 근사일 뿐이다.
- 그래서 지도는 "어디서 정보를 가져갔는가"에 대한 힌트로 읽는다. 근거라고 주장하려면 그 영역을 가리고 예측이 얼마나 바뀌는지 같은 검증을 더한다.

### Q. ViT Head별 평균 Attention 거리 측정 결과를 CNN의 receptive field와 비교하면 무엇이 같고 무엇이 다른가요?
id: vitc-distance-vs-receptive
type: 연결
level: 심화
related: vit-attention-distance, cnn-receptive-field, vit-vs-cnn

#### 풀이
- **다른 점**: CNN 3×3은 첫 층에서 바로 옆 픽셀만 보고 층이 쌓여야 3 → 5 → 7로 넓어진다. 이것은 **구조가 정한 한계**다. ViT는 1층부터 Head마다 0~22px부터 110px 넘게까지 제각각이었다. 볼 수 있는 범위는 처음부터 이미지 전체이고, 실제로 어디까지 볼지는 학습이 정했다.
- **같은 점**: 깊어질수록 넓게 본다. ViT도 깊은 층에서 모든 Head가 115~120px로 모여 전체를 봤다.
- **흥미로운 점**: 앞쪽 일부 Head는 자기 주변만 보는, CNN 커널 같은 역할을 스스로 배웠다. "가까운 곳을 보는 게 쓸모 있다"는 사실을 CNN은 구조로 받았고 ViT는 데이터에서 다시 발견한 셈이다. 이 차이가 데이터 요구량의 차이로 이어진다.

### Q. Head Only는 학습 파라미터가 2,307개, Full은 85,800,963개로 약 37,000배 차이인데, 에폭당 시간은 1.4~1.7배밖에 차이 나지 않았습니다. 왜 그럴까요?
id: vitc-headonly-time
type: 개념
level: 심화
related: vit-freeze-vs-full, vit-finetune-strategy

#### 풀이
Head Only도 **순전파는 Backbone 전체를 지나야** 하기 때문입니다. [CLS] 특징을 얻으려면 Patch Embedding부터 Encoder 12층까지 모두 계산해야 합니다.
- Head Only가 아끼는 것은 Backbone의 역전파와 가중치 갱신뿐이다. 순전파, 데이터 불러오기, 전처리는 똑같다.
- 2,307 = 768 × 3 + 3이다. 파라미터 수 차이가 시간 차이로 그대로 옮겨 가지 않는다.
- 차이가 크게 나는 쪽은 **GPU 메모리**다. Full은 8,580만 개 가중치 모두의 기울기와 AdamW 상태를 들고 있어야 한다.
- 시간을 정말 줄이려면 Backbone이 낸 [CLS] 특징을 한 번만 계산해 저장해 두고 Head만 반복 학습할 수 있다. 다만 그러면 에폭마다 다른 데이터 증강을 쓸 수 없다.

### Q. beans에서 Full은 Head Only보다 test 정확도가 8.6%p 높았습니다(0.961 vs 0.875). 그래도 Head Only를 고를 만한 상황은 언제일까요?
id: vitc-when-head-only
type: 생각해보기
level: 심화
related: vit-freeze-vs-full, vit-finetune-lr, resnet-freeze-backbone

#### 풀이
정확도만이 기준이 아니거나, Full의 장점이 사라지는 조건일 때입니다.
- **데이터가 아주 적을 때**: Full은 8,580만 개를 학습 데이터에 맞춰 고친다. 수십 장 수준이면 과적합 위험이 커서 Head Only가 안정적이다.
- **자원이 부족할 때**: GPU 메모리가 모자라면 Full은 아예 돌지 않을 수 있다.
- **여러 작업이 Backbone 하나를 공유할 때**: Backbone을 고정하면 작업마다 작은 Head만 따로 저장하면 된다.
- **새 데이터가 사전학습 데이터와 비슷할 때**: 이미 있는 특징으로 충분해 Full의 이득이 작다.

반대로 beans처럼 작은 반점 차이가 중요하고 사전학습과 성격이 다른 분야라면 Backbone까지 고쳐야 이득이 큽니다. 이때도 잘 학습된 특징을 망가뜨리지 않도록 작은 학습률(2e-5)을 씁니다. 뒤쪽 몇 층만 풀거나, Head Only로 먼저 맞춘 뒤 전체를 푸는 중간 선택지도 있습니다.

### Q. CLIP 학습에는 클래스 라벨이 없습니다. 그러면 cross-entropy의 정답은 어디서 오나요?
id: vitc-clip-no-labels
type: 개념
level: 기본
related: clip-contrastive-loss, clip-overview

#### 풀이
**배치 안의 자리**가 정답입니다. i번째 이미지와 i번째 문장이 짝으로 함께 들어오므로 N×N 점수표의 대각선이 정답입니다.
- 행마다(이미지 하나가 문장 N개 중 짝 고르기) N지선다 분류이고 정답 번호는 i다. 그래서 라벨은 `[0, 1, ..., N-1]`
- 열마다(문장 하나가 이미지 N장 중 짝 고르기)도 똑같이 하고, 손실은 두 방향 cross-entropy의 평균이다.
- 사람이 따로 붙이는 것은 클래스가 아니라 이미지에 딸려 있던 설명 문장이다. 인터넷의 이미지-문장 쌍 약 4억 개를 그대로 쓸 수 있었던 이유다.
- 옷 검색 프로젝트에서도 `return_loss=True`가 이 계산을 해 줬다.

### Q. CLIP을 배치 크기 1로 학습하면 어떻게 될까요? 배치 6, 64, 32,768과 비교해 보세요.
id: vitc-small-batch
type: 만약에
level: 심화
related: clip-batch-size, clip-contrastive-loss

#### 풀이
**배치 1이면 아무것도 배우지 못합니다.** 표가 1×1이라 후보가 짝 하나뿐이고, softmax가 항상 1이라 손실도 기울기도 0입니다.
- 대조 학습의 신호는 "오답보다 짝이 높아야 한다"에서 나온다. 배치 N이면 샘플마다 오답이 N-1개다.
- **배치 6**: 오답 5개. 블로그에서 계산한 손실은 0.0001이었다. 개, 버스, 자전거처럼 서로 쉬운 오답이라 배울 게 거의 없다.
- **배치 64**(옷 프로젝트): 오답 63개. 비슷한 원피스끼리처럼 헷갈리는 오답이 섞일 가능성이 커진다.
- **배치 32,768**(CLIP 논문): 오답 32,767개. 어려운 오답이 많아 세밀하게 구분하도록 학습된다. 대신 표와 메모리가 커서 여러 GPU의 임베딩을 모아야 한다.
- 이 의존도를 줄이려고 SigLIP은 쌍마다 따로 판정하는 sigmoid 손실을 쓴다.

### Q. 잘 학습된 CLIP인데도 짝 이미지-문장의 코사인 유사도는 0.3 근처였고, 이미지끼리(0.406)나 문장끼리(0.524)가 오히려 더 비슷했습니다. 그런데도 검색과 분류가 되는 이유는 무엇일까요?
id: vitc-low-cosine
type: 생각해보기
level: 심화
related: clip-modality-gap, clip-logit-scale

#### 풀이
CLIP 학습이 요구한 것이 "짝이 1에 가까워라"가 아니라 **"같은 줄의 다른 후보보다 짝이 높아라"**였기 때문입니다.
- 손실은 한 행(또는 열) 안의 softmax라서 후보끼리의 차이만 본다. 한 줄의 모든 점수가 함께 오르내려도 softmax 결과는 같으니 절댓값을 키울 압력이 없다.
- 그래서 이미지와 문장이 공간의 다른 구역(PCA에서 왼쪽, 오른쪽)에 모여 있어도 괜찮다. 각 구역 안의 상대 배치가 맞으면 이미지 하나 기준으로 문장들을 줄 세울 때 짝이 1등이 된다. 이것이 modality gap이다.
- 작은 차이는 logit_scale(100)이 벌려 준다. 0.35 대 0.16이 35 대 16이 된다.
- 주의할 점: "0.3이 넘으면 맞다" 같은 고정 기준으로 판정하거나 이미지와 문장을 한 결과 목록에 섞어 순위를 매기면 이 간격 때문에 틀어질 수 있다. CLIP 점수는 **같은 질의 안에서 후보끼리 비교**할 때 의미가 있다.

### Q. "logit_scale을 크게 하면 이미지와 가장 잘 맞는 문장(1등)이 바뀔 수 있다."
id: vitc-ox-scale-rank
type: OX
level: 심화
related: clip-logit-scale

#### 풀이
**X.** logit_scale은 모든 유사도에 같은 양수를 곱할 뿐이라 **순서가 그대로**입니다. 1등도 그대로입니다.
- 바뀌는 것은 확률 분포의 모양이다. 곱하지 않으면 0.20 대 0.16처럼 평평하고, 100을 곱하면 짝이 1.00을 가져가는 뾰족한 분포가 된다.
- 학습할 때는 이야기가 다르다. 온도가 손실의 크기와 기울기를 바꿔 오답을 얼마나 강하게 밀어낼지 정하므로, 학습된 임베딩 자체에는 영향을 준다. CLIP은 이 값을 1/0.07에서 시작해 함께 학습하고 100을 넘지 않게 제한했다.

### Q. CLIP zero-shot 분류를 ViT 분류기의 `Linear(768, C)` Head와 비교하면, 후보 문장의 임베딩은 어떤 역할을 하고 있나요?
id: vitc-zeroshot-as-head
type: 개념
level: 심화
related: clip-zeroshot, clip-vs-classifier, clip-prompt

#### 풀이
후보 문장들의 임베딩이 **분류 Head의 가중치 행**을 대신합니다.
- ViT 분류기: [CLS] 특징 × W(클래스마다 한 행) → 클래스별 점수. W는 라벨 데이터로 학습한다.
- CLIP zero-shot: 이미지 임베딩(512) × [문장 임베딩 C개를 쌓은 행렬]ᵀ × logit_scale → 클래스별 점수. 행은 Text Encoder가 문장에서 바로 만들어 준다.
- 그래서 새 클래스는 학습 없이 문장 한 줄로 행 하나를 더 쌓으면 된다.
- 같은 이유로 문장 표현이 결과를 바꾼다. "A photo of a {label}."처럼 학습 캡션과 비슷한 틀을 쓰면 더 좋은 행이 나온다. 여러 틀의 임베딩을 평균 내는 프롬프트 앙상블도 행 하나를 더 좋게 만드는 방법이다.
- 한계도 그대로다. Text Encoder와 Image Encoder가 그 개념을 모르면 좋은 행을 만들 수 없다. 콩잎 병명이 그랬다.

### Q. 콩잎 zero-shot 정확도는 0.336이었고, 증상을 자세히 묘사한 문장으로 바꾸자 0.273으로 더 떨어졌습니다. 자세히 설명했는데 왜 나아지지 않았고, 무엇을 해야 할까요?
id: vitc-beans-zeroshot-fail
type: 생각해보기
level: 심화
related: clip-zeroshot-limit, clip-prompt, clip-vs-classifier

#### 풀이
문장을 아무리 자세히 써도 **이미지 쪽 임베딩이 그 차이를 담고 있지 않으면** 비교할 거리가 없기 때문입니다.
- CLIP이 배운 것은 인터넷 이미지와 캡션의 짝이다. "잎 사진"이라는 건 알아도 각반병과 녹병을 구분하는 캡션은 거의 없었을 것이다. 그러면 세 클래스 사진의 임베딩이 비슷한 자리에 모인다.
- 점수 차가 작으면(검색에서 9장이 0.305~0.356에 몰림) 승부는 이미지 내용보다 문장 쪽 사정으로 갈린다. "갈색", "반점" 같은 단어를 넣은 묘사가 특정 후보 쪽으로 쏠리게 만들었을 수 있고, 결국 정상 잎은 한 장도 고르지 않았다.
- 후보 목록만 바꿨는데 답이 뒤집힌 것(rust 0.89 → angular leaf spot 0.91)도 같은 신호다. 높은 확률도 후보 사이의 상대 비교일 뿐이다.

할 일은 목적에 따라 갈립니다.
1. 분류만 필요하면 라벨로 ViT를 파인튜닝한다. 같은 데이터에서 test 0.961이었다.
2. 문장 검색이 필요하면 그 분야의 이미지-문장 쌍으로 CLIP 자체를 다시 학습한다.
3. 중간 방법으로 CLIP 이미지 임베딩 위에 작은 분류기를 라벨로 학습해 볼 수 있다. 다만 이미지 임베딩이 병을 구분하지 못하면 이것도 한계가 있다.

### Q. 질의 5개에서 정답 상품의 순위가 각각 1, 3, 1, 2, 7등이었습니다. Recall@1, Recall@5, MRR을 구하세요. 그리고 질의가 27개일 때 질의 하나가 Recall@1을 얼마나 움직이나요?
id: vitc-retrieval-metrics-calc
type: 계산
level: 기본
related: clip-retrieval-metrics, clip-finetune-retrieval

#### 풀이
- Recall@1 = 1등이 정답인 질의 2개 / 5 = **0.4**
- Recall@5 = 5등 안에 든 질의 4개 / 5 = **0.8** (7등 하나만 빠짐)
- MRR = (1/1 + 1/3 + 1/1 + 1/2 + 1/7) / 5 = (1 + 0.333 + 1 + 0.5 + 0.143) / 5 = 2.976 / 5 ≈ **0.595**
- 질의 27개면 하나가 1/27 ≈ **0.037**을 움직인다. 블로그 표의 Recall@1 변화(영어 0.852 → 0.815, 한국어 0.778 → 0.815)가 정확히 질의 하나 차이라서, 좋아졌다거나 나빠졌다고 단정하기 어렵다.
- MRR은 1등을 놓쳐도 2등이면 0.5를 줘서 "얼마나 아깝게 빗나갔는지"까지 반영한다. Recall@1만 볼 때보다 변화가 부드럽다.
